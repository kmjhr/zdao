## 1. 一页 PRD

### 1.0 产品内核：一张拼豆图就是一个 OC（v1.4 重写）

一句话：**玩家在 29×29 的市面拼豆图纸上拼一个 Q 版 OC，每一颗豆同时记录「色号」和「部件」两个值；同一张双矩阵既是角色的形象，也是可换的服装，也是地图上的物件。**

四层含义：



1. **画布即图纸**：29×29 与市售拼豆图纸逐格对齐，玩家可用现成图纸、可照图买真豆复刻，作品天然能实体化。

2. **每颗豆两个值**：`color`（MARD 色号）+ `part`（部件标签，如 hair/eyes/coat）。先按色号拼（创作态），再标部件（可动、可换装）；一格一豆，标部件不改像素。

3. **一张矩阵三处通用**：同一个编辑器产出三种东西 —— 角色形象（全部件）、服装（只覆盖外层部件的稀疏矩阵）、地图物件（小尺寸矩阵）。玩家的每一次作画都同时喂养三条系统，这是零美术能撑住一个世界的真正原因。

4. **零美术成本**：不生成位图、不做文生图。外观 100% 由玩家矩阵决定，屏幕上那个 OC 永远就是他亲手拼的那一个。

这条窄缝是个人开发唯一能打赢大厂的地方：**没有美术资产，只有结构化数据；同一个矩阵贯穿角色、衣柜、地图。**

产品按个人开发设计：单机可玩、无账号也能走完核心循环、0 次模型调用也能每天有新内容。

### 1.1 一句话定位

玩家用**拼豆式画布**造一个像素 OC（不用会画），填一张**角色卡**，把他放进一个**像素世界**（星露谷式瓦片地图，可换装、可摆物件、可自己改地图），然后看他和其他 OC 自由过日子 —— 像一个**蚂蚁箱**：玩家搭环境、偶尔投喂，剩下的交给它们自己忙。世界彼此独立、可开门相通，但一个角色只属于一个世界。

> 【补全】上述定位由三份文档的核心循环归纳；最终措辞待目标用户确认后可能调整。

### 1.2 目标用户



* **OC / 同人创作者**：已有角色设定或小说文本，希望角色 “活起来” 并被看见。

* **像素 / 拼豆手作爱好者**：享受一格一豆的确定性创作与实体感。

* **模拟经营与陪伴向玩家**：喜欢观察小人自主生活、积累关系与回忆。

> 【补全】目标用户为推导结论，尚未经过用户调研；
> **待目标用户确认后可能调整**
> 。

### 1.3 核心循环

`立宇宙（填世界观卡） → 画 OC（拼豆画布） → 填角色卡并放入世界 → 换装与摆物件 → 观察与沉淀（事件 / 关系 / 年表）`



1. **立宇宙**：先填世界观卡（语言腔调、时代氛围、拼豆色板、OOC 基准），宇宙与岛 1:1，允许先建成空岛。

2. **造人**：在该宇宙的色板与腔调下画形象、填角色卡（姓名、性别、生日、简介、标签、禁忌），放入世界。

3. **安顿**：给 OC 换装、摆物件、调整地图布局，让岛像有人住。

4. **过日子**：OC 按现实时间与日程在地图上走动，与其他 OC 自发互动；事件池每天产出 2–4 件小事。

5. **沉淀**：事件落成年表与纪念册，关系留下痕迹，反哺下一轮创作。

### 1.4 核心差异点



1. **一张矩阵三处通用**：角色形象、服装、地图物件共用同一套拼豆编辑器与双矩阵格式；外观永远由玩家决定，不生成位图，零美术资产。

2. **OOC 四层边界**：角色硬约束 → 创造者边界 → 世界规则 → 当前场景关系，逐层过滤；冲突取更严，创造者只能加严不能放宽。

3. **一格一豆 + MARD 色号**：默认 29×29 市面图纸、40×40 上限、5×5 纯黑粗线、零缝隙填色、图层与部件双矩阵，同时具备绘画软件与拼豆图纸工具的能力。

4. **四层社交且默认私密**：私密宇宙 → 好友圈 → 广场 → 公开页；内容先在私密层生长，公开是逐条动作。

### 1.5 范围与明确不做

**本期必须闭环**：1 张空白角色卡 → 拼豆画出形象 → 填姓名 / 性别 / 生日 → 放入 1 张预设地图 → 换 1 套衣服 + 1 件手持物 → 与另一个 OC 自发互动 1 次 → 事件池当天产出 ≥2 件事 → 本地存档可恢复。

**产品范围外（v1.4 已从需求表删除，不再是「以后做」）**：生文生成、文本演绎、模型接入（原 R037–R046、R074–R086）。删掉它们不是延期，是把产品重新定位成一颗不依赖模型也能成立的世界观察器。

**本期不做**：多世界同时在线切换（只做门跳转）、联机约戏、广场市场（录像 / 片段 / 模板）、精选策展、图纸名片、通知聚合、录像导出。

**本期一律不做**：实时大厅、频道聊天 / 陌生人私信、公会 / 阵营、排行榜、实时多人同屏、多人实时共创宇宙、陌生人进岛。

### 1.7 一个游戏日走读（v1.5 新增・判断有没有意思就看这一节）

> 设定：20×15 地图、两个 OC（「姐姐」与示例角色「阿岭」）、8x 倍速（1 游戏日 = 现实 2.5 分钟）。以下全部是已写进规格的系统，不新增任何玩法。

**19:58 打开游戏。** 屏幕左上角写着「第 3 天 08:12」。先弹出一张离线报告：昨晚她一个人把椅子推到门口，坐了很久；今早水缸满了（下过雨）；阿岭在门口站了十分钟，然后回去了。三行字，全是模板生成的。

**20:00 开始看。** 姐姐站在门口，不动。点她一下，头顶冒出一行字：「她在等雨停。」天明明是晴的。玩家笑了一下，什么也没做。

**20:01 拖她。** 按住，像素小人被提起来 —— 脚离地两像素、手臂下垂、腿轻晃，地上留一个影子，落点是水井边，虚线格。松手，她落地，先愣 0.8 秒，头顶冒了个抖动的小符号，然后开始走。她没有走回门口，而是绕到井的另一侧站着。

玩家心里冒出一句：她不想站在我刚放她的地方。

**20:02 什么都没点。** 阿岭从屋里出来，两人相距两瓦片、关系档位够，自动并肩坐下，播了 2.5 秒。玩家全程没碰鼠标。

**20:03 摆了把伞。** 「摆」档，在门口放了一把伞。放完没有任何反馈，玩家不确定这么做有没有用。

**20:04 天阴了。** 8x 下 1 个游戏日只有 2.5 分钟，半天很快就过去。事件池出了「天气：下雨」，屏幕开始落像素雨点。

**20:05 姐姐走向那把伞。** 从井边走到门口，站在伞下，没再动。

玩家在这里「哦」了一声。那把伞是我三分钟前放的，它自己走过去用了。

**20:06 阿岭也来了。** 两个人挤在一把伞下，触发关系事件，纪念册自动记了一条：「第 3 天・雨中，两人共用一把伞。」

**20:07 关掉。** 关之前看了眼最后一眼：阿岭站在伞边，有一半肩膀在外面淋着。

**第二天打开。** 离线报告第一句：昨晚阿岭在伞下站了很久，肩膀一直是湿的。

**这一天的乐趣在哪**

不是「我下了指令」，也不是「我看到了剧情」。是**我放的东西被它自己用上了，而且用得比我想的更有意思**。玩家全程只做了三件事：拖一下、摆一把伞、看一会儿。系统做了四件事：拒绝被摆布、自己走开、触发关系、写进纪念册。没有一步是玩家写出来的。

**这一节能证明的三件事（实现时照着核对）**



1. 5 分钟现实 ≈ 2 个游戏日，一次会话能看到 2–3 件事件，密度够，不需要更多内容。

2. 玩家的动作必须是「布景」，不能是「指令」。一旦玩家能命令 OC 做事，这一段的乐趣立刻归零。

3. 回访钩子最好是一个**没结局的画面**（半个肩膀在外面），而不是任务清单或成就列表。

**同时暴露的一个口径冲突（本节顺手裁决）**：§4 的 R035 原写「1 游戏日 = 现实 2 小时」，与 §12.1 的 X01-b「1 游戏日 = 20 分钟」相差 6 倍，且离线 72 小时上限在两种口径下分别等于 36 天与 216 天，均不成立。**统一为：1 游戏日 = 现实 20 分钟（1x）；离线推演按 1x 结算、不随倍速放大，上限 7 个游戏日。**

### 4.1 M0 进入、账号与支撑

#### R001 首次进入与首宇宙创建 ｜ P0



* 规则：启动即可本地玩，登录可选；先展示 “世界私密” 说明，再走三步向导（入口选择 → 宇宙名与世界观卡 → 创建）。入口含 “从零建世界 / 导入文本（自动抽世界观与角色）/ 示例宇宙”。宇宙名 2–20 字，世界观卡至少四项基准；示例只预填、不共享数据。

* 数据 / 判定：`universe{id, owner_id, name, world_card, color_palette, status, created_at}`；同名允许、id 唯一；重复提交幂等；无网可创建，联网补同步。

* 验收：3 分钟内创建宇宙并看到首个 OC 的 29×29 图纸；中途关闭重开草稿仍在；未登录可完成。

* 来源：【原文】F01（2.6/8.1）、B01；【补全】首启路径、必填字段与 3 分钟时限。

#### R002 世界观卡定义、继承与唯一裁决 ｜ P0



* 规则：四项必填基准＝语言腔调、时代氛围、拼豆色板、OOC 基准；扩展字段最多 12 项。卡是该宇宙的宪法：角色、场景、物件、生成文本全部带 `world_card_version`；角色只能在卡的基础上加严，不能放宽卡或角色硬禁忌（冲突取更严）。

* 数据 / 判定：`world_card{id, universe_id, tone, era, palette, ooc_baseline, extensions[], version}`；`inheritance{card_version, applied_to}`；缺卡版本拒绝发布；卡缺失用默认卡并提示补填。

* 验收：同一剧情在两种语言腔调卡下语气不同；换色板后新物件只取卡内色；冲突测试中卡与角色硬禁忌均未被放宽。

#### R012 OC 卡与可执行人格 ｜ P0



* 规则（五类约束不变，性格改为可执行结构）：性格不是形容词，而是 **7 个 1–5 刻度**（`社交度 / 表达量 / 节奏 / 好奇 / 秩序 / 情绪波动 / 亲密距离`）+ **1 个枚举**（冲突方式：`硬顶 / 回避 / 示弱`）；价值观 ≥1；禁忌 / 雷区 ≥1；说话风格＝句式模板 + 私人词汇包 10–20 词；知识边界（已知 / 未知 / 绝不可知）。另设 `never_do`（≤10 条，硬边界，永不变）与 `soft_limits`；字段矛盾标红并阻止「完成」；**OC 必须归属某个宇宙**。

* 规则（两种填法）：**选词法（默认）**—— 从 24 个性格词里挑 3–5 个，系统按内置映射折算刻度（同刻度累加后钳制 1–5）；**滑杆法（高级）**—— 直接拉 7 个滑杆 + 选 1 个冲突方式。选词法在含「冷脸 / 慢热」类词时**自动生成条件修正**（对关系档位 ≥3 的人社交度 +2），这就是「外冷内热」的实现；修正最多 3 条，每条 = `{when, axis, delta}`。

* 规则（漂移）：刻度每 30 天最多 ±1，由关系事件累积推动；`never_do` 与价值观永不改；说话风格只在玩家手动修改时变。**允许矛盾词**（如「自来熟 + 怕生」）：标红提示但不阻止，代价是行为会摇摆 —— 这是有意的创作空间。

* 规则（性格如何驱动行为）：每 2 秒为一个 OC 生成 4–6 个候选动作，按 `性格权重 × 需求紧迫 × 关系系数 × 可达性` 打分取最高；硬边界先过滤候选，不做事后检查；随机种子 = `universe_id + event_id`，保证同卡同场景可复现。

* 数据 / 判定：`oc{id, universe_id, name, profile, persona{axis{social, express, tempo, curiosity, order, volatility, proximity}, conflict(confront/avoid/yield), modifiers[{when, axis, delta}], vocab[10–20], cadence{len, question_rate, address}}, ooc_boundary{taboos[], never_do[], soft_limits[]}, summary, completion, version}`；完成度不足不能进入世界；修改从下一次事件生效，不回改历史记录。

* 验收：同卡、同场景、同种子两次行为一致；硬边界 0 违反；刻度 30 天漂移不超过 ±1；5 人盲测同一段录像对「是不是同一个 OC」判断一致。

* 来源：【原文】F07/A01/A02（2.2/6.2）；【补全】字段清单、完成度与「历史不回改」；【v1.5】性格由形容词改为 7 刻度 + 1 枚举 + 条件修正，并补打分公式与可复现种子。

* 画布：一格一豆，最大 40×40（自定 N 8–64）；常用档 15×15 / 21×21 / 29×29（市面拼豆图纸标准，新建默认）/ 40×40；**默认启动为空白画布**（不预置任何形象、不标色号，玩家自己拼）；改尺寸三选一（居中裁剪 / 扩展画布 / 整数倍最近邻重采样，非整数倍禁用），可预览 / 取消 / 撤销。

* 网格：**全部线为纯黑**（细线、粗线、外框统一黑色）；细线 1 设备像素、每 5 格一条 2 倍粗线，粗线以左上角 `(0,0)` 为固定原点并闭合外框；40×40＝8×8 大块，29×29／21／15 余块保留、不居中、不改格数；粗线默认开且可独立关；线宽按设备像素取整、线坐标与像素网格对齐，避免抗锯齿稀释成灰；落笔吸附整格；网格不进入导出矩阵。

* 工具：画笔 B（Bresenham 补点防断线）、油漆桶 G（当前层同色连通、容差 0）、橡皮 E（透明）、吸管 I（取合成色映射最近色号）、平移（空格 / 中键）、缩放 0.5–8x、撤销 Ctrl+Z、重做、图层切换 `[`/`]`、标记模式 M、部件打标 P、洋葱皮 O；右键拖拽临时橡皮；所有操作必须有可见反馈。

* 色号：MARD 标准色号体系。当前原型内置 **38 色常用子集**（H 灰白 7 / G 棕・肤 7 / E 粉 3 / F 红 5 / A 橙黄 3 / B 绿 3 / C 蓝青 6 / D 紫 4），色表见附录 A；界面按系列分组展示，支持直接输入色号（如 `C24` / `H2` / `D20`，与市售图纸色号对照）。全 291 色表待授权与版本核实后扩展，不阻塞当前绘制；`palette_version` 管理新增色，旧编号保留别名，历史作品锁版本；导入导出保留色号与 `palette_version`，缺色标「缺失色号」不静默近似替换。

* 填色渲染（v1.4 裁决）：填色格必须 `fillRect` 直角铺满整格（含四角），压住格线不留缝；空格内缩 1px 留出白缝；空格不标色号文字；外框在填色层之后最后绘制。

* 空 / 透明：空格 `color_id=null`，无像素、不统计；上色后每格必须绑定有效色号；橡皮为 `transparent`（显式记录、`alpha=0`），空与透明分账。

* 部件模型：`part{id, name, dictionary_type, parent_id, pivot, rotate_center, visible, order, layer_refs[{layer_id, cells[]}]}`；部件只保存 “哪些格属于我”，像素仍归图层，改色不改归属。**同一图层内一格只能归一个部件**；同一 `(x,y)` 在不同图层可分别归不同部件（外套层归外套、手层归手），跨层重叠不算冲突；不设 `exclusive_group`，不设主归属。重复标记已占用格必须弹 “替换 / 移除后加入 / 取消”，禁止静默覆盖。父子最多 3 层；每部件必须有锚点，默认包围盒中心（头发发根、眼睛中心偏下、下半身髋中线）；旋转按 90° 整数倍保存，自由角度仅预览。

* 词典：`head→hair→bangs`；`head→eye_l/eye_r、brow_l/brow_r、nose、mouth、ear_l/ear_r`；`body→upper_body→coat`；`body→lower_body→pants`；预留 `hand_l/hand_r、foot_l/foot_r、accessory`；标准 ID 不可改名删除；自定义挂标准类型或 `other`，个人词典 ≤20，可后续映射并保留别名。

* 标注与标记模式（v1.5 裁决：荧光笔感）：矩形框选、1/2/3 格刷选、魔法棒（当前层同色连通、容差 0、透明不参与）；选择不改像素、不进撤销；「打标 / 取消 / 重标 / 复制到其他层」各 1 步，共用 50 步撤销栈；跨层复制要求目标格已有像素且该层未占用。标记模式用按钮 / M 切换，与上色工具互斥；**11 个部件各固定一个高饱和荧光色**（见附录 B），以 α0.55 满格叠在底色上，像荧光笔划过 —— 不同部位一眼可分；颜色层与标记层独立开关；退出后已标记格仍可正常上色；标记撤销只回退归属与覆盖，不回退像素。

* 动画与导出：动画只引用部件 ID（眨眼 = 眼睛切帧 / 位移 1 格，说话 = 3 口型，走路 = 下半身交替，转头 = 头组绕锚点，头发 = 发根小幅旋转）；导出默认 PNG + JSON sidecar，必含 `parts[]`、按 `(layer_id,x,y)` 的唯一 `cell_membership`、`dictionary_version`、`color_system/palette_version`、尺寸 / 图层 / 顺序；导出前校验同层唯一归属，冲突阻止并列出冲突格；仅导 PNG 提示部件与色号丢失。

* 数据 / 判定：`artwork{id, universe_id, oc_id?, size, grid{minor:1, major:5, major_origin(0,0)}, color_system{name:"MARD", palette_version, source, verified}, layers[], palette[], parts[], animations[], marker_view, cover_frame}`；同层每格至多一个 `part_id`。

* 性能：40×40＝1600 格，全量重绘 ≤8ms，拖拽 ≥60fps；框选命中 ≤16ms，高亮 / 荧光笔重绘 ≤8ms，单格归属查询 ≤1ms；100 部件清单 ≥30fps；单作品内存 <20MB。

* 验收：15/21/29/40 与自定 N 均可建；粗线 3+1/4+4/6+2/8×8；同层重复打标必弹三选一且无法双重归属；跨层同位置可分别归属；父移动 / 旋转带动子；色号可定位、未命中不误上色、断网可用；荧光笔标注可切换 / 互斥 / 分色 / 独立开关 / 正确撤销；导出 JSON 可回读双矩阵、部件、层级、锚点与色号版本。

* 来源：【原文】F47/H13/F10（5.2/5.3/5.6）；【用户裁决】同层唯一归属、跨层可不同、MARD 色号体系（38 色内置）、空 / 透明、独立标记模式、40×40 与 5×5 粗线；【补全】锚点、词典、选区、导出与性能阈值。字体候选与许可证【需核实】。

#### R019 豆色与世界观色板 ｜ P0



* 规则：色号统一取自 MARD 标准（当前内置 38 色常用子集，附录 A）；创建宇宙推荐 6–12 色，玩家可增删至上限 24；拼豆 / 生成只用当前色板；任务、事件、图鉴可解锁限定色；限定色不跨宇宙通用；色板变更不影响已保存图纸历史颜色。

* 数据 / 判定：`palette{universe_id, colors[{code, hex, name, unlocked, source}]}`；`user_color_unlock`；导出必须携带色号与 `hex` 以保证还原；外部色值导入映射到最近色号；不提供付费抽色。

* 验收：切换宇宙后编辑器色板随之变化；未解锁色不可选；导出再导入颜色一致。

* 来源：【原文】F11（5.4/7.2）；【补全】上限、解锁来源与导出规则；MARD 38 色常用子集已于原型内置（附录 A），全表授权待核实。

#### R020 设定即任务 ｜ P0



* 规则：任务卡只存在于某个宇宙的创作台（无宇宙先走 R001）；首次进创作台出现 5 项任务卡（外貌 / 性格 / 边界 / 关系 / 图纸）；点击直达对应字段；完成打勾并给一次性奖励；可跳过但标 “未完成”；全部完成出现 “去戏台”；老玩家新建宇宙可复用模板。

* 数据 / 判定：`onboarding_task{task_key, status, reward_granted}`；任务与 R012 完成度联动；跳过不阻塞主流程；7 天未完成提醒一次；重复完成不重复发奖。

* 验收：5 项均可直达并完成；完成度实时反映到 OC 卡；全部完成后首次布景引导出现。

* 来源：【原文】F12（2.2/2.8/8.1）；【补全】5 项任务、奖励与跳过规则。

#### R021 自拼物件、部件与配方 ｜ P0



* 规则：部件分底座 / 主体 / 装饰 / 交互点；配方＝部件组合 + 尺寸 + 必要标签；物件尺寸 16×16/32×32/48×48（物件可大于角色）；产出默认归玩家自创并记录作者与宇宙；配方可复用、可分享，使用配方不消耗原件。

* 数据 / 判定：`part{id, name, type, matrix, anchor}`；`recipe{parts[], size, tags[], author, visibility}`；`item{recipe_id, author, source(diy)}`；缺主体 / 超尺寸 / 循环引用 / 缺作者均拒绝。

* 验收：同一配方产出 2 件独立物件；作者来源正确；删除配方不影响已产出物件。

* 来源：【用户原话】“岛上各种东西可以自己拼出来”【原文】D01/H10；【补全】部件类型、配方、尺寸与归属。

#### R022 预设物件获取 ｜ P0



* 规则：渠道＝初始赠送 / 任务奖励 / 商店 / 导入；新宇宙初始赠 3–5 件；任务奖励一次性；商店只卖外观与预设，不卖数值；每个预设必须有来源与版权字段（官方 / 授权 / 用户导入）；未知来源拒绝上架；跨宇宙默认需授权。

* 数据 / 判定：`preset{channels[], availability, license{type, source, commercial_use}}`；`grant{source, preset_id, user, universe, ts}`；重复领取不重复发；版权缺失拒绝。

* 验收：四渠道均可获得；分类 / 标签可筛选；无版权信息不可用；跨宇宙未授权不可用。

* 来源：【用户原话】“也可以获取游戏预设物件”【原文】D02/H11；【补全】四渠道、分类与版权标注。

#### R023 物件属性、可用性与沙盘行为 ｜ P0



* 规则：分类＝家具 / 装饰 / 道具 / 食物 / 特殊；行为属性＝可坐 / 可躺 / 可交互 / 可携带 / 可破坏 / 可进戏 / 可赠予，每属性有触发条件与冷却；可交互必须绑定 ≥1 动作；可破坏需二次确认、不得伤害 OC、破坏后留痕；装饰物只作装饰；属性冲突标待确认。

* 数据 / 判定：`item.behavior{sit, lie, interact, carry, breakable, stage, giftable, cooldown, actions[]}`；`item_event{action, result, ts}`；无绑定动作的交互物不可用；属性与场景冲突置灰。

* 验收：椅子可坐、门可交互、花瓶可破坏但有确认；装饰物不产生交互；属性变更后下一次行为生效。

* 来源：【原文】D03/H12；【补全】行为属性清单、冷却与安全限制。

### 4.3 M2 角色岛与日常

#### R024 小岛沙盘与时间同步 ｜ P0



* 规则：岛上时间与现实同步（**1 游戏日 = 现实 20 分钟**，1x 基准；8x 时 2.5 分钟，见 §12.1 X01-b）；日程分晨 / 日 / 昏 / 夜四段；无网络时本地时钟继续推演，**按 1x 结算、不随倍速放大，上限 7 个游戏日**；超过按 “沉睡” 处理，只补关键事件；同一时刻同屏 OC 上限按性能档 4/8/12；跨午夜正确切换。

* 数据 / 判定：`island{id, universe_id, time_mode, day_phase, layout}`；`schedule{oc_id, phase, activity}`；`world_clock{now, last_tick}`；时间跳变超过 5 分钟需重新校准并提示。

* 验收：8 小时后 OC 位置与行为符合其作息；跨天不重复结算；断网 72 小时内行为连续。

* 来源：【原文】F13/B06；【补全】时间倍率、72 小时上限与同屏上限。

#### R025 自由行为引擎（六步可审计） ｜ P0



* 规则：固定六步 —— 感知快照 → 意图生成 → 候选 1–3 → 四层过滤 → 执行与表现 → 写记忆；优先使用模板 / 规则，全部由模板与规则决策，不做模型调用；常规日外部调用次数 0；同一 OC 两次意图最小间隔 30 秒；意图不得越出可活动区；每步写 trace。

* 数据 / 判定：`behavior_trace{trace_id, oc_id, perception_id, intent, candidates[], filtered_reason, action, memory_id, ts}`；`intent` 必须含目标与理由；候选为空转 idle；trace 保留 7 天，供 “为什么这样做” 查询。

* 验收：每次可见行动都有完整 trace；常规日不产生外部调用；行为不越界；过滤理由可解释。

* 来源：【原文】F44/B04/C02/H05；【补全】30 秒间隔、trace 保留期；【v1.4】去掉「何时调模型」，全部走模板。

#### R026 感知快照 ｜ P0



* 规则：只采集当前场景可见信息（在场 OC、物件、时间、天气、最近事件）；不读取其他宇宙、未在场 OC 的私密记忆、玩家未公开内容；快照 5 分钟过期；知识边界外信息不进入候选；缺字段用默认值。

* 数据 / 判定：`perception{id, oc_id, scene, visible_ocs[], items[], time, weather, recent_events[], knowledge_scope}`；`knowledge_scope` 与 R012 对齐；过期快照不得复用。

* 验收：不在场 OC 不出现在快照；私密内容不泄漏；删除物件后快照不再引用。

* 来源：【原文】C01；【补全】5 分钟过期与默认值。

#### R027 候选行为与约束过滤 ｜ P0



* 规则：每轮 1–3 个候选，必须带目标、动作、预期结果；过滤顺序＝角色硬禁忌 → 创造者边界 → 世界规则 → 场景 / 关系约束；任一硬层命中即淘汰并记录原因；软层可按权重降级；同输入同状态选择稳定（可 seeded）。

* 数据 / 判定：`candidate{action, target, reason, score, filtered_by}`；`filter_result{layer, rule_id, decision}`；无候选转 idle 并写 “无事可做”。

* 验收：禁忌候选 100% 不执行；过滤顺序可回放；同一 seed 重放结果一致。

* 来源：【原文】C03；【补全】字段、seed 与 idle。

#### R028 可活动范围与行为白 / 黑名单 ｜ P0



* 规则：初始化定义可行走区（格子 / 多边形）；行为白名单限定可用动作；黑名单限定不可用动作；黑名单优先于白名单；未定义区域视为不可行走；玩家可逐区开关；变更即时生效。

* 数据 / 判定：`nav_area{polygon}`；`behavior_policy{whitelist[], blacklist[]}`；黑名单并集；路径不可达时选最近可达点并提示。

* 验收：OC 不出可行走区；黑名单动作 100% 不执行；白名单外动作不可选。

* 来源：【原文】C04；【补全】黑名单优先与不可达降级。

#### R029 世界规则 ｜ P1



* 规则：规则分硬规则（不可违反）与软规则（可降级）；来源分官方 / 玩家 / 系统安全；玩家可新增，但不能删除系统安全规则；冲突取更严；规则必须写明适用范围与例外。

* 数据 / 判定：`world_rule{id, level, scope, text, source, active}`；`rule_conflict{winner, reason}`；未写范围的规则不得启用；规则变更需确认。

* 验收：硬规则不可被角色边界放宽；玩家删除安全规则时被拒；冲突有可读理由。

* 来源：【原文】C05；【补全】规则字段与安全规则不可删。

#### R030 岛布局与物件摆放 ｜ P1



* 规则：网格化摆放，同格不重叠；物件可旋转 90° 整数倍；越界自动钳制到最近合法格；事件可改变布局（如搬家），变更进入可回滚队列；玩家手动编辑优先于事件自动变更。

* 数据 / 判定：`layout{grid, items[{item_id, x, y, rotation, layer}]}`；`layout_change{source(manual/event), before, after}`；保留最近 5 次；同一变更重复应用幂等。

* 验收：同格摆第二件时提示并偏移；演后布局真实改变；回滚 5 次可用。

* 来源：【原文】B05；【补全】旋转、钳制与回滚队列。

#### R031 观察与点击互动 ｜ P0



* 规则：点击 OC 打开底部互动面板，四个主按钮＝打招呼 / 聊天 / 送礼 / 查看状态；聊天为短句，不进入自由多轮长对话；每次互动必须有可见反馈并写记忆；同一 OC 每日 ≤20 次，间隔 10 秒；重复点击同一内容不重复写记忆；互动前过 OOC 前置校验。

* 数据 / 判定：`interaction{oc_id, type, input, response, memory_id, ts}`；`daily_counter{oc_id, date, count}`；超限提示 “今天聊够了”；响应失败用角色内短句兜底。

* 验收：每次互动均有动画 / 文字 / 音效之一；记忆去重；超限被拦；越界输入被安全回复。

* 来源：【原文】F14/B02；【补全】四按钮、每日上限、冷却与去重。

#### R032 送礼与物件归属 ｜ P0



* 规则：玩家在岛上给 OC 送礼，每日 ≤3 次；礼物需在玩家持有物中；OC 按偏好 / 关系 / 场景决定接受或婉拒；接受后物件所有权从玩家转移至 OC（或岛），玩家不可再直接收回；婉拒也写事件；同一物件不可重复赠送；送礼可影响关系强度（单次 ≤20）。

* 数据 / 判定：`gift{from, to, item_id, status(accepted/refused), relation_delta, memory_id}`；`ownership{item_id, owner_type(player/oc/island)}`；所有权变更需原子性；礼物被删则事件保留。

* 验收：送 3 次后第 4 次被拦；接受后物件出现在 OC 持有列表；婉拒有明确反馈且留痕。

* 来源：【原文】F15/D04；【补全】每日上限、偏好判定、所有权与幂等。

#### R033 物件影响行为与记忆 ｜ P1



* 规则：交互物进入候选行为池（如椅子→坐下、床→睡觉、书→阅读）；物件偏好标签影响选择权重；使用后写记忆并附物件 ID；可破坏物被破坏后从布局移除并留事件；物件不得伤害 OC 或改变硬边界。

* 数据 / 判定：`item.behavior` 与 `memory{refs[]}` 双向引用；物件下架但已存在时可继续使用；缺失物件回退普通动作；破坏需确认。

* 验收：有椅子时 OC 会坐；偏好匹配提高选择率；破坏后不再出现。

* 来源：【原文】D05；【补全】候选池、偏好权重与移除规则。

#### R034 回忆碎片 ｜ P1



* 规则：每日 1–3 次，在岛内以气泡 / 短动画呈现；内容取自 OC 记忆，优先 7 天未被引用的；时长 5–15 秒，可点击展开可收藏；受 OOC 与可见性约束；不展示玩家私密原文。

* 数据 / 判定：`memory_fragment{memory_id, oc_id, shown_at, collected}`；同一记忆 7 天内不重复；错过可进纪念册；无记忆时不生成。

* 验收：碎片内容有来源记忆；7 天去重；可收藏并在纪念册可见。

* 来源：【原文】F16；【补全】频次、时长、去重与收藏。

#### R035 人设守护日志 ｜ P1



* 规则：只在真实发生硬拦截、软改写、玩家诱导被拒时记录；不记录内部判断过程；每条含时间、触发输入摘要、命中约束、处理方式；每日 ≤5 条；不复述雷区原文；用户可删除，删除后不再引用。

* 数据 / 判定：`guard_log{level, rule_id, input_summary, action(block/rewrite/refuse), ts}`；日志默认私密；按 OC 可筛；导出不含原文；删除为软删并断开引用。

* 验收：一次真实越界产生 1 条；无越界不产生；日志不含禁忌原文；删除后生成不再引用。

* 来源：【原文】F17；【补全】触发条件、字段、上限与删除。

#### R036 离线事件报告 ｜ P1



* 规则：离线 ≥1 个游戏日（20 分钟）生成；报告 1–3 件事，含时间、地点、参与者、结果；全部模板文案；事件来自离线推演且符合 R025 过滤；只弹一次，可 “查看详情 / 去找他 / 知道了”；不重复写入。

* 数据 / 判定：`offline_report{start, end, events[], generated_by, read_at}`；离线 <2h 不生成；72h 以上只补关键事件；事件引用失效时用摘要。

* 验收：离线 8 小时有报告；随机 3 件事可定位到 OC / 地点；重复登录不重复弹。

* 来源：【原文】F18；【补全】2 小时阈值、模板文案与只弹一次。

### 4.5 M4 沉淀

#### R047 纪念册时间线 ｜ P0



* 规则：纪念册是该宇宙的共同记忆事实源；按时间倒序；每条含事件、参与 OC、地点、来源（事件池 / 互动 / 离线报告 / 送礼）；可筛选角色 / 类型 / 时间；事件发生后自动写 1 条；同一事件只保留 1 条；纪念册默认私密，不自动进入公开页。

* 数据 / 判定：`memorial_entry{universe_id, type, title, summary, refs[], actors[], visibility, official, created_at}`；引用被删时保留快照摘要；不覆盖旧条目；可按 OC 聚合。

* 验收：事件后 1 条；筛选正确；引用删除仍可读；私密不外泄。

* 来源：【原文】F25；【补全】事件类型、官方版与快照。

#### R048 关系天平与关系活地图 ｜ P0



* 规则：关系值统一为 0–100 双向（按 R014）；单事件变化 ≤20；每日无事件回落 1；双向独立；地图以 OC 为节点、关系为边，支持按类型 / 强度过滤；点击边显示事件；只展示玩家有权查看的关系。

* 数据 / 判定：`relation_state{strength_ab, strength_ba, status, last_event}`；`relation_heatmap` 由事件派生；孤立 OC 单列；不公开展示他人关系。

* 验收：送礼 / 事件改变关系且可追溯；天平双向不同；地图过滤正确。

* 来源：【原文】F26；【补全】回落、过滤与可见性。

#### R049 岛与道具改变 ｜ P1



* 规则：事件可触发预定义改变（搬家 / 换家具 / 物件损坏 / 新增装饰）；改变必须来自事件模板且玩家可见提示；进入可回滚队列最近 5 次；手动编辑优先；同一事件不重复应用。

* 数据 / 判定：`island_change{type, target_id, before, after, source_event, applied_at}`；`idempotency_key = event_id + change_id`；回滚需确认。

* 验收：演 “搬家” 后布局真实改变；回滚 5 次可用；重播不重复。

* 来源：【原文】F27；【补全】预定义类型、提示、幂等与回滚。

#### R050 收藏图鉴 ｜ P2



* 规则：图鉴分 OC / 色号 / 事件 / 物件四册；新内容首次获得自动点亮；删除内容不回收图鉴；与角色卡册分开；显示获取时间与来源；不展示未解锁内容详情。

* 数据 / 判定：`collection_entry{type, ref_id, unlocked_at, source}`；`collection_progress` 派生；重复获得不重复计数；跨宇宙可汇总但标注来源。

* 验收：新 OC / 色号 / 事件自动点亮；删除后仍显示；未解锁不剧透。

* 来源：【原文】F28；【补全】四册、来源与汇总规则。

### 4.6 M5 多宇宙

#### R051 宇宙管理、隔离、切换与归档 ｜ P1



* 规则：所有实体（OC / 关系 / 物件 / 纪念册 / 事件 / 缓存 / 记忆）必须带 `universe_id`，查询与事件默认按宇宙过滤；切换只换视图，不把 A 宇宙实体拖入 B；跨宇宙引用一律只读快照；复制必须显式 “复制到我的宇宙” 并生成新 ID；归档宇宙只读、可回访、不参与计费；删除按 R008 分级执行。

* 数据 / 判定：`universe_ref{universe_id}`；`cross_universe_ref{source_universe, target_universe, snapshot_id, mode(readonly/copy)}`；隔离测试：A 的记忆不出现在 B 的检索；归档不可写；删除前检查引用。

* 验收：切换宇宙后 OC / 物件 / 纪念册均不串；跨宇宙只读；归档可回看；删除有引用时列出。

* 来源：【原文】F29/B03/H09；【用户裁决】“宇宙必须隔离”；【补全】实体字段、只读引用与归档语义。

#### R052 宇宙解锁节奏与门控 ｜ P1



* 规则：新建第 2 个宇宙，要求当前宇宙达到 **L3 有生活**——≥2 个 OC 完成卡并入住、≥1 条双向关系事件、日常事件池连续运行满 14 天；新建第 3 个要求当前宇宙达到 **L4 有沉淀**—— 纪念册 ≥5 条且至少一组关系升到第 2 档。任何时刻「未完成的新宇宙」≤1；同时 active ≤3；禁止付费 / 道具 / 任何形式跳过；**新宇宙建成后 7 天内不能建下一个**（冲动是即时的，等级挡不住它）；已建宇宙 14 天无 OC 时提示归档或邀请，不自动删除。

* 口径：**门控不用剧情进度**—— 剧情是玩家自己编的，自己判自己「完成」等于没有门控；只用可观测的使用痕迹（OC 数、入住天数、关系事件、事件天数、纪念册条数）。原「关键节点 100% + 官方演出 ≥ 节点数 + 1 + 账号等级 L5/L8/L10」三条件在有演绎与账号体系时再作为加严项，本期不适用。

* 数据 / 判定：`universe_maturity{universe_id, level(1–4), oc_ready_count, days_since_first_oc, relation_events, event_days, memorial_count}`；`unlock_gate{target_universe, unmet[]}`；`cooldown{next_allowed_at}`。

* 验收：L2 宇宙不能建第 2 个；事件池未满 14 天仍锁定；L3 解锁后 7 天内再点新建被拦；第 4 个 active 被拦；无任何跳过入口。

* 来源：【原文】F30/I09–I11；【用户原话】「防摊大饼」；【裁决】v1.4 指标改为宇宙成熟度（原节点 + 演出 + 账号等级随演绎删除而失效）。

#### R053 跨宇宙客串 ｜ P1



* 规则：客人 OC 进入宿主宇宙，单场 ≤2 人；时长三选一（单场 / 1 游戏日 / 3 游戏日），到期自动返回；宿主主权五级 —— 宿主世界观卡 > 宿主角色硬禁忌 > 双方软边界交集 > 客人角色设定 > 客人原宇宙惯例；冲突时宿主卡与硬禁忌优先，其次取双方更严；文化冲突只作为候选事件，需玩家确认才发生；客串期间只共享 “共同记忆摘要”，不读写对方私密纪念册；客人不得修改宿主布局 / 关系 / 物件归属；离开时生成一份双方可见的客串记录。

* 数据 / 判定：`guest_session{guest_oc, host_universe, duration, sovereignty_log[], shared_memory_summary, status}`；`guest_boundary = host_hard ∩ guest_hard ∩ (host_soft ∩ guest_soft)`；硬层取并集（任一禁止即禁止），软层取交集（双方都允许才允许）；超 2 人拒绝；到期强制返回并留记录。

* 验收：客人不能突破宿主 `never_do`；双方软边界冲突时取更严；客串记忆不进入对方私密纪念册；到期自动返回。

* 来源：【原文】F31/I05–I08；【用户裁决】“客串边界取交集、宿主主权”；【补全】五级顺序、时长与共同记忆摘要；原 F31 标 P2，项目书要求提前，按 P1。

* 违和点（v1.4 补）：客串开始前，系统比对双方世界观卡的**语言腔调 / 时代氛围 / 拼豆色板**三项，产出 1–3 个「违和点」（如「文言腔 × 现代奶茶店」「冷色板 × 暖阳小镇」），喂进日常事件池的模板插槽，0 次模型调用即可生成「他用文言腔点了杯奶茶，老板愣了三秒」这类小事；违和点只作候选，需玩家确认才发生。客串者保留**原宇宙**色板与腔调，画面上一眼是外来者。

* 数据补充：`culture_clash{guest_card_hash, host_card_hash, points[{dim, guest_val, host_val}], adopted[]}`；未确认的违和点不写入事件。

* 验收补充：进入前能看到 1–3 个违和点；确认后才发生；客串者立绘配色与宿主场景形成可见差异。

#### R054 宇宙图鉴 ｜ P2



* 规则：每个宇宙建成即生成唯一编号（如 `U-0001`）；记录名称、世界观卡摘要、风格标签（≤3 个，可后补）、完成度（派生，不手填）、创建时间；可只读分享；不公开私密内容；删除宇宙后编号保留不可复用。

* 数据 / 判定：`universe_codex{code, universe_id, name, card_summary, style_tags[], completion, created_at}`；完成度由 OC 数 / 事件数 / 图鉴派生；分享只读快照。

* 验收：建成自动编号；标签可补但不超 3；完成度随进度变化；删除后编号不复用。

* 来源：【原文】I04；【补全】编号格式、派生完成度与只读分享。

### 4.7 M6 社交（四层结构）

#### R055 私密宇宙与默认私密 ｜ P0



* 规则：新宇宙、新 OC、新事件、新纪念册、新物件默认 `private`；他人任何视图只能看到只读快照，不能看到边界原文、记忆原文、草稿、未公开内容；私密内容不进入搜索 / 推荐 / 广场；公开是逐条动作，不继承；关闭公开页不影响已授权的好友访问（按条目授权）。

* 数据 / 判定：`visibility` 默认 `private`；`snapshot{source_id, allowed_fields[], version}`；快照字段白名单不含 `never_do/soft_limits/memory_raw`；越权请求返回 403。

* 验收：新内容默认私密；他人视图无敏感字段；关闭公开页后好友授权仍按条目有效。

* 来源：【原文】F60/K01/J01；【用户裁决】“默认私密、先有可晒内容再谈社交”；【补全】快照字段白名单。

#### R056 好友关系、请求、分组与拉黑 ｜ P0



* 规则：加好友需双向同意；请求 7 天过期；拒绝后 24 小时冷却；好友上限 200、分组 50、单分组 20；分组只影响展示与批量授权，不影响既有授权；拉黑立即断开所有授权、停止手信与通知；解除拉黑不自动恢复授权。

* 数据 / 判定：`friend_request{from, to, status, expires_at}`；`friendship{status, groups[], since}`；`block{from, to, ts}`；拉黑为最高优先级；被拉黑方不可再发请求。

* 验收：单向请求不成为好友；过期自动失效；拉黑后岛门 / 手信立即不可用；解除拉黑需重新授权。

* 来源：【原文】F61/K02/J02；【补全】上限、冷却与拉黑语义。

#### R057 岛门授权与串门 ｜ P0



* 规则：岛门默认关闭；授权三种 —— 一次性（进入 1 次后失效）、长期（7/30 天可续；永久默认不提供，见 Q23）、白名单（指定好友）；可限定区域（客厅 / 花园 / 全岛）、是否允许看到 OC 在场、是否允许互动（只读 / 打招呼 / 送礼）；玩家可随时撤销，撤销后 3 秒内断开；访客只能看到授权区域与公开内容；每次进入留痕 30 天。

* 数据 / 判定：`island_gate{host_universe, grantee, mode(once/long/whitelist), areas[], scopes[], expires_at, revoked_at}`；`visit_log{visitor, entered_at, left_at, areas[], actions[]}`；授权不可转让；越区访问拒绝。

* 验收：未授权无法进岛；一次性进入后失效；撤销 3 秒内生效；访客看不到未授权区域与私密纪念册。

* 来源：【原文】F62/K03/J03；【补全】区域、权限分层与撤销时限。

#### R058 手信赠送与记忆归属 ｜ P0



* 规则：手信只能送给好友；每日 ≤3 次、同一好友 7 天 ≤10 次；手信携带赠送者、时间、来源宇宙、物件 / 文本与一条 “共同记忆摘要”；对方接受后写入对方 OC 记忆，赠送方保留一条共同摘要，私密细节归收件方；7 天未领取自动退回；拉黑即退回；手信不可转赠；不接受不产生记忆。

* 数据 / 判定：`handletter{from, to, source_universe, item_ref, memory_summary, status(pending/accepted/returned/expired), expires_at}`；`memory.origin(handletter_id)`；归属不可篡改；重复领取幂等。

* 验收：跨宇宙手信带来源标识；7 天退回；拉黑即退；拒收不写记忆。

* 来源：【原文】F63/K04/J04；【补全】频率、来源字段、退回与幂等。

#### R060 图纸市场 ｜ P1



* 规则：上架需公开可见 + 来源 / 版权字段完整；获取方式三选一（免费 / 兑换码 / 条件领取如关注）；来源署名不可移除；可二次修改但需标注 “改编自”；下架后不可再分发，已获取仍可用；不得上架他人未授权内容。

* 数据 / 判定：`market_listing{artwork_id, author, license, acquire_mode, status}`；`acquire_record{user, listing, ts}`；版权缺失拒绝；举报下架进入 R068。

* 验收：三种获取方式可用；署名保留；下架后新用户不可获取；改编标注可见。

* 来源：【原文】F65/K06/J06；【补全】上架条件、获取方式与下架语义。

#### R063 世界观模板广场 ｜ P2



* 规则：只提供世界观卡结构与风格标签，不含具体 OC / 纪念册；领取生成副本并保留来源；可评分 / 收藏；不得冒充原作者；模板可二次修改。

* 数据 / 判定：`world_template{card_structure, tags[], author, license}`；领取记录；来源署名保留；举报处理同 R068。

* 验收：领取后是副本；来源保留；不含他人私密内容。

* 来源：【原文】F68/K09/J09；【补全】副本、署名与许可。

#### R064 公开页与 OC 展示柜 ｜ P0



* 规则：公开页默认关闭；开启后展示 OC 12 个、事件卡 6 条、图纸 12 张；可置顶 1 个 OC；陌生人可见但不可进岛、不可私信、不可下载原件；展示他人 OC 需授权；下架条目 404；公开页不等于把纪念册公开。

* 数据 / 判定：`public_page{owner, enabled, pinned_oc, showcase[], visibility}`；`showcase_entry{type, ref, authorization, order}`；超限拒绝；未授权条目不可上架；关闭后全部 404。

* 验收：默认关闭；限额生效；陌生人无法进岛；未授权 OC 不可展示；关闭即 404。

* 来源：【原文】F69/K10/J10；【裁决】F69 由 P1 上调 P0，作为社交 MVP 出口；【补全】限额与授权。

#### R065 精选世界与策展 ｜ P1



* 规则：只从公开且过审的世界快照中选择；标准公开（主题 / 完成度 / 原创性 / 无争议）；每期 ≤20；作者可拒绝入选；入选不改变归属与收益（本期无收益）；连续 2 期不活跃可下榜。

* 数据 / 判定：`curation{period, entries[], criteria, author_consent}`；未过审不可选；拒绝即移除；下榜留记录。

* 验收：未过审不可入选；作者拒绝生效；每期不超 20。

#### R066 图纸名片与陌生人入口 ｜ P1

### 5.2 关键状态机



* **生成任务**：`queued → running → (paused ⇄ running) → completed | failed | cancelled`；取消 / 失败清理临时结果；`idempotency_key` 防重复；连续 3 次失败 → 熔断 10 分钟。

* **事件**：`pending → active → resolved | expired`；`resolved` 写 1 条纪念册；`expired` 不写；同一事件不重复应用。

* **好友 / 岛门**：请求 `pending → accepted | refused | expired`；岛门 `closed → granted(once/long/whitelist) → revoked | expired`；撤销 3 秒断开；拉黑覆盖一切。

* **宇宙**：`draft → active → archived → deleted`；`draft` 转 `active` 的条件＝世界观卡四项基准齐（不要求有 OC）；`archived` 只读；`deleted` 按 R008 软删 30 天。

* **删除**：`active → archived → soft_deleted(purge_at) → purged`；永久删除需名称确认；有引用未处理则拒绝。

* **客串**：`invited → active → returning → ended | cancelled`；到期 / 手动 / 宿主撤销均返回；共同记忆摘要最多 1 条。

### 5.3 全局不变量



1. 任何实体必须有 `universe_id`（账号 / 系统级对象除外），跨宇宙访问默认只读。

2. 任何行为 / 事件必须携带 `world_card_version` 与 `constraint_pack.hash`。

3. 任何关系变化必须有 `relation_event`；任何事件必须有 `event_record`；任何公开内容必须有 `visibility_setting`。

4. 边界、记忆、草稿、密钥永不出现在公开 / 分享快照中。

5. 删除是软删优先；引用未处理不得永久删除。

### 6.3 OOC 四层约束与越界判定



| 层          | 内容                      | 来源         | 优先级 | 可否放宽                   |
| ---------- | ----------------------- | ---------- | --- | ---------------------- |

| L3 世界规则    | 世界观卡、语言腔调、时代、色板、官方安全规则  | 宇宙 / 系统    | 中   | 玩家可加严，不可删安全规则          |

**越界判定**：

> 说明：四层不是 “四选一”。硬层（L1 角色硬约束、L3 中的世界硬规则 / 安全规则）之间冲突一律取更严，世界观卡是宇宙宪法，不得被角色或场景放宽；L2/L4 只能加严，不能反向覆盖。表中优先级仅用于同一层内或无法比较时的裁决顺序。



| 级别  | 定义                               | 检测        | 处置                       |
| --- | -------------------------------- | --------- | ------------------------ |
| 硬越界 | 命中 `never_do`/ 雷区 / 安全规则 / 知识边界  | 规则 + 模型双检 | 直接拦截，0 落库；必要时角色内拒绝；写守护日志 |
| 软偏离 | 语气、关系称呼、尺度偏离 `soft_limits`/ 世界规则 | 规则 + 模型   | 改写重检，最多 2 次；仍失败用安全模板     |
| 漂移  | 长文中角色 / 关系 / 设定逐渐不一致             | 分段一致性检查   | 标记问题段落，重写 1 次，仍偏标记不静默通过  |

**裁决顺序**：L1 > L2 > L3 > L4；硬层取并集（任一禁止即禁止），软层取交集（双方都允许才允许）；跨宇宙客串时再叠加宿主主权（宿主卡 > 宿主硬禁忌 > 双方软交集 > 客人设定 > 客人原宇宙惯例）。**0 泄漏是验收底线**。

## 7. 异常与降级

**原则**：任何失败必须有可见反馈（禁止静默失败）；优先保数据，其次保流程，最后保体验；降级不得伪造成功，不得越过 OOC 与可见性边界。



| 场景        | 触发           | 用户可见                     | 系统处理与降级                              |
| --------- | ------------ | ------------------------ | ------------------------------------ |
| 启动崩溃 / 白屏 | 资源损坏、版本不匹配   | 错误页 + “安全模式 / 重试 / 导出诊断” | 安全模式禁用动画与插件；保留最近存档；诊断包脱敏、无密钥         |
| 存档写入失败    | 磁盘满、权限、文件锁   | “保存失败，已保留内存副本”           | 重试 3 次；转临时文件；提示清理；退出前再次确认            |
| 云同步冲突     | 两端并发编辑       | 冲突列表                     | 纪念册条目人工选；其余按版本号 + 时间；本地副本保留；不静默覆盖    |
| 存档损坏      | 断电、坏块        | “已恢复到最近快照”               | 校验 hash；回滚最近 20 快照；仍失败进入只读导出模式       |
| 密钥泄露风险    | 日志 / 导出 / 分享 | 无（后台阻断）                  | 全链路脱敏扫描；发现即阻断并提示；密钥仅本地；删除配置即擦除       |
| 行为 / 事件越界 | R082 四层命中    | 角色内拒绝 / 转为安全行为           | 拦截 0 落库；兜底通用行为；写守护日志；不泄露原文           |
| 动作缺失      | 动作不在库        | 静止 + 通用动作                | 不阻断事件；记录降级点；提示补动作库                   |
| 地图素材缺失    | 物件 / 瓦片被删    | 占位图 + 提示                 | 用纯色占位；不空白画面                          |
| 布局冲突      | 同格摆放 / 越界    | 高亮冲突 + 偏移建议              | 钳制最近合法格；不可解则拒绝；可撤销                   |
| 关系引用失效    | OC 被删 / 边被删  | “关系已失联”                  | 用快照摘要；不虚构新人；事件按 “陌生” 降级              |
| 记忆检索失败    | 索引损坏 / 超时    | “记忆暂不可用”                 | 回退结构化事件；不带原文；重建索引；不阻塞事件              |
| 手信超时 / 拉黑 | 7 天未领 / 被拉黑  | “手信已退回”                  | 原子退回；写通知；不写对方记忆；可重发（限频）              |
| 岛门撤销      | 宿主撤销 / 到期    | 访客 3 秒内断开                | 立即失效；留痕 30 天；不删除访客本地快照               |
| 公开内容被举报   | 举报成立         | 作者收到处置与申诉入口              | L1–L4；24/48h 时限；下架 404；申诉 7 天；未成年转人工 |
| 分享链接失效    | 撤销 / 过期 / 删除 | 404 + “内容不可见”            | 快照按 `expires_at` 失效；不泄露原内容是否存在       |
| 存储 / 内存不足 | 大图纸 / 多 OC   | “已降档 / 请清理”              | 降分辨率 / 降同屏；清理缓存；保留存档；不丢用户创作          |
| 字体 / 色号缺失 | 资源未加载 / 离线   | 占位字体 /“缺失色号”             | 不静默近似替换；布局不崩；提示补资源；导出标缺失             |

## 8. 非功能要求

### 8.1 性能



| 项   | 要求                                                                         |
| --- | -------------------------------------------------------------------------- |
| 启动  | 冷启动 ≤5 秒进入首屏；桌宠 ≤5 秒出现                                                     |
| 沙盘  | 中档设备 8 OC ≥30fps；低档 4 OC ≥30fps；单帧逻辑 ≤16ms                                 |
| 编辑器 | 40×40 全量重绘 ≤8ms；拖拽 ≥60fps；框选命中 ≤16ms；单格归属查询 ≤1ms；100 部件 ≥30fps；单作品内存 <20MB |
| 生成  | 首字 / 首段可感知 ≤5 秒（受服务商影响）；长文分段可续；超时按 R077                                    |
| 存档  | 自动存档不阻塞交互；快照恢复 ≤3 秒；云同步增量                                                  |

### 8.2 离线与弱网



* 无网可完成建卡、建岛、拼豆、模板生成、事件与纪念册的回看；离线推演 ≤7 个游戏日（按 1x 结算）；超过按 “沉睡” 补关键事件。

* 所有写操作本地先行；联网后增量同步；冲突按 R006；离线不调用外部模型；缓存按宇宙隔离。

* 弱网下生成可取消 / 重试；不重复落库；不伪造 “已发送”。

### 8.3 隐私与数据



* 默认私密；最小采集；不采集与功能无关的个人信息；匿名可玩。

* 密钥仅本地加密；日志 / 导出 / 分享 / 诊断包全链路脱敏；云端只见 “配置存在” 标记。

* 删除分级；注销清除云端 + 本地密钥；软删 30 天；备份中的删除在周期内生效（周期需核实）。

* 可见性逐条授权；撤销即时；审计留痕；不向第三方出售 / 共享用户内容（除法律要求，需法务确认）。

### 8.4 内容安全



* 输入 / 输出双过滤；覆盖违法、色情、暴力、未成年不适、仇恨、自伤；策略不可关闭；涉及未成年更严并转人工。

* OOC 四层约束 + 前后置校验；0 泄漏；拦截不复述原文；守护日志默认私密。

* 公开内容先审后发；举报 — 处置 — 申诉闭环；版权 / 署名 / 改编标注；侵权投诉渠道（细则需核实）。

### 8.5 可靠性与兼容



* 关键路径（存档 / 授权 / 举报 / 删除）联网优先、可重试、可恢复；非关键路径可降级。

* 平台范围（v1.5 已定，见 §12.17）：**移动端优先**（iOS / Android，横屏为主）；PC / Steam 后置、不排除；桌宠移动端不实现（iOS 无系统能力），保留为 PC 后置能力。

* 分辨率：手机横屏 852×393 起（地图 1x 居中），高 DPI 适配（DPR 2–3）；**整数倍缩放、禁插值**；触控热区 ≥44pt；减少动效模式；色弱可辨（标记纹理 + 文字，见 §12.14）。

* 版本升级兼容旧存档；迁移前备份；不可逆迁移需确认；旧版本至少可导出。

### 8.6 可维护与可观测



* 所有生成 / 行为带 `constraint_pack.hash` 与 `world_card_version`，可复现；trace 保留 7 天。

* 关键指标：建界完成率、拼豆完成率、布景使用率、事件产出率、越界拦截数、存档恢复率、举报处置时长。

* 日志分级与脱敏；不记录密钥、边界原文、私密记忆原文；诊断包需用户确认后导出。

### 12.0 一句话

玩家拿到的不是编辑器＋文本框，而是一个**能住人的像素世界**：角色卡是身份证，衣柜是换装层，地图是舞台，事件池是内容发动机。

玩起来像**一个蚂蚁箱**：你搭好环境、丢点东西进去，然后隔着玻璃看它们自己忙；你能做的只有摆、挪、拎、喂、改地形，**不能指挥它们今天干什么**—— 就像养蚂蚁的人会晃动盒子、把蚂蚁拨到别处，但没法命令它去搬哪粒米。观察类游戏的乐趣不在「我让它做什么」，而在「它居然自己做了这个」。

三条硬决策（本期的技术边界，改动前须重新评估产能）：



| 决策 | 取值                                | 为什么                               |
| -- | --------------------------------- | --------------------------------- |
| 视角 | 斜俯视瓦片；角色**单朝向**，左右移动用镜像翻转         | 玩家只画一张立绘；四方向会把作画成本 ×4，且拼豆立绘没有自然背面 |
| 地图 | 地图＝瓦片级「大拼豆矩阵」，复用同一编辑器             | 一套编辑器通吃角色 / 物件 / 地图，零美术资产         |
| 穿戴 | 穿戴物＝**图层**：默认一层衣服可替换，饰品另开层叠加，均可盖脸 | 本体矩阵只读，脱掉即完全还原                    |

### 12.1 世界地图（X01 地图规格与渲染）



* 空间：瓦片 16×16 设备像素；默认地图 20×15 瓦片（＝320×240 逻辑分辨率）；可选 8×6 – 64×48。

* 渲染：逻辑分辨率整数倍放大（2x/3x/4x），`imageSmoothingEnabled=false`；UI 与地图同一缩放栅格，禁止 1.5x 等非整数倍。

* 角色站位：立绘 29×29 按 **1 豆＝1 设备像素** 渲染（≈1.8 瓦片），占格取 2×2 瓦片，脚点底边中点为锚；碰撞盒只取脚下 1×1；**深度排序按脚点 y**，同 y 按 x，遮挡关系正确。

* 碰撞：瓦片属性表＝可走 / 不可走 / 可交互 / 可放置；角色碰撞盒只取脚下 1×1；寻路用 A\*（BFS 兜底），不可达就近取点。

* 性能：单图 ≤64×48 瓦片时整图预渲染到离屏画布，逐帧只绘制动态层与角色；目标 30fps（中档设备）。

* 验收：手机横屏 1x 下地图完整可见无裁切、2x 查看无模糊（整数倍、`imageSmoothingEnabled=false`）；角色绕树走不会穿模；同屏 4 个 OC ≥30fps、8 个 OC ≥24fps（移动端口径，见 §12.17）。

**X01-b 时间与倍速（观察类游戏的命门）**



* 基准：**游戏内 1 天 = 现实 20 分钟**（1x）；白天 06:00–20:00 占 14 分钟，夜晚 20:00–06:00 占 6 分钟。倍速只改时间流速，不改走速手感以外的任何判定。

* 三档 + 暂停：`1x`（20 分钟 / 天，沉浸）、`8x`（2.5 分钟 / 天，**默认**）、`24x`（50 秒 / 天，概览）；任意档位可暂停，并提供「单步 1 游戏分钟」用于看清一帧。

* 为什么默认 8x：「布景与事件回响」的延迟是 3–7 天，1x 要等 60–140 分钟，自己试玩都等不起；8x 下是 7.5–17.5 分钟，刚好「去做点别的再回来看」的节奏。24x 只用于快速验证世界能不能自转。

* 渲染分档（关键，否则角色会瞬移）：


  * `1x`：正常播放，30fps。

  * `8x`：位置按逻辑时间更新，**走路动画播放速度封顶 2x**，超过的部分用 1 格跳步表现（看起来像快进，不像瞬移）。

  * `24x`：**概览模式**——12fps，角色位置每秒更新 1 次且不插值，优先渲染事件气泡与关系变化，不做走路过程。

* 一致性：切倍速不改变已发生的事件、不重算关系、不重排事件队列；暂停时 OC 冻结在原地，不消耗游戏时间；退出后按真实流逝时间补算离线推演（沿用 R036；离线固定按 1x 结算，上限 7 个游戏日，不随在线倍速放大），补算结果按同一事件池规则生成。

* 数据：`clock{mode(pause/1x/8x/24x), game_minutes, day_index, last_tick}`；`step_request{minutes=1}`。

* 验收：三档切换无跳变、不重算历史；8x 下角色不出现跨屏瞬移；24x 下事件气泡仍可读；暂停 10 分钟后恢复，游戏时间未流逝；切回 1x 后动画速度正常。

### 12.2 预设地图与编辑（X02 地图预设与编辑权三档）



* 预设 3 张：**草地庭院 / 小镇街道 / 雪原**（各含出生点、可行走区、2–4 个可交互点、1 个「门」格）；预设只读模板，进入世界时复制一份。

* **编辑权分三档，由玩家自己选，不按等级锁**（同一份地图数据，能力逐级开放）：



| 档位 | 名字           | 能做什么                                                            | 优先级 |
| -- | ------------ | --------------------------------------------------------------- | --- |
| ①  | **看**（默认）    | 用预设、换出生点、换瓦片皮肤（不改结构）                                            | P0  |
| ②  | **摆**（默认）    | 单格 / 矩形 / 刷子拖拽替换瓦片；摆放与移动物件；改地图尺寸（钳制 8×6–64×48）；设出生点与门格          | P0  |
| ③  | **画**（高级，可开） | 自由涂地形（逐格涂任意瓦片）；刷子 1/3/5；区域填充；矩形选区复制粘贴；地面 / 覆盖 / 物件三层；导出并复用自制瓦片集 | P1  |



* 为什么分三档：**只养 OC 的人不该被编辑器吓到**，「看」和「摆」够他玩一辈子；而想手搓地图的人要的是「涂」，不是「一格一格点」。同一套 `tiles[][]` 数据支撑三档，画档只是把「摆」的刷子放大到任意瓦片 —— 不是另一套系统。

* **摆下即变（一帧确认）**：物件摆进世界的瞬间自己切到「已放置」那一帧 —— 伞撑开、水缸出现水面、椅子转向最近的人。**不做粒子与音效堆叠**，只做一帧状态差，玩家因此知道「它进世界了」，而不是摆完毫无反应。摆歪了 3 秒内可直接拖动改位，不弹确认框；除此之外不给任何奖励反馈（摆东西本身不是得分行为）。

* 摆下的物件进入 `placeable_in_use` 候选池，事件池与动机链可以立刻引用它 —— 这是「三分钟后下雨，她自己走到伞下」能成立的前提。同一物件 1 个游戏日内未被引用不算失败，只进统计。

* 仍然不做：地形自动过渡（autotile）、超过 3 层的地形、地表贴花叠加。缺角用「素色瓦片 + 手绘边界」解决。

* 数据：`map{id, universe_id, size, edit_mode(look/place/paint), tiles[3][][]（ground/overlay/object）, tile_attr{}, objects[], spawn, gates[], version}`；`tileset{id, name, tiles[], source(preset/diy)}`；画档每次提交生成 `map_patch` 供撤销（复用 X13.1 撤销栈）。

* 验收：三档切换不丢已画内容；画档刷子可撤销 50 步；改尺寸不丢已摆物件（越界物件进「待安置」列表）；自制瓦片集导出再导入一致；不装 autotile 也不出现拼接缝。

### 12.3 角色卡（X03 卡面、信息与放入世界）



* 新建：像素大手从屏幕顶部扔下一张**空白 ID 卡**，落定悬浮居中；动画 ≤1.0s，可点击 / 空格跳到终态；同一场景只允许一张卡。

* 卡面：360×520；**照片热区**（左）与**信息热区**（右）各为独立按钮，最小 44px；两热区键盘可达。

* 卡正面简版：姓名 / 性别 / 生日；点信息热区进**详情页**（性格、简介、标签、关系、今日状态、最近 3 件事）。

* 信息字段：姓名 1–12 字必填；性别＝男 / 女 / 未知 / 其他（四选一，默认未知）；生日＝月 / 日（年份可空）；简介 0–200；标签 0–6。

* 完成条件：有形象矩阵 + 有姓名。完成前卡面盖「草稿」角标，不可放入世界。

* 放入世界：完成卡后点「放入世界」，卡片以「贴到入口格」的 0.5s 动画落到目标世界；世界选择器只列当前可进入的世界。

* 性格区（v1.5，详情页「性格」页签）：两种填法 ——**选词**（24 词挑 3–5，默认）或**滑杆**（7 刻度 + 冲突方式三选一，高级）。选词即折算刻度，含「冷脸 / 慢热」类词时自动加一条条件修正（对关系 ≥3 的人社交度 +2），这样「外冷内热」才有落点。

* 24 个词：自来熟、话痨、爱热闹、怕生、寡言、独来独往、冷脸、慢热、黏人、疏离、易炸、没脾气、急性子、磨蹭、坐不住、宅、爱乱走、守着不动、强迫症、邋遢、认死理、随和、嘴硬、心软。

* 互斥组合（如「自来熟 + 怕生」）标红提示但**不阻止**：允许矛盾人格，行为会摇摆，这是创作空间不是 bug。

* 卡面**只显示玩家选的 3–5 个词，不显示任何刻度数值**；数值只在编辑器调试面板可见，正式世界不可见 —— 玩家要靠看行为归纳他的性格。

* 生日联动：生日当天由事件池自动产出一条生日事件（见 X07），不依赖模型。

* 数据：`oc_card{oc_id, cover{matrix_id, crop_rect, ratio}, name, gender, birthday, intro, tags[], status(draft/ready)}`。

* 验收：从触发到可点 ≤1.2s；姓名 / 性别 / 生日 30 秒内填完；未完成卡不能进世界；放入后世界入口格可见该 OC。

* 切换时机：世界里即时生效；角色卡打开中切换不打断已有动画，下一帧生效。
* 性能：换皮只重绘 1 张 9-slice + 改文本色，不重新加载照片矩阵；切换 ≤1 帧。
* 验收：六套主题下分别截图，卡片外框与两热区位置逐像素一致；切换主题后照片不闪烁、不重载；色弱模式下仍能区分主次文本。


### 12.4 衣柜与穿戴（X04 图层模型）

一句话：**所有穿戴物都是图层。默认形象自带一层衣服；换衣服就是换这一层；饰品是再开一层盖上去。本体永远只读，脱了就回来。**

**层栈（自下而上）**



| 层           | 内容             | 权限      | 说明                                        |
| ----------- | -------------- | ------- | ----------------------------------------- |
| `L0` 本体     | 皮肤 / 五官 / 头发   | **只读**  | 任何操作写不进去；换装后校验 `base_hash` 不变             |
| `L1` 默认衣服   | 创作者画的第一套衣服，可为空 | 替换      | 换衣服＝换这一层；旧衣服永久留在 `wardrobe`，随时换回          |
| `L2–L5` 饰品层 | 最多 4 层同时       | 新增 / 叠加 | 可写任意格子，**含 head /hair/eyes /mouth**       |
| `H` 手持物     | 独立小矩阵          | 不写角色矩阵  | 绑 `hand_l` / `hand_r` / `back`，2–4 帧 8fps |



* **创作侧已经对齐**：编辑器 v1.5c 里新建形象就是固定两层 ——`本体`（皮肤 / 五官 / 头发，不可删）与 `衣服`（可整层替换）。**部件按层开放**：本体层只能标 hair /head/eyes /mouth/upper /lower，衣服层只能标 top /pants/coat /shoes，饰品层只能标 acc；切层后不可用的按钮变灰，点了会提示它属于哪一层。因此从创作第一步就保证 `L0` 与 `L1` 分开，不留后期拆层的工作。

* **不再有「禁止碰脸」这条规则**。服装和饰品在渲染上是同一件事 —— 一层稀疏矩阵。区别只有两点：`L1` 只有一层、换它是「替换」；`L2+` 可以多层、是「叠加」。兜帽、面罩、高领、兽耳、眼罩全部走饰品层。

* 盖脸带来的唯一真问题：**表情动画被挡住**。每层声明 `face_anim_passthrough`：


  * 默认 `false`：盖住 eyes/mouth 时表情不透传，看起来「面瘫」—— 面罩本来就该看不见表情，这是设计而不是 bug。

  * 可设 `true` + `opacity 60%`：半透明，仍能看见眼睛变化（像素游戏常规做法）。

* 层序可调：衣柜面板上下拖动改 `z`，同 `z` 按 `priority`，冲突给三选一（替换 / 叠上去 / 取消），禁止静默覆盖。透明度 0–100% 可调。

* 特别饰品仍有归属：`owner_oc_id` 有值＝仅本人可穿（别人衣柜里灰色锁定），`unique` 标记进宇宙图鉴；这两项与图层模型不冲突。

* 换装动画＝0.2s 层闪烁 1 次；手持物切换 0.15s 抬起。

* 数据：`base_matrix`（只读）/ `wear_layer{id, name, cells[], parts[], z, face_anim_passthrough, opacity}` / `outfit{oc_id, layers[], active_held[]}` / `wardrobe{oc_id, entries[]}`；穿戴物可导出为图纸复用，也可作 `item` 进世界被别的 OC 拾取。

* 验收：换 10 次衣服能 100% 回到最初那件；每次换装后 `base_hash` 不变（本体从未被写）；饰品盖脸后摘下五官一像素不差；改 `z` 或透明度遮挡即时刷新；面罩盖脸时表情不透传且可配置；三件以上饰品同格冲突必出三选一。

### 12.5 世界结构（X05 归属唯一与跨世界链接）



* 世界＝原 `universe`（1:1 岛），本期改称「世界」；世界有 `map_id`、入口格、主题色板、出生点。

* **一个 OC 只能属于一个世界**（`oc.world_id` 唯一，硬约束）；改变归属必须走「迁移」（二次确认 + 关系 / 记忆随迁）。

* 世界间**链接**不是传送：A 世界的「门」格可指向 B 世界，点击跳转只切视图；角色不能常驻他界，串门临时 ≤1 游戏日，到期自动回原世界并写一条「串门记录」。

* 世界数量：已建不限，同时 active ≤3（沿用 R004/R052 的容量口径，本期不再设等级门控，见 X12）。

* 数据：`world{id, name, map_id, palette, spawn, gates[{x,y,target_world_id}], status}`；`world_link{from_world, to_world, gate, mode(readonly)}`。

* 验收：一个 OC 不会同时出现在两个世界；点门 1 步跳转；串门到期自动返回。

### 12.6 观察与自由互动（X06 互动面、X07 日常事件池）

**X06 互动面**



* 点 OC 开底部像素面板：打招呼 / 聊天（短句）/ 送礼 / 看状态；每次互动有可见反馈并写记忆；同一 OC 每日 ≤20 次、间隔 10 秒。

* OC 之间自由互动：两个 OC 靠近（≤2 瓦片）且关系档位允许时，自动触发打招呼 / 并肩坐 / 递东西，播 2–3 秒，不打断玩家操作。

* 看状态面板：心情、今天做了什么（`behavior_trace` 摘要 3 条）、与在场 OC 的关系档位。

**X06-a 动机链（点开就得看懂它为什么在这儿）**



* 交互：点任意 OC，200ms 内出 1 句话（≤20 字 / 行、最多 2 行），说明它此刻在做什么、为什么。这是「观察」与「屏保」的唯一分界线，优先级高于任何新增玩法。

* 做法：**手写模板 50–60 条，不接模型**。五个动作类 × 每类 10–12 个变体（数量依据见 §12.12 的内容量账），槽位只用 OC 卡与当前状态里已有的信息，因此不可能说出 OOC 的话。



| 类       | 语义        | 样例（槽位由状态填充）                       |
| ------- | --------- | --------------------------------- |
| 等 wait  | 在等人 / 等时间 | 「他在门口站了十分钟，等 XX 回来。」「她在等雨停。」      |
| 找 seek  | 在找东西 / 找人 | 「她在找那把伞，昨天落在河边了。」「他在找 XX，但走错了方向。」 |
| 躲 hide  | 在避开什么     | 「他躲到树后面，因为 XX 在那儿。」「她不想被看见，蹲在屋后。」 |
| 看 watch | 在看什么      | 「他盯着那扇门看，没打算进去。」「她在看水面上那圈涟漪。」     |
| 守 guard | 在守着什么     | 「他守着那堆东西，谁靠近都不让。」「她守在床边，没走。」      |



* 槽位：`对象`（某个 OC / 某个物件 / 某个地点，只从本宇宙已存在的实体取）、`原因`（关系档位 / 未满足需求 / 最近记忆 / 天气）；同一状态 3 分钟内不重复同一句，避免刷屏。

* **前置条件（不满足就不进候选池）**：每条模板自带 `precondition`——「等雨停」只在天气＝雨时出现；「在找那把伞」只在该 OC 记忆里确有「把伞落在某处」时出现；「躲到树后面，因为 XX 在那儿」要求 XX 确实在同一地图且距离 ≤6 瓦片；「守着那堆东西」要求该物件存在且距她 ≤3 瓦片。检查放在**候选生成之前**，不是事后过滤；回退句保持中立，不暗示天气与人物。§1.7 走读里「她在等雨停，天明明是晴的」就是这条缺失造成的错，必须由前置条件拦住。

* 回退：无匹配模板时输出固定句「他站着，没在想什么。」——**永远不留空**，也不允许拼接自由文本补位。

* 数据：`motivation_template{id, cls(wait/seek/hide/watch/guard), slots[], precondition{}, text}`（50–60 条常驻配置，每类 10–12）；`motivation{oc_id, template_id, slots{}, ts}`；推导只读 `oc_state` + `perception`，不回写。

* 验收：点任意 OC ≤200ms 出句；无匹配走回退句；句中不出现 OC 卡与当前状态之外的信息；**连续观察 200 次，0 次出现与画面矛盾的句子**（如晴天说等雨停）；同状态 3 分钟内不重复；断网可用。

**X06-b 拎起与拖动（物理干预，不是指令）**



* 交互：按住 OC 直接拖走。被按住时进入 `grabbed` 状态 —— 像素小人被提起来（脚离地 2px、手臂下垂、双腿轻晃），地面留影子，落点显示虚线格。这是玩家唯一「直接碰身体」的动作，对应「人有时候会摆弄蚂蚁」。

* 松手：落到落点脚下 1×1 碰撞格；落点不可走则自动回退到最近可走格（不拒绝玩家，只做微调）；落地先愣 0.8 秒（头顶冒一个小抖动的像素符号），再恢复自主行动。

* 三条反应规则（趣味全在这里）：

1. **被放到陌生地方**：迷茫 3–5 秒（问号气泡），随后自己找路回常去的点；若寻路不通，会站在原地发愁 —— 玩家看得见它卡住了，可以再去帮它一把。

2. **被放到喜欢的人旁边**：按关系档位给概率，触发一次意外相遇事件。这条让「捣乱」变成「制造机会」—— 玩家可以拿它当实验工具，把两个人拖到一起，看会不会发生什么。

3. **反复被拖**（单日 ≥5 次）：烦躁值上升，关系中的「信任」下降；好感低时抓 3 秒就自己挣脱跑开；连续 3 天被反复拖，次日会躲着光标走（实现方式是「避开屏幕中心 2 瓦片范围」，不做 AI 识别）。

* 边界：不可拖入不可走瓦片（属性表否决）；不可拖出地图（钳制到边缘格）；被拖期间不接收其他 OC 的互动；**拖拽本身不改任何关系数值**，一切关系变化仍走 `relation_event`（沿用 R048）。

* 防滥用：拖拽不产生收益、不加速、不刷好感；两个 OC 被强行拖到一起也不保证发生好事，概率由关系档位决定；拖动不进图鉴、不计入成就类统计（本期也没有成就）。

* 数据：`drag_action{oc_id, from, to, held_ms, reacted}`；`oc_state.grabbed`；`irritation`（烦躁值，日清）；落点校验复用 `tile_attr`。

* 验收：拖到禁区自动回退且不报错；同一 OC 拖 5 次触发烦躁并降信任；拖到一起可触发意外相遇但概率受关系档位限制；拖动全程不写关系数值；拖拽中杀进程重开，OC 回到最近合法格而不卡在空中。

**X07 日常事件池（0 模型调用，本期最重要的内容发动机）**



* 供给源四类：天气与时段 × 物件状态 × 关系档位 × 角色偏好 / 生日。

* 每日产出 2–4 件小事，写同一个 `event` 结构，同时喂给 `perception.weather` 与 `perception.recent_events[]`。

* 事件只用模板 + 规则拼装，不调用模型；特殊日（生日、关系加深、季节首日）走专门模板。

* 约束：事件必须过 OOC 四层过滤（沿用 R027/R082）；不得伤害 OC；不得凭空改变关系（关系变化必须有 `relation_event`）。

* 数据：`event{id, world_id, type(weather/item/relation/season/birthday), actors[], place, result, template_id, ts}`；`event_pool{world_id, recent[], cooldown{}}`。

* 验收：连续 7 天每天有 2–4 件事件且无重复模板；断网仍有事件；事件全程产生 0 次模型调用。

### 12.7 UI 像素规范（X08 全站像素风）



* 边框：9-slice，边 8px，拉伸只拉伸中段；面板＝1 底色 + 1 深描边，无渐变、无投影、无模糊。

* 字体：像素字体（Fusion Pixel 12px 等，SIL OFL，授权待核实 §Q24）；字号只用 12 / 16 / 24；禁用系统字体混排。

* 图标：16×16 / 32×32 手绘，整数倍缩放，`nearest`；不使用矢量图标。

* 圆角：一律用像素阶梯圆角（4px 阶梯 2 级），不做 CSS 圆角。

* 交互反馈：按下位移 1px + 描边反色；hover 只做桌面增强，不承担信息。

* 验收：全站 0 处抗锯齿糊边；852×393 与 1280×720 都不出现半像素错位；触控热区 ≥44pt、无仅靠 hover 的信息。

### 12.11 回访钩子（X14：为什么第二天还会打开）

观察类游戏的自然死法是「看两天就腻」。这不靠加内容解决，靠**离开时留下一个没关的门**。三类钩子，全部模板化，0 次模型调用。



| 类型              | 定义          | 怎么生成                                                                     | 怎么消费                                              |
| --------------- | ----------- | ------------------------------------------------------------------------ | ------------------------------------------------- |
| **悬念**（suspend） | 一件开了头、没收尾的事 | 事件池里标记为 `open` 的事件；预期 1–3 游戏日内出现对应 `close` 事件，概率 70–85%（按关系档位与物件状态浮动）    | 收到 `close` 即关闭；3 个游戏日未收尾转 `expired`，写进纪念册并标「后来没了」 |
| **待办**（todo）    | 只有玩家能补的一个缺口 | 某 OC 在半径 2 瓦片内反复往返或静止 ≥1 个游戏日，且该区域缺少某个 `function_tag`（坐处 / 避雨 / 照明 / 储水） | 玩家摆上对应物件即解除，并立刻生成一条悬念事件作为回报                       |
| **累积**（collect） | 册子还差几条      | 纪念册按册计，每册 12 条；图鉴按首次触发记                                                  | 满册不解锁奖励，只生成一页回顾（12 条按时间轴排 + 一句模板总述）               |

**三条硬规则**



* **悬念不依赖玩家**：收尾由世界自身推进，玩家全程不干预也能看到结局。否则不干预的玩家永远等不到收尾，钩子会变成惩罚。

* **待办不明说**：一级提示只有行为（她在门口站了很久）；二级提示藏在点 OC 的动机句里（「她想坐下，但这里没有能坐的地方」）；三级提示只在连续 2 天无响应后，由离线报告给一句旁白。**任何时候不弹红点、不给计数、不说「你有 3 件事待处理」。**

* **不惩罚离开**：不枯萎、不掉好感、不做连续登录奖励、不做每日任务。离开 7 天回来，世界只是「过了 7 天」，不是「你欠了 7 天」。

**离线报告排序**（接 R036）：悬念 > 待办 > 累积，最多 3 行（沿用 R036 的 1–3 件事），超出折叠；同一钩子只报一次（`reported` 标记）；未关闭的钩子第二天继续报，但换一条模板，不重复同一句。

**数量上限**：同时存在的悬念 ≤3 条（超出按最老的转 `expired`）；待办 ≤2 条；累积无上限。理由：钩子太多等于没有钩子。



* **物件功能标签**：每个可摆物件带 `function_tag`（sit /shelter/light /water/storage），摆档时按物件类型自动填。待办钩子靠它判断「这里缺什么」，事件池也靠它决定「下雨时谁会去哪儿」。

* 数据：`hook{type(suspend/todo/collect), id, opened_day, deadline_day, payload, status(open/closed/expired), reported}`；`todo_hook{region, missing_tag, level(1/2/3), responded}`；`journal_volume{index, entries[], filled, summary}`；`object{... , function_tag}`。

* 验收：连续 7 天每天打开一次 —— 每次离线报告至少 1 条未了事件，悬念同时不超过 3 条，且至少出现 1 次「昨天看到的那件事今天收尾了」；连续 14 天完全不干预 —— 世界仍产生新事件与收尾，无红点、无催促、无惩罚性数值；待办 —— 摆上正确物件后 ≤1 个游戏日解除并生成一条新悬念，摆错物件不解除也不报错；累积 —— 第 12 条写入当帧生成回顾页，回顾页可回看、不重复生成。

* **反模式（写下来防以后自己加）**：不做每日签到、不做限时活动、不做「回来看看，你的 OC 想你了」这类拟人催回、不做离开越久收益越高的离线挂机奖励。

### 12.12 内容量账与首版验收（X15：到底要写多少条模板）

**算账基准**（全部取 §12.1 与 X01-b 的定值，不另设参数）



* 1 游戏日 = 20 分钟（1x）；8x = 2.5 分钟。

* 每日事件 2–4 件（取中位 3）。

* 一次会话按 5 现实分钟算 = 2 游戏日 = **6 件事件**；每天打开 1 次。

**事件模板要多少条**



| 周期        | 游戏日 | 事件消耗 |
| --------- | --- | ---- |
| 一次会话      | 2   | 6    |
| 一周（7 次会话） | 14  | 42   |
| 两周        | 28  | 84   |

判断标准不是「两周不重样」—— 那条会把第一版逼到写 84 条，是错的。真正的标准是：**玩家记住的是「发生了什么」，不是「用了哪条模板」**。同一条模板换个对象、换个地点、换个时段，感知上就是新事件。于是定两条可执行下限：



* **窗口内不重复**：同一 OC + 同一模板，3 个游戏日内不重复出现。

* **复用上限**：同一模板两周内复用 ≤4 次（84 件 ÷ 20 条 ≈ 4.2，刚好压线）。

→ **事件模板 20 条（五类 × 4 条）**，第一版够用。

**动机模板要多少条（这里需要往上加）**



* 一次会话玩家会点 3–5 次 OC（取 4）；每天 1 次会话 = 4 次点击；一周 28 次。

* 但模板按**状态**分池，不是全库随机：晴天的「等雨停」不出现，可用池会缩到 4 类。

* 极端情况 —— 一整天下雨、玩家反复点同一个 OC：6 条单类模板在 1.5 个游戏日内就被拿完两轮，第 3 天必然撞重复。

→ **单类 6 条太少，扩到每类 10–12 条，合计 50–60 条。** 这是整本账唯一需要加量的地方。

**产能**



| 内容                     | 条数 | 单条工时  | 合计                   |
| ---------------------- | -- | ----- | -------------------- |
| 动机模板（带 `precondition`） | 50 | 8 分钟  | 6.7 小时               |
| 事件模板（带参数槽与触发条件）        | 20 | 15 分钟 | 5 小时                 |
| **合计**                 | —  | —     | **约 12 小时 ≈ 1.5 人日** |

内容不是瓶颈，写代码才是。所以「先堆内容」是常见的错误优先级。

**首版验收（一句话，可证伪）**

> **自己连续 5 天、每天打开 5 分钟，每次都能看到至少一件没见过的事件，且没有一次觉得「又是这套」。**

为什么是 5 天不是 7 天：按上面的账，20 条事件在 5 天（10 游戏日、30 件）里基本不会重样；到第 7 天开始出现可见复用。**诚实的验收线比夸大的好**—— 达不到就补模板，不要改标准。

**一条反推纪律**：如果某天发现「为了撑到 7 天必须把事件加到 40 条以上」，说明事件密度过高（每天 3 件太多），应该把每日事件从 2–4 降到 1–3，而不是堆内容。观察类游戏的密度上限由「玩家一次能注意到几件事」决定，不由模板库存决定。

### 12.13 一帧数据流（X16：系统怎么接线、顺序为什么不能乱）

一帧里数据只走**一条主线、三条旁路**。单向、不回流、0 次模型调用。

**主线（每帧执行，顺序固定）**



| 步 | 系统                        | 读什么                      | 写什么                                          | 频率                     |
| - | ------------------------- | ------------------------ | -------------------------------------------- | ---------------------- |
| 1 | 时钟 `clock`                | `last_tick`              | `game_minutes`、`day_index`、时段（晨 / 日 / 昏 / 夜） | 每 tick                 |
| 2 | 感知 `perception`           | 地图、OC 位置、物件、天气、时段        | `perception`（每 OC 一份快照）                      | 每 tick，可降频至 10Hz       |
| 3 | 事件池 `event_pool`          | `perception`、`hook`、每日配额 | `world_event`、`relation_event`               | 事件触发时写；每日 2–4 件        |
| 4 | 行为决策 `decide`             | 性格权重 × 需求紧迫 × 关系系数 × 可达性 | `oc_state.intent`                            | 决策点（到达目标或被打断时）         |
| 5 | 寻路与移动 `path`+`move`       | `intent`、`tile_attr`     | `position`、`path_queue`                      | 每 tick（**倍速只改这一步的步长**） |
| 6 | 交互与记忆 `interact`+`memory` | 距离、关系档位、`oc_state`       | `interaction`、`memory`（最近 N 条）               | 满足距离阈值时                |
| 7 | 渲染 `render`               | 全部只读                     | 帧缓冲                                          | 每帧                     |

**三条旁路**



* **动机句（A）**：只在玩家点击 OC 时触发，读 `oc_state + perception`，过 `precondition`，出 1 句，**不回写任何状态**。所以它永远不可能影响世界 —— 这是它敢随便说话的前提。

* **关系变化（B）**：只能由 `relation_event` 触发，事件池是唯一入口。拖动、摆物、互动都不能直接改关系值。

* **纪念册与钩子（C）**：事件写入后同步记一条与更新钩子状态；只读事件，不回写世界。

**四条不变量（写代码时拿来守）**



1. `perception` 是**只读快照**，任何系统不得回写。

2. 关系数值**只有一个写入入口**（`relation_event`）。

3. 倍速**只改第 5 步的步长**，不改事件频率、不改判定、不改关系。

4. 全链路 **0 次模型调用**；断网时链路完整可跑。

**顺序为什么不能乱**



* 感知必须在事件之前：事件要靠「谁在哪、天气怎样」才成立。

* 事件必须在决策之前：否则角色会对刚发生的事毫无反应。

* 决策必须在移动之前：移动只是把 `intent` 兑现。

* 记忆必须在交互之后：记的是「已经发生的事」，不是「打算做的事」。

* 数据：帧级只传 `frame{tick, dt, mode}`；各系统的读写面严格按上表，跨系统只读不写。

* 验收：把第 3 步替换为「事件池返回空」，其余不动 —— 世界应继续运转（角色照常走路、动机句照常出、渲染正常），只是不发生新事件。这条用来证明「事件池不是主循环的必需品」，也是断网兜底的依据。

### 12.14 设置与无障碍（X17：不影响玩法，但影响能不能玩下去）

设置只做真正改变体验的项，不做「调色板数量」这类伪选项。



| 分组  | 项                  | 取值                 | 默认                | 为什么是这一项                                         |
| --- | ------------------ | ------------------ | ----------------- | ----------------------------------------------- |
| 时间  | 默认倍速               | 1x / 8x / 24x，记住上次 | 8x                | 8x 是「去做点别的再回来」的节奏（X01-b）                        |
| 显示  | 缩放                 | 2x / 3x / 4x / 自适应 | 自适应               | 像素图必须整数倍，不提供非整数选项                               |
| 显示  | 网格显示               | 开 / 关              | 编辑器内开，世界内关        | 世界里出现网格会毁掉「看世界」的感觉                              |
| 显示  | 减少动态               | 开 / 关              | 关                 | 关掉抖动、闪烁、卡片掉落动画（卡面直接跳终态）                         |
| 显示  | 上帝之手               | 开 / 关              | 开                 | 关掉后新建 / 放入 / 拎起不出手、直跳终态；开启「减少动态」时自动关闭（见 §12.20） |
| 无障碍 | 色弱模式               | 无 / 红绿 / 蓝黄 / 全色盲  | 无                 | 见下                                              |

| 音频  | 主音量 / 环境 / 事件 / UI | 0–100 四滑杆          | 40 / 40 / 60 / 50 | 分开控，因为有人只要环境不要事件音                               |
| 存档  | 导出 / 导入 / 手动备份     | —                  | —                 | 本地优先，云同步本期不做（Q13）                               |

**色弱模式的实现（不能只改颜色）**



* 38 色 MARD 色板对红绿型色弱不友好（F2/F3/A4、G7/G9 都很接近）。三条补偿同时生效：

1. **格内色号文本**（开关打开后每格角显色号）。

2. **部件标注改用图案**，不只靠荧光色 ——hair 斜线、head 点阵、eyes 十字、mouth 波浪、top 竖线、pants 横线、coat 斜网格、shoes 交叉、acc 星点。色弱玩家靠图案也能认出部件归属。

3. **状态不只用颜色表达**：关系档位加档位点（1–5 个圆点），钩子状态加图形符号，不用纯色区分。

* 铁律：**任何信息不得仅靠颜色传达**（这条在 UI 评审时逐项过）。

* 数据：`settings{default_speed, zoom, grid_in_world, reduce_motion, hand_ui, colorblind_mode(none/rg/by/full), show_color_code, high_contrast, volume{master,ambient,event,ui}}`。

* 验收：切色弱模式后，睁眼能靠色号文本与图案独立完成「标 hair / 标 top」两次操作，不依赖颜色；关掉减少动态后，卡面掉落动画立即跳终态且不影响后续点击；设置项全部即时生效、无需重启。

### 12.15 音频（X18：观察类游戏要做「环境」，不做「配乐」）

**不做 BGM。** 观察类游戏一放配乐就会盖住事件音，而事件音正是「有事发生了」的唯一非视觉提示。默认只有环境层与事件层。



| 层            | 音源数 | 内容                                 | 触发             | 规则                             |
| ------------ | --- | ---------------------------------- | -------------- | ------------------------------ |
| 环境 `ambient` | 4   | 雨、风、夜虫、脚步                          | 天气 / 时段 / 有人行走 | 循环播放，**最多 3 个叠加**，切换 0.5s 淡入淡出 |
| 事件 `event`   | 8   | 物件摆下、伞撑开、门响、关系升温、开始下雨、雨停、钩子收尾、点 OC | 对应事件           | **同一时刻最多 1 个**，后来的排队 0.3s，超时丢弃 |
| UI `ui`      | 3   | 点击、翻卡、开关                           | 交互             | 不与环境层抢音量                       |



* 技术口径：8-bit 风格，22050Hz 采样，单声道，单文件 ≤32KB；总音源 ≤24 个（当前 15 个）；音频初始化失败时**静默降级**，不报错、不阻塞游戏。

* 为什么事件音要「同一时刻只一个」：观察类游戏事件密度低但偶发并发（下雨 + 关系升温），叠三个音会像故障。宁可丢，不可糊。

* 数据：`sound{id, layer(ambient/event/ui), file, loop, gain}`；`audio_state{ambient_stack[], event_queue[], last_play}`。

* 验收：断网、无声卡两种环境下游戏功能完整、无报错；同时触发两个事件只播一个且不重复排队；环境层叠加不超过 3 个；关闭主音量后所有音源停止且 CPU 占用无回升。

### 12.16 存档与版本迁移（X19：每加一个系统，老存档都要能读）

**写入策略**



* 原子写：先写 `save.tmp`，成功后 `rename` 覆盖 `save.json`，同时保留上一份为 `save.bak`（只留 1 份）。

* 读档顺序：`save.json` → 失败读 `save.bak` → 都失败进**只读回看模式**（纪念册、图鉴、地图可看，世界不可动、不可存），明确提示「这一份读不出来了，可以导出后手动修」。

**版本**



* 字段 `save_version`（如 `1.3`），语义为「主版本 = 结构变更，次版本 = 字段新增」。

* **迁移逐级进行**，不允许跳级：`v1→v2→v3`，每级一个 `migrate_<n>_to_<n+1>(data)` 纯函数，输入输出都是完整存档对象。

* 次版本升级（新增字段）走「缺字段填默认值」，不写迁移函数。

* **不可变字段**：`universe_id`、`oc_id`、`map_id`。迁移中这三类 id 一律不得重新生成，否则关系与纪念册会全部失联。

**存档内容（单 JSON，≤2MB）**

`{save_version, universe{id,name,world_book}, maps[], ocs[](含卡、矩阵、衣柜层栈、性格、关系、memory、irritation), journal[], hooks[], settings, clock{game_minutes,day_index}, rng_seed}`



* `rng_seed` 必须落盘：否则同一个世界重新打开后事件序列会变，玩家会发现「昨天那件事今天没发生」。

* 数据：见上；备份文件 `save.bak`；导出与导入使用同一 schema，导入时按 `save_version` 走同一套迁移。

* 验收：用 v1 存档连升到 v3，每个 OC 的衣柜层栈、关系数值、纪念册条数完全一致；写入中途杀进程，重开后读到的是上一次完整存档（不是半截）；手改坏 JSON 后能识别并进只读回看模式不崩溃；同一个 seed 连续打开两次，前 3 个事件序列一致。

### 12.17 平台与输入（X20：移动端优先，触控是第一公民）

**本期拍板**



| 项          | 取值                          | 后果                                   |
| ---------- | --------------------------- | ------------------------------------ |
| 目标平台       | **移动端（iOS / Android），横屏为主** | 触控成为第一输入；hover 不再承载信息；UI 按 44pt 热区重排 |
| PC / Steam | 后置，不排除                      | 输入层与缩放从一开始抽象，避免二次改造；不做双端同步开发         |
| 联机         | 以后做，本期纯本地                   | 存档结构与事件 id 预留幂等；不写网络层                |
| 变现         | 本期零内购入口                     | 不做付费墙、体力、抽卡；未来可能 Steam 买断            |

**为什么不矛盾**：观察式玩法与手机天然贴合（躺着看、随时打开），而编辑器的精度更适合鼠标。所以策略是**手机是主战场，PC 是后置的第二个渠道**，不是两套并行。这也意味着编辑器必须先在手机上能用 —— 见下文最难的一段。

**屏幕与缩放**



* 逻辑分辨率不变：20×15 瓦片 = **320×240 设备像素**。

* 缩放只允许整数倍（1x/2x/3x），取可用区域高度 ÷ 240 的整数部分；**取不到就不放大，直接 1x 居中，绝不插值**。

* 手机横屏 852×393 下：地图 1x 居中，占宽约 37%、占高约 61%，两侧与上下留给 UI。

* 2x / 3x 进入**查看模式**：地图可拖动、可跟随某个 OC 自动居中；双击或点「回到全景」退回 1x。

* OC 立绘高约 29 逻辑像素（≈屏幕 29pt），**点选用 44pt 容错半径 + 最近优先**，不要求点准那 29px。

**手势表（触控是一等公民）**



| 手势           | 行为          | 备注             |
| ------------ | ----------- | -------------- |
| 单指点 OC       | 出动机句（X06-a） | 44pt 容错        |
| 单指按住 OC 0.3s | 拎起（X06-b）   | 与「点」靠时长区分，不弹菜单 |
| 单指拖 OC       | 拖动，落点虚线格    | 拖出地图边界回弹       |
| 单指拖地图        | 平移（仅查看模式下）  | 1x 全景不平移       |
| 双指捏合         | 缩放 1x/2x/3x | 松手吸附到最近整数倍     |
| 双指按住         | 出放大镜（编辑器专用） | 见下             |
| 双击地图         | 进入 / 退出查看模式 | —              |
| 三指点按         | 撤销（编辑器）     | 可选；优先右下角按钮     |

**编辑器在手机上的方案（全游戏最难的一处）**

29 格 × 44pt = 1276pt，远超手机屏宽 852pt。**手机上不可能一屏画完 29×29**，必须做三件事：



1. **默认「整图见」**：每格 20–26pt，能看全整体形状，但点不准。用于判断比例。

2. **双指放大镜**（移动端像素画的成熟做法）：双指按住，手指处浮出 7×7 的 8 倍放大窗；单指在窗内移动即落笔，窗随手走；松手窗消失。既不反复缩放，又能画准。

3. **右下角缩放环**：单指按住不动 0.6s 出环形刻度，拖动即缩放，避免与双指手势冲突。

**配套硬要求（在移动端从「方便」升为 P0）**



* **参考图垫层（X13.5）**：手机上没临摹对象就画不出人形。

* **骨架提示（X13.6）**：29×29 的头 / 眼 / 嘴 / 躯干分区参考线。

* **一键描边（X13.7）**：手指画不准外轮廓。

* **自动猜部件（X13.8）**：手指逐格标 11 类部件不可行，必须自动预标再手改。

→ 这四项在 **§12.9 落地顺序里必须前置**，否则第一版到不了「画出第一个 OC」这一步。

**横竖屏**



* 游戏主界面**只支持横屏**；竖屏时显示「请横屏使用」。

* 例外只有编辑器：竖屏时改为「上半画布 + 下半工具栏」的纵向排布（竖屏更利于单手绘画），仍可用。

**角色卡尺寸（原 360×520 放不进手机横屏）**



* 横屏用**横版卡 480×300**：照片区 260×260 在左，信息区在右。

* 竖屏用**竖版卡 360×520**：照片在上、信息在下。

* 两版热区各 ≥44pt；切换屏幕方向时卡不重排数据，只换布局。

* **卡面皮肤只换配色与边框纹，不换尺寸**：横版仍是 420×262、竖版仍是 360×520，换皮前后热区位置逐像素不变（见 §12.3）。

**存档位置**



* iOS / Android 应用沙盒目录，**不写公共相册、不写外部存储**。

* 导出走系统分享面板（单 JSON ≤2MB）；导入走系统文件选择器；原子写与 `save.bak` 沿用 §12.16。

**联机预留（本期不做，但结构先对）**



* 所有实体用稳定 id（`universe_id / oc_id / map_id / event_id`），全局唯一，**不用自增序号**。

* 事件带 `event_id` + `ts`，可幂等重放；同 id 重复到达只结算一次。

* 存档为纯 JSON、不含本地路径与绝对坐标，可直接搬到服务端。

**性能档（移动端）**



* 中档手机（骁龙 7 系 / A14 级）：同屏 4 个 OC ≥30fps；8 个 OC 降到 24fps 概览（沿用 X01-b 分档）。

* 内存峰值 ≤180MB；冷启动 ≤3s；地图离屏预渲染一张；每帧角色合成 ≤8 个。

* 后台切回按真实流逝时间补算离线（§12.1 一致性，上限 7 个游戏日）。

**桌宠（M7）在移动端的处置**



* iOS 无桌面宠物系统能力，Android 悬浮窗要做权限与能耗豁免。两者都不适合本期。

* **本期移动端不实现桌宠**；M7 保留为 PC 后置能力，与 Steam 一起评估。

* 验收：iPhone 13/14/15 与一台 1080p Android 上 —— 地图 1x 完整可见、无裁切；2x 查看模式拖动流畅；单指点 OC 命中率 ≥95%（连续 20 次）；编辑器双指放大镜可用、8 倍窗内落笔准确，画错率不高于桌面版 5 个百分点；横竖屏切换布局不崩、数据不丢；冷启动 ≤3s；切后台 10 分钟回来补算正确。

### 12.18 物件与动效帧预算（X21：让东西动起来要几张图）

**四档分类（每个物件先归到一档，再决定画几张）**



| 档    | 典型物件                                     | 帧数  | 判断依据                               |
| ---- | ---------------------------------------- | --- | ---------------------------------- |
| 静止   | 树、石头、墙、桌椅、床、栅栏                           | 1   | 它本来就不该动；硬加摆动像故障                    |
| 状态   | 伞（收 / 撑）、水缸（空 / 半 / 满）、门（关 / 开）、灯（灭 / 亮） | 2–3 | 这不是动画帧，是**状态图**；切换时直接换图，不做过渡       |
| 循环   | 火堆、水面、旗帜、蜡烛                              | 3   | 3 帧 @ 8fps ≈ 0.375 秒一轮，眼睛会自动补成「在动」 |
| 交互瞬间 | 摆下、被碰、被使用、被拖动                            | 0   | 全部用程序化位移与明暗，**不画新图**               |

**五个通用配方（写死一套，套所有物件，0 张新图）**



| 配方  | 触发         | 实现                | 时长    |
| --- | ---------- | ----------------- | ----- |
| 落下  | 物件摆下       | y 从 −4 → 0，2 帧    | 120ms |
| 晃一下 | 被碰到、被踩过    | x −1 → +1 → 0，3 帧 | 150ms |
| 亮一下 | 被使用、被选中    | 整体提亮 12%，2 帧      | 100ms |
| 浮一下 | 可交互提示      | y 0 → −1 → 0，循环   | 1s    |
| 抖两下 | 拒绝、装不下、拖动中 | x ±1 交替，4 帧       | 200ms |

**帧数上限（超了就是浪费）**



* 静止 ≤1、状态 ≤3、循环 ≤3、交互瞬间 0。**不存在 4 帧以上的常规物件。**

* 像素动画靠「跳」不靠「顺」：做 8 帧火焰更贵，而且失去像素味。

**必须画新图的唯一判定**：状态变了且**外形轮廓真的不同**。伞收 / 撑、水缸空 / 满、门关 / 开、灯灭 / 亮 —— 四种。其余一律用配方。

**不用画的情形（常见误判）**



* 椅子有人坐 → 角色叠加在椅子上，不画「坐着的椅子」。

* 两人共伞 → 伞 + 两角色叠，伞不加新帧。

* 火堆变大变小 → 3 帧循环 + 偶尔换色，不画尺寸帧。

**配置集中（不许散落代码）**



```
{

&#x20; "tree":      { "type": "static", "frames": 1 },

&#x20; "campfire":  { "type": "loop",   "frames": 3, "fps": 8 },

&#x20; "water\_tank":{ "type": "state",  "frames": 3, "states": \["empty","half","full"] },

&#x20; "umbrella":  { "type": "state",  "frames": 2, "states": \["closed","open"] },

&#x20; "door":      { "type": "state",  "frames": 2, "states": \["closed","open"] },

&#x20; "lamp":      { "type": "state",  "frames": 2, "states": \["off","on"] }

}
```

所有时间驱动的循环节奏（循环帧率、状态切换间隔）**只允许出现在&#x20;**`anim_profile.json`，不允许散在渲染代码里。

**账**：20 个物件 = 静止 12 × 1 + 状态型 5 × 3 + 循环型 3 × 3 = **39 张**，每张 10 分钟 ≈ **6.5 小时**。



* 验收：随机抽 3 个物件 —— 静止型在任何操作下都不出现位置抖动；状态型切换时无中间过渡帧、无半帧糊边；循环型连续观察 30 秒无跳帧与闪烁；交互五配方在每个物件上都能触发且不覆盖物件本体像素。

### 12.19 角色部件变换表（X22：10 个动作 × 11 个部件）

**基础姿态**：所有帧以「站立」为基准位移 (0, 0)。单位是**设备像素**（1 豆 = 1 设备像素）。



| 动作 | 帧数 | 节奏        | 有变化的部件与位移（dx, dy）                                                                            |
| -- | -- | --------- | -------------------------------------------------------------------------------------------- |
| 站立 | 1  | —         | 无。呼吸变体：upper/top/head/hair/eyes/mouth/acc 统一 dy −1，2 帧 1.2s 交替                               |
| 走路 | 4  | 8fps      | 帧 1：lower dy −1、pants dy −1、shoes dx −1；帧 3：同帧 1 但 shoes dx +1；帧 2/4 全回 0；整体 dy −1 只出现在帧 1/3 |
| 跑步 | 4  | 12fps     | 同走路，dx ±2、整体 dy −2、周期减半                                                                      |
| 坐下 | 2  | 一次性 120ms | 整体 dy +2；lower/pants **纵向压缩 2px**（底边贴地）；shoes dy +2 并画到椅子前面                                  |
| 蹲下 | 2  | 一次性 120ms | 整体 dy +3；head/hair/eyes/mouth/acc dy +1；lower/pants 压缩 3px                                   |
| 抬手 | 2  | 6fps      | upper dy −1、top dy −1、acc 跟随 upper                                                           |
| 递物 | 2  | 一次性       | 抬手 + 手持物矩阵贴到 upper 前端（**不写进角色矩阵**）                                                           |
| 拥抱 | 2  | 一次性       | 两人间距压到 ≤1 瓦片；双方 upper dy −2；相对侧镜像；头顶 ♥                                                       |
| 争执 | 3  | 8fps      | 整体 dx −1 / 0 / +1 交替；upper dy −1；头顶怒符                                                        |
| 转身 | 1  | 瞬间        | 整体水平镜像（scaleX −1），锚点与脚下碰撞盒不变                                                                 |
| 离场 | —  | 走 + 淡出    | 走向最近地图边缘，最后 0.3s 透明度 1 → 0                                                                   |

**位移约束（三条铁律）**



1. **单次位移 ≤3 设备像素**。29×29 的小人，移 4px 就断手断脚。

2. **只压不拉**：允许纵向压缩（坐下、蹲下），**禁止横向拉伸**（像素会被拉糊）。

3. **镜像后眼睛高光会左右反**—— 接受，这是像素小人的惯例，不要为此重画。

**部件缺失时的兜底（UGC 必然遇到）**



| 缺失部件       | 兜底行为                    |
| ---------- | ----------------------- |
| `lower` 为空 | 走路只做整体 dy，不抖腿（避免腿部阴影乱飞） |
| `eyes` 为空  | 不做眨眼，其余动作照常             |
| `upper` 为空 | 抬手、拥抱退化为只有整体位移          |
| `acc` 为空   | 所有跟随 acc 的位移跳过          |

**头顶符号集（不画表情也能表达情绪）**

8 个，统一 8×8，单色 + 1px 描边，出现在头顶上方 2px：



| 符号  | 含义       | 典型触发             |
| --- | -------- | ---------------- |
| 汗滴  | 紧张、被拖、窘迫 | 单日被拖 ≥5 次（X06-b） |
| 问号  | 困惑、找不到   | 寻路失败、物件被拿走       |
| 爱心  | 亲密       | 拥抱、关系档位上升        |
| 怒符  | 冲突       | 争执、被挡路           |
| 省略号 | 发呆、沉默    | 回退句触发（X06-a）     |
| 音符  | 开心       | 看风景、听雨、收到礼物      |
| 闪电  | 惊吓       | 突然下雨、被拎起         |
| Z   | 睡着       | 夜间静止 ≥3 分钟       |



* 规则：**同一 OC 同时最多 1 个符号**；持续 1.5–3 秒自动消失；符号不进角色矩阵，是独立图层。

* 规则：符号**不能与动机句同时出现**（否则像弹幕），动机句优先。

* 验收：把 `lower` 人为清空后播放走路，角色不发生撕裂或腿部残影；连续切换 10 个动作，角色比例不漂移（头始终在躯干上方、脚始终落地）；同屏 4 个 OC 各带不同符号，符号不互相遮挡且不与头顶气泡重叠。

### 12.20 上帝之手（X23：交互动效层，可关可开）

**定位**：这不是装饰，是**上帝视角的化身**。玩家不是「点一个按钮」，而是「伸手把它拿过来 / 扔下去 / 递进去」。

**手的规格（一只基础姿态 + 四种派生，不做六套）**

| 项 | 取值 |
| --- | --- |
| 尺寸 | **56×72 逻辑像素**；屏幕上按整数倍放大，2x = 112×144pt（约占手机横屏宽的 13%、高的 36%）。尺寸从 44×56 上调的原因：44 格宽画不下食指与手掌的 1 格指缝，降采样必然糊成一团；56 格宽是能保住「根根分明」的下限 |
| 描边 | 1px `#1A1A1A`，必须**闭合不断线**——这是拼豆手感的第一条，断一截就变贴图 |
| 填充 | 亮部 `#EACBA4`、暗部 `#C8A47C`；暗部固定出现在右侧与下侧各 1–2 格，制造体积 |
| 姿态 | **1 个基础姿态**（食指竖起 + 拇指张开 = 捏取），派生四种：0° / 90° / 180° / 水平镜像 |
| 派生映射 | 0° 持卡与刷卡；90° 掌根前推（摆物件）；180° 拎起（指尖朝下）；镜像用于反向出手 |
| 方向规则 | 从顶边伸入用 180°（指尖朝下）；从底边托起用 0°；推物件用 90°。**旋转只允许 90° 整数倍**，不做任意角度 |
| 为什么不做六套 | 六套要手绘 6 张、彼此比例极难统一，而且玩家根本分不清「张手」和「松开」的区别；一张加旋转镜像覆盖全部用途，省 5 张图 |
| 与角色的比例 | 角色立绘 29×29，手 56×72 —— **手必须明显比小人「大一号」**（约 1.9 倍宽、2.5 倍高）。这个比例是「我比它大」的全部来源，画小了就变成图标在拖东西 |
| 地图内只露指尖 | 拎起 OC 发生在世界地图上，整只手会盖住近三成的可视区。规则：**地图内出手只显示 sprite 上部 32×32（指尖）**，其余裁掉；卡面模式（新建/放入）才显示整只手 |

**三个出手节点（其余任何时候都不出手）**



| 节点         | 阶段                                           | 时长    | 曲线                                                |
| ---------- | -------------------------------------------- | ----- | ------------------------------------------------- |
| ① 建立：新建角色  | 手降下 120ms → 松手 80ms → 卡跌落旋转 150ms → 落定 60ms  | 410ms | 降下 ease-in；跌落 ease-in + 轻微旋转；落定 **ease-out-back** |
| ② 交付：放入世界  | 卡立起 150ms → 划过读取槽 200ms → 停 100ms → 翻正 150ms | 600ms | 划槽 linear + 中间 100ms 顿帧；「嘀」一声                     |
| ③ 夺走：拎起 OC | 捏住 80ms → 提起 120ms                           | 200ms | 之后长随光标（X06-b）                                     |

**ease-out-back 是整条链的关键**：落定要过冲一点点再回，才有「这卡是实体」的重量感。少这条曲线，卡会像 PPT 飞入一样飘。

**悬浮**：卡停在屏幕正中后，y 轴浮动 ±1px，周期 2 秒，ease-in-out sine。不能闪、不能抖。

**出场克制（三条硬规矩）**



1. **同一操作不重复出手**：连续新建第二张卡时，省略入场，卡直接淡入。

2. **每次出手 ≤0.6 秒**，做完立刻缩回。

3. **手永不遮挡角色卡的信息区**（照片区可以让，信息区不让）。

**开关（可关可开）**



| 档     | 行为                                 |
| ----- | ---------------------------------- |
| 开（默认） | 三个节点各出一次手                          |
| 关     | 完全不出手，新建 / 放入 / 拎起直接跳终态，保留 0.1s 淡入 |



* 与「减少动态」（X17）联动：**开启减少动态时自动关闭上帝之手**，不另行提示。

* 开关是玩家可见的设置项，不是隐藏彩蛋。

**实现要点**



* 手是**独立的顶层图层**（z-index 最高），不参与地图坐标计算，不占瓦片。

* 手的 XY 用屏幕坐标，不改地图相机。

* 卡在三段动画期间**不可点击**，落定后才恢复热区（防止动画中被误触）。

* 音效：仅「嘀」一声（刷卡）与「啪」（落定），不配背景音乐（X18 不做 BGM）。

**美术量**：手 1 张（56×72）+ 卡正 / 背 2 张 + 读取槽 1 张 = **4 张，约 1 小时**。其余是缓动代码与旋转。



* 验收：新建角色全程 410ms 内可点（或可跳过），手不遮挡信息区；放入世界刷卡 600ms 内完成且卡面在划槽时出现扫光；关闭上帝之手后三次操作全部直跳终态、无残影；连续新建 3 个角色，第 2/3 次不再出现入场手。

### 12.21 戳戳感（X24：所有交互的反馈规范）

**它解决什么**：手机上手指挡住点击点，玩家最容易产生的疑问不是「这个按钮叫什么」，而是**「我到底按到了没有」**。戳戳感的第一职责是回答这一句，第二职责才是好看。

**五种基础原语（全站只用这五种，禁止临时自创动画）**

| 原语 | 动作 | 幅度 | 时长 | 曲线 | 用在哪 |
| --- | --- | --- | --- | --- | --- |
| 压 | y +1px，按住期间保持 | 1px | 按住全程 | 立即 | 所有按钮按下 |
| 弹 | y −1px 过冲后回位 | 1–2px | 120ms | ease-out-back | 松手、确认、切换成功 |
| 抖 | x −1 → +1 → 0 | 1px | 150–200ms | 线性 | 拒绝、错误、装不下 |
| 浮 | y 0 → −1 → 0 循环 | 1px | 1s 一轮 | ease-in-out | 可交互物件、可点的 OC |
| 波纹 | 8×8 星形从落点扩散至 16px | 8→16px | 80ms | ease-out | **触屏每次点击**，无例外 |

**交互矩阵（哪一项用哪种，写死不许临场发挥）**

| 交互 | 原语组合 | 附加 |
| --- | --- | --- |
| 点 OC | 波纹 + 浮 | 动机句同帧出现 |
| 点物件 | 波纹 + 亮 12% | 有功能标签时出气泡 |
| 按住 OC 0.3s | 压（纵深 2px） | **按住 0.1s 时边框亮一圈**作预兆 |
| 拖 OC | 波纹 + 提起 2px + 落后光标 2px | 松手弹回 0 |
| 摆下物件 | 落下（y −4→0）+ 波纹 | 3 秒内可改位，不弹框 |
| 摆错位置 | 抖 + 拒绝音 | 落点虚线格变红一帧 |
| 按按钮 | 压 + 弹 | 描边反色（附录 D.3 已有） |
| 打开面板 | 从触发点撑开 + 过冲 2px | 120ms |
| 关闭面板 | 缩回 + 淡出 | 100ms |
| 切倍速 | 数字滚动 + 弹 | 时钟指针同步跳 |
| 切图层 | 高亮块滑移 | 100ms，不闪现 |
| 选中色块 | 波纹 + 外框弹出 | 外框从中心向外 120ms |
| 新建角色 | 上帝之手扔卡（§12.20） | 大仪式，不加波纹 |
| 放入世界 | 上帝之手刷卡（§12.20） | 大仪式，不加波纹 |

**三条铁律**

1. **幅度 ≤3px，默认 1px**。像素小人只有 29×29，位移超过 3px 就散架。
2. **时长 80–200ms**。低于 80ms 看不见，高于 200ms 变拖沓；大仪式（§12.20）单独放宽到 600ms。
3. **曲线不许线性**：进 ease-out、出 ease-in、确认 ease-out-back、循环 sine。唯一允许 linear 的是扫光与数字滚动。

**触屏专项（三件事，每一件都不能省）**

* **确认**：每次点击都出波纹（80ms，不依赖元素本身是否响应）。手指遮住的地方，只有波纹能证明「按到了」。
* **预兆**：长按类交互（拎起 OC）在按下 0.1s 时先让边框亮一圈，告诉玩家「再等 0.2 秒就成立」。没有预兆的长按，玩家只会以为卡了。
* **重量**：拖动时元素**落后光标 2px**，松手弹回 0。这 2px 是「它有点沉」的全部来源；完全跟随光标的东西像贴图，不像东西。

**性能与实现**

* 所有反馈走**同一个 tween 池**，最多 8 个并发；超出时新反馈直接跳终态，不排队。
* 统一一个 `requestAnimationFrame` 循环，禁止每个元素各自开动画。
* **禁用 CSS transition 做像素位移**：亚像素会产生灰边，一律用整数像素步进。

**分工（不要互相抢戏）**

* 上帝之手：三个大节点（建立 / 交付 / 夺走），稀缺、有重量。
* 戳戳感：所有小交互，无处不在、每次 100ms 级。
* **手出现的时刻不再叠加波纹**——否则一个大仪式里同时有五种反馈，观众不知道看哪。

* 验收：随机点 10 个可交互元素，每个都在 200ms 内给出可见反馈；手机连续点 20 次，波纹 20 次全出、无一次「点了没反应」；长按拎起有明确的 0.1s 预兆；拖动时元素稳定落后 2px 且松手归位；全站抽查 0 处亚像素模糊。
