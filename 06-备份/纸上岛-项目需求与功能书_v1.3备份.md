## 1. 一页 PRD

### 1.0 产品内核：拼豆成灵（v1.1 新增，全书技术地基）

一句话：**玩家在 29×29 的市面拼豆图纸上拼一个 Q 版 OC，每一颗豆同时记录「色号」和「部件」两个值；这张双矩阵本身就是剧本 —— 序列化成符号文本喂给大模型，模型回动作与台词，再用同一张矩阵确定性渲染回像素。**

四层含义：



1. **画布即图纸**：29×29 与市售拼豆图纸逐格对齐，玩家可用现成图纸、可照图买真豆复刻，作品天然能实体化。

2. **每颗豆两个值**：`color`（MARD 色号）+ `part`（部件标签，如 hair/eyes/coat）。先按色号拼（创作态），再标部件（可动化）；一格一豆，标部件不改像素。

3. **矩阵即语言**：双矩阵序列化成紧凑符号文本（附录 C），模型读的是「哪一格是什么颜色、属于哪个部位」，而不是图片。输入输出都可复算、可 diff、可版本化。

4. **零美术成本**：不生成位图、不做文生图。外观 100% 由玩家矩阵决定，AI 只负责剧情与动作，永远不会画出「不像那个 OC」的脸。

这条管线是市面没有的，也是个人开发唯一能打赢大厂的窄缝：**没有美术资产，只有结构化数据。**

产品按个人开发设计：单机可玩、无账号也能走完核心循环、API 成本玩家自付。

### 1.1 一句话定位

玩家用**拼豆式画布**造一个像素 OC（不用会画），填一张**角色卡**，把他放进一个**像素世界**（星露谷式瓦片地图，可换装、可摆物件、可自己改地图），看他和别的 OC 自由过日子；世界彼此独立、可开门相通，但一个角色只属于一个世界。生文与演绎是后续扩展，不是这一期的地基。

> 【补全】上述定位由三份文档的核心循环归纳；最终措辞待目标用户确认后可能调整。

### 1.2 目标用户



* **OC / 同人创作者**：已有角色设定或小说文本，希望角色 “活起来” 并被看见。

* **像素 / 拼豆手作爱好者**：享受一格一豆的确定性创作与实体感。

* **模拟经营与陪伴向玩家**：喜欢观察小人自主生活、积累关系与回忆。

> 【补全】目标用户为推导结论，尚未经过用户调研；
>
> **待目标用户确认后可能调整**
>
> 。

### 1.3 核心循环

`建世界（选/改地图） → 画 OC（拼豆画布） → 填角色卡并放入世界 → 换装与摆物 → 观察与互动 → 沉淀（关系/事件/纪念册）` ｜ 后续扩展：`接自带 API 生文 → 像素演绎`



1. **立宇宙**：先填世界观卡（语言腔调、时代氛围、色板、OOC 基准），宇宙与岛 1:1，允许先建成空岛。

2. **造人**：在该宇宙的色板与腔调下填写性格、价值观、禁忌、说话风格、知识边界，形成可执行的 OC 卡并放入岛中。

3. **过日子**：OC 按现实时间与日程自由活动，玩家观察、点击互动、送物件。

4. **看日子**：OC 按现实时间与日程在地图上走动，与别的 OC 自发互动，每天由事件池产出 2–4 件小事。（长内容与演绎为后续扩展：接自己的模型生成小说，再把文本演出来。）

5. **演绎**：文本被清洗、分场、抽节拍、映射动作，由像素矩阵确定性播放。

6. **沉淀**：演出进入纪念册，关系数值变化，岛与物件留下痕迹，反哺下一轮创作。

### 1.4 核心差异点



1. **双矩阵 + 符号文本**：每颗豆存「色号 + 部件」两个值，序列化成符号文本给大模型；AI 只产出结构与动作，外观由矩阵决定，100% 可复现，不做逐格文生图。

2. **OOC 四层边界**：角色硬约束 → 创造者边界 → 世界规则 → 当前场景关系，逐层过滤，越界 0 泄漏。

3. **BYO API**：玩家自付成本、自选模型；密钥只存本地，失败自动降级模板。

4. **一格一豆 + MARD 色号**：默认 29×29 市面图纸、40×40 上限、5×5 纯黑粗线、零缝隙填色、图层与部件双矩阵，同时具备绘画软件与拼豆图纸工具能力。

5. **四层社交且默认私密**：私密宇宙 → 好友圈 → 广场 → 公开页；内容先在私密层生长，公开是逐条动作。

### 1.5 范围与明确不做

**本期必须闭环**：1 张空白角色卡 → 拼豆画出形象 → 填姓名 / 性别 / 生日 → 放入 1 张预设地图 → 换 1 套衣服 + 1 件手持物 → 与另一个 OC 自发互动 1 次 → 事件池当天产出 ≥2 件事 → 本地存档可恢复。生文与演绎不在本期（后续扩展）。

**本期不做**：生文与演绎（R037–R046、R074–R086）、多世界同时在线切换（只做门跳转）、联机约戏、广场市场（录像 / 片段 / 模板）、精选策展、图纸名片、通知聚合、演出录像导出。

**本期一律不做**：实时大厅、频道聊天 / 陌生人私信、公会 / 阵营、排行榜、实时多人同屏、多人实时共创宇宙、陌生人进岛。

### 3.2 四层社交结构（R055–R069）



| 层 | 名称   | 默认可见性      | 装什么                  | 核心规则                        |

四层不是四个独立产品，而是同一份内容的四种出口：内容先在①生长，作者逐条决定是否进入②③④。**默认私密**；此前 “默认公开” 的讨论作废。纪念册属于①，是 OC 与玩家共同记忆的事实源；约戏成品同时写入双方①的纪念册各一份，②保留 “合作演出” 索引；③④只能引用快照。

### 3.3 明确不做



| 不做              | 理由                          |
| --------------- | --------------------------- |
| 实时大厅            | 需要实时同步与在线运营，违背 “异步为主、无运营成本” |
| 频道聊天 / 陌生人私信    | 骚扰与未成年风险最高，且与 “岛门授权” 模型冲突   |
| 公会 / 阵营         | 会把关系变成组织，稀释 “OC 与玩家” 的私人关系  |
| 排行榜             | 把创作变成数值竞争，与 “宇宙私密、关系沉淀” 相反  |
| 实时多人同屏 / 多人实时共创 | 本期一律不做；联机约戏是异步协作            |
| 陌生人进岛           | 公开页只展示，不提供任何进岛路径            |

* 规则：四项必填基准＝语言腔调、时代氛围、拼豆色板、OOC 基准；扩展字段最多 12 项。卡是该宇宙的宪法：角色、场景、物件、生成文本全部带 `world_card_version`；角色只能在卡的基础上加严，不能放宽卡或角色硬禁忌（冲突取更严）。

* 来源：【用户原话】“卡建立后能否修改、如何迁移、历史版本如何处理”【原文】I03；【补全】三类影响与三种迁移。

* 来源：【原文】F09（2.2/5.2/6.1）；【补全】锁定项、合规校验与降级模板；48 档裁决见 Q14。

#### R018 人物形象编辑器（重做版，合并 F47/H13） ｜ P0



* 画布：一格一豆，最大 40×40（自定 N 8–64）；常用档 15×15 / 21×21 / 29×29（市面拼豆图纸标准，新建默认）/ 40×40；**默认启动为空白画布**（不预置任何形象、不标色号，玩家自己拼）；改尺寸三选一（居中裁剪 / 扩展画布 / 整数倍最近邻重采样，非整数倍禁用），可预览 / 取消 / 撤销。

* 色号：MARD 标准色号体系。当前原型内置 **38 色常用子集**（H 灰白 7 / G 棕・肤 7 / E 粉 3 / F 红 5 / A 橙黄 3 / B 绿 3 / C 蓝青 6 / D 紫 4），色表见附录 A；界面按系列分组展示，支持直接输入色号（如 `C24` / `H2` / `D20`，与市售图纸色号对照）。全 291 色表待授权与版本核实后扩展，不阻塞当前绘制；`palette_version` 管理新增色，旧编号保留别名，历史作品锁版本；导入导出保留色号与 `palette_version`，缺色标「缺失色号」不静默近似替换。

* 填色渲染（v1.4 裁决）：填色格必须 `fillRect` 直角铺满整格（含四角），压住格线不留缝；空格内缩 1px 留出白缝；空格不标色号文字；外框在填色层之后最后绘制。

* 空 / 透明：空格 `color_id=null`，无像素、不统计；上色后每格必须绑定有效色号；橡皮为 `transparent`（显式记录、`alpha=0`），空与透明分账。

* 部件模型：`part{id, name, dictionary_type, parent_id, pivot, rotate_center, visible, order, layer_refs[{layer_id, cells[]}]}`；部件只保存 “哪些格属于我”，像素仍归图层，改色不改归属。**同一图层内一格只能归一个部件**；同一 `(x,y)` 在不同图层可分别归不同部件（外套层归外套、手层归手），跨层重叠不算冲突；不设 `exclusive_group`，不设主归属。重复标记已占用格必须弹 “替换 / 移除后加入 / 取消”，禁止静默覆盖。父子最多 3 层；每部件必须有锚点，默认包围盒中心（头发发根、眼睛中心偏下、下半身髋中线）；旋转按 90° 整数倍保存，自由角度仅预览。

* 词典：`head→hair→bangs`；`head→eye_l/eye_r、brow_l/brow_r、nose、mouth、ear_l/ear_r`；`body→upper_body→coat`；`body→lower_body→pants`；预留 `hand_l/hand_r、foot_l/foot_r、accessory`；标准 ID 不可改名删除；自定义挂标准类型或 `other`，个人词典 ≤20，可后续映射并保留别名。

* 标注与标记模式（v1.5 裁决：荧光笔感）：矩形框选、1/2/3 格刷选、魔法棒（当前层同色连通、容差 0、透明不参与）；选择不改像素、不进撤销；「打标 / 取消 / 重标 / 复制到其他层」各 1 步，共用 50 步撤销栈；跨层复制要求目标格已有像素且该层未占用。标记模式用按钮 / M 切换，与上色工具互斥；**11 个部件各固定一个高饱和荧光色**（见附录 B），以 α0.55 满格叠在底色上，像荧光笔划过 —— 不同部位一眼可分；颜色层与标记层独立开关；退出后已标记格仍可正常上色；标记撤销只回退归属与覆盖，不回退像素。

* 动画与导出：动画只引用部件 ID（眨眼 = 眼睛切帧 / 位移 1 格，说话 = 3 口型，走路 = 下半身交替，转头 = 头组绕锚点，头发 = 发根小幅旋转）；导出默认 PNG + JSON sidecar，必含 `parts[]`、按 `(layer_id,x,y)` 的唯一 `cell_membership`、`dictionary_version`、`color_system/palette_version`、尺寸 / 图层 / 顺序；导出前校验同层唯一归属，冲突阻止并列出冲突格；仅导 PNG 提示部件与色号丢失。

* 数据 / 判定：`artwork{id, universe_id, oc_id?, size, grid{minor:1, major:5, major_origin(0,0)}, color_system{name:"MARD", palette_version, source, verified}, layers[], palette[], parts[], animations[], marker_view, cover_frame}`；同层每格至多一个 `part_id`。

* 性能：40×40＝1600 格，全量重绘 ≤8ms，拖拽 ≥60fps；框选命中 ≤16ms，高亮 / 荧光笔重绘 ≤8ms，单格归属查询 ≤1ms；100 部件清单 ≥30fps；单作品内存 <20MB。

* 验收：15/21/29/40 与自定 N 均可建；粗线 3+1/4+4/6+2/8×8；同层重复打标必弹三选一且无法双重归属；跨层同位置可分别归属；父移动 / 旋转带动子；色号可定位、未命中不误上色、断网可用；荧光笔标注可切换 / 互斥 / 分色 / 独立开关 / 正确撤销；导出 JSON 可回读双矩阵、部件、层级、锚点与色号版本。

* 来源：【原文】F47/H13/F10（5.2/5.3/5.6）；【用户裁决】同层唯一归属、跨层可不同、MARD 色号体系（38 色内置）、空 / 透明、独立标记模式、40×40 与 5×5 粗线；【补全】锚点、词典、选区、导出与性能阈值。字体候选与许可证【需核实】。

#### R019 豆色与世界观色板 ｜ P0



* 规则：色号统一取自 MARD 标准（当前内置 38 色常用子集，附录 A）；创建宇宙推荐 6–12 色，玩家可增删至上限 24；拼豆 / 生成只用当前色板；任务、事件、图鉴可解锁限定色；限定色不跨宇宙通用；色板变更不影响已保存图纸历史颜色。

* 验收：切换宇宙后编辑器色板随之变化；未解锁色不可选；导出再导入颜色一致。

* 来源：【原文】F11（5.4/7.2）；【补全】上限、解锁来源与导出规则；MARD 38 色常用子集已于原型内置（附录 A），全表授权待核实。

#### R020 设定即任务 ｜ P0

* 验收：5 项均可直达并完成；完成度实时反映到 OC 卡；全部完成后首场演出入口出现。

* 来源：【原文】F12（2.2/2.8/8.1）；【补全】5 项任务、奖励与跳过规则。

#### R021 自拼物件、部件与配方 ｜ P0



* 规则：部件分底座 / 主体 / 装饰 / 交互点；配方＝部件组合 + 尺寸 + 必要标签；物件尺寸 16×16/32×32/48×48（物件可大于角色）；产出默认归玩家自创并记录作者与宇宙；配方可复用、可分享，使用配方不消耗原件。

* 数据 / 判定：`part{id, name, type, matrix, anchor}`；`recipe{parts[], size, tags[], author, visibility}`；`item{recipe_id, author, source(diy)}`；缺主体 / 超尺寸 / 循环引用 / 缺作者均拒绝。

* 验收：同一配方产出 2 件独立物件；作者来源正确；删除配方不影响已产出物件。

* 来源：【用户原话】“岛上各种东西可以自己拼出来”【原文】D01/H10；【补全】部件类型、配方、尺寸与归属。

#### R022 预设物件获取 ｜ P0



* 规则：渠道＝初始赠送 / 任务奖励 / 商店 / 导入；新宇宙初始赠 3–5 件；任务奖励一次性；商店只卖外观与预设，不卖数值；每个预设必须有来源与版权字段（官方 / 授权 / 用户导入）；未知来源拒绝上架；跨宇宙默认需授权。

* 数据 / 判定：`preset{channels[], availability, license{type, source, commercial_use}}`；`grant{source, preset_id, user, universe, ts}`；重复领取不重复发；版权缺失拒绝。

* 验收：四渠道均可获得；分类 / 标签可筛选；无版权信息不可用；跨宇宙未授权不可用。

* 来源：【用户原话】“也可以获取游戏预设物件”【原文】D02/H11；【补全】四渠道、分类与版权标注。

#### R023 物件属性、可用性与沙盘行为 ｜ P0



* 规则：分类＝家具 / 装饰 / 道具 / 食物 / 特殊；行为属性＝可坐 / 可躺 / 可交互 / 可携带 / 可破坏 / 可进戏 / 可赠予，每属性有触发条件与冷却；可交互必须绑定 ≥1 动作；可破坏需二次确认、不得伤害 OC、破坏后留痕；装饰物只作装饰；属性冲突标待确认。

* 数据 / 判定：`item.behavior{sit, lie, interact, carry, breakable, stage, giftable, cooldown, actions[]}`；`item_event{action, result, ts}`；无绑定动作的交互物不可用；属性与场景冲突置灰。

* 验收：椅子可坐、门可交互、花瓶可破坏但有确认；装饰物不产生交互；属性变更后下一次行为生效。

* 来源：【原文】D03/H12；【补全】行为属性清单、冷却与安全限制。

### 4.3 M2 角色岛与日常

#### R024 小岛沙盘与时间同步 ｜ P0



* 规则：岛上时间与现实同步（可配 1:1 或 1 游戏日 = 现实 2h）；日程分晨 / 日 / 昏 / 夜四段；无网络时本地时钟继续推演，上限 72 小时；超过 72 小时按 “沉睡” 处理，只补关键事件；同一时刻同屏 OC 上限按性能档 4/8/12；跨午夜正确切换。

* 数据 / 判定：`island{id, universe_id, time_mode, day_phase, layout}`；`schedule{oc_id, phase, activity}`；`world_clock{now, last_tick}`；时间跳变超过 5 分钟需重新校准并提示。

* 验收：8 小时后 OC 位置与行为符合其作息；跨天不重复结算；断网 72 小时内行为连续。

* 来源：【原文】F13/B06；【补全】时间倍率、72 小时上限与同屏上限。

#### R025 自由行为引擎（六步可审计） ｜ P0



* 规则：固定六步 —— 感知快照 → 意图生成 → 候选 1–3 → 四层过滤 → 执行与表现 → 写记忆；优先使用模板 / 规则，只有 “无合适模板、重大关系变化、玩家输入” 才调模型；常规日外部生成次数 0；同一 OC 两次意图最小间隔 30 秒；意图不得越出可活动区；每步写 trace。

* 数据 / 判定：`behavior_trace{trace_id, oc_id, perception_id, intent, candidates[], filtered_reason, action, memory_id, ts}`；`intent` 必须含目标与理由；候选为空转 idle；trace 保留 7 天，供 “为什么这样做” 查询。

* 验收：每次可见行动都有完整 trace；常规日不产生外部调用；行为不越界；过滤理由可解释。

* 来源：【原文】F44/B04/C02/H05；【补全】30 秒间隔、trace 保留期与触发模型的三种情况。

#### R026 感知快照 ｜ P0



* 规则：只采集当前场景可见信息（在场 OC、物件、时间、天气、最近事件）；不读取其他宇宙、未在场 OC 的私密记忆、玩家未公开内容；快照 5 分钟过期；知识边界外信息不进入候选；缺字段用默认值。

* 数据 / 判定：`perception{id, oc_id, scene, visible_ocs[], items[], time, weather, recent_events[], knowledge_scope}`；`knowledge_scope` 与 R012 对齐；过期快照不得复用。

* 验收：不在场 OC 不出现在快照；私密内容不泄漏；删除物件后快照不再引用。

* 来源：【原文】C01；【补全】5 分钟过期与默认值。

#### R027 候选行为与约束过滤 ｜ P0



* 规则：每轮 1–3 个候选，必须带目标、动作、预期结果；过滤顺序＝角色硬禁忌 → 创造者边界 → 世界规则 → 场景 / 关系约束；任一硬层命中即淘汰并记录原因；软层可按权重降级；同输入同状态选择稳定（可 seeded）。

* 数据 / 判定：`candidate{action, target, reason, score, filtered_by}`；`filter_result{layer, rule_id, decision}`；无候选转 idle 并写 “无事可做”。

* 验收：禁忌候选 100% 不执行；过滤顺序可回放；同一 seed 重放结果一致。

* 来源：【原文】C03；【补全】字段、seed 与 idle。

#### R028 可活动范围与行为白 / 黑名单 ｜ P0



* 规则：初始化定义可行走区（格子 / 多边形）；行为白名单限定可用动作；黑名单限定不可用动作；黑名单优先于白名单；未定义区域视为不可行走；玩家可逐区开关；变更即时生效。

* 数据 / 判定：`nav_area{polygon}`；`behavior_policy{whitelist[], blacklist[]}`；黑名单并集；路径不可达时选最近可达点并提示。

* 验收：OC 不出可行走区；黑名单动作 100% 不执行；白名单外动作不可选。

* 来源：【原文】C04；【补全】黑名单优先与不可达降级。

#### R029 世界规则 ｜ P1



* 规则：规则分硬规则（不可违反）与软规则（可降级）；来源分官方 / 玩家 / 系统安全；玩家可新增，但不能删除系统安全规则；冲突取更严；规则必须写明适用范围与例外。

* 数据 / 判定：`world_rule{id, level, scope, text, source, active}`；`rule_conflict{winner, reason}`；未写范围的规则不得启用；规则变更需确认。

* 验收：硬规则不可被角色边界放宽；玩家删除安全规则时被拒；冲突有可读理由。

* 来源：【原文】C05；【补全】规则字段与安全规则不可删。

#### R030 岛布局与物件摆放 ｜ P1



* 规则：网格化摆放，同格不重叠；物件可旋转 90° 整数倍；越界自动钳制到最近合法格；演出可改变布局（如搬家），变更进入可回滚队列；玩家手动编辑优先于演出自动变更。

* 数据 / 判定：`layout{grid, items[{item_id, x, y, rotation, layer}]}`；`layout_change{source(manual/performance), before, after}`；保留最近 5 次；同一变更重复应用幂等。

* 验收：同格摆第二件时提示并偏移；演后布局真实改变；回滚 5 次可用。

* 来源：【原文】B05；【补全】旋转、钳制与回滚队列。

#### R031 观察与点击互动 ｜ P0



* 规则：点击 OC 打开底部互动面板，四个主按钮＝打招呼 / 聊天 / 送礼 / 查看状态；聊天为短句，不进入自由多轮长对话；每次互动必须有可见反馈并写记忆；同一 OC 每日 ≤20 次，间隔 10 秒；重复点击同一内容不重复写记忆；互动前过 OOC 前置校验。

* 数据 / 判定：`interaction{oc_id, type, input, response, memory_id, ts}`；`daily_counter{oc_id, date, count}`；超限提示 “今天聊够了”；响应失败用角色内短句兜底。

* 验收：每次互动均有动画 / 文字 / 音效之一；记忆去重；超限被拦；越界输入被安全回复。

* 来源：【原文】F14/B02；【补全】四按钮、每日上限、冷却与去重。

#### R032 送礼与物件归属 ｜ P0



* 规则：玩家在岛上给 OC 送礼，每日 ≤3 次；礼物需在玩家持有物中；OC 按偏好 / 关系 / 场景决定接受或婉拒；接受后物件所有权从玩家转移至 OC（或岛），玩家不可再直接收回；婉拒也写事件；同一物件不可重复赠送；送礼可影响关系强度（单次 ≤20）。

* 数据 / 判定：`gift{from, to, item_id, status(accepted/refused), relation_delta, memory_id}`；`ownership{item_id, owner_type(player/oc/island)}`；所有权变更需原子性；礼物被删则事件保留。

* 验收：送 3 次后第 4 次被拦；接受后物件出现在 OC 持有列表；婉拒有明确反馈且留痕。

* 来源：【原文】F15/D04；【补全】每日上限、偏好判定、所有权与幂等。

#### R033 物件影响行为与记忆 ｜ P1



* 规则：交互物进入候选行为池（如椅子→坐下、床→睡觉、书→阅读）；物件偏好标签影响选择权重；使用后写记忆并附物件 ID；可破坏物被破坏后从布局移除并留事件；物件不得伤害 OC 或改变硬边界。

* 数据 / 判定：`item.behavior` 与 `memory{refs[]}` 双向引用；物件下架但已存在时可继续使用；缺失物件回退普通动作；破坏需确认。

* 验收：有椅子时 OC 会坐；偏好匹配提高选择率；破坏后不再出现。

* 来源：【原文】D05；【补全】候选池、偏好权重与移除规则。

#### R034 回忆碎片 ｜ P1



* 规则：每日 1–3 次，在岛内以气泡 / 短动画呈现；内容取自 OC 记忆，优先 7 天未被引用的；时长 5–15 秒，可点击展开可收藏；受 OOC 与可见性约束；不展示玩家私密原文。

* 数据 / 判定：`memory_fragment{memory_id, oc_id, shown_at, collected}`；同一记忆 7 天内不重复；错过可进纪念册；无记忆时不生成。

* 验收：碎片内容有来源记忆；7 天去重；可收藏并在纪念册可见。

* 来源：【原文】F16；【补全】频次、时长、去重与收藏。

#### R035 人设守护日志 ｜ P1



* 规则：只在真实发生硬拦截、软改写、玩家诱导被拒时记录；不记录模型内部推理；每条含时间、触发输入摘要、命中约束、处理方式；每日 ≤5 条；不复述雷区原文；用户可删除，删除后不再引用。

* 数据 / 判定：`guard_log{level, rule_id, input_summary, action(block/rewrite/refuse), ts}`；日志默认私密；按 OC 可筛；导出不含原文；删除为软删并断开引用。

* 验收：一次真实越界产生 1 条；无越界不产生；日志不含禁忌原文；删除后生成不再引用。

* 来源：【原文】F17；【补全】触发条件、字段、上限与删除。

#### R036 离线事件报告 ｜ P1



* 规则：离线 ≥2 小时生成；报告 1–3 件事，含时间、地点、参与者、结果；最多 1 条 LLM 叙事，其余模板；事件来自离线推演且符合 R025 过滤；只弹一次，可 “查看详情 / 去找他 / 知道了”；不重复写入。

* 数据 / 判定：`offline_report{start, end, events[], generated_by, read_at}`；离线 <2h 不生成；72h 以上只补关键事件；事件引用失效时用摘要。

* 验收：离线 8 小时有报告；随机 3 件事可定位到 OC / 地点；重复登录不重复弹。

* 来源：【原文】F18；【补全】2 小时阈值、1 条 LLM 上限与只弹一次。

### 4.4 M3 戏台与演绎

#### R037 剧情输入、清洗、分场与节拍抽取 ｜ P0



* 规则：输入支持粘贴、导入、R011 解析结果、R086 候选；先清洗（去水印、统一标点、保留对白、剔除无法执行的舞台指示），再分场（3–6 场，每场含地点 / 在场 / 时长），再抽节拍（每 beat 含角色 / 动作 / 对白 / 情绪 / 目标）；角色必须在本宇宙且在场，缺角色提示添加或替换；玩家可逐段对照原文；分场 / 节拍可手改。

* 数据 / 判定：`script{id, universe_id, source, scenes[{location, actors[], beats[]}], version, status}`；`beat{actor, action, dialogue, emotion, target}`；无法映射的动作降级为旁白；清洗不得改变原意；确认前不进入演绎。

* 验收：示例 1300 字生成 4 场、6 节拍；每个 beat 可执行；原文可逐段对照；缺角色被拦。

* 来源：【原文】F19 / 功能书 - F01–F03；【补全】清洗规则、场数范围与字段。

#### R038 动作映射到像素小人 ｜ P0



* 规则：建立动作库（待机 / 走 / 跑 / 坐 / 挥手 / 点头 / 摇头 / 拥抱 / 递物 / 惊讶等，具体数量待 Q22）；每 beat 映射 “1 个主动作 + 1 个表情”，可叠加朝向；动作必须在库内，库外降级 “旁白 + 站立 + 表情”；目标点不可达则选最近可达点；同一 beat 重演结果一致。

* 数据 / 判定：`action_map{beat_id, action_id, expression, target, fallback}`；`action_library{id, name, loop, duration, allowed_parts}`；映射缺失即阻断该 beat 并提示。

* 验收：动作库内 100% 可执行；库外有明确降级；两次重演一致。

* 来源：【原文】功能书 - F04；【补全】动作 + 表情、不可达降级与一致性。

#### R039 确定性舞台演出与播放控制 ｜ P0



* 规则：舞台上每个像素小人的位置 / 动作 / 表情 / 道具由剧本矩阵确定，不由模型实时发挥；同一剧本 + 同一场景 + 同一物件状态 → 同一演出；单场 1–3 分钟；0.5–2x 变速；按场景跳转；可暂停 / 继续；中断后从最近场景续播；离线可回放（素材本地化）。

* 数据 / 判定：`performance{id, script_id, universe_id, scene_snapshot, item_snapshot, timeline[], status}`；`timeline` 记录每帧 / 每事件；渲染与逻辑分离；缺素材用占位；不得边生成边演。

* 验收：同剧本两次逐帧一致；变速不改剧情；跳过不丢结尾；离线可完整回放。

* 来源：【原文】F20 / 功能书 - F05；【补全】时长、变速、场景跳转与离线。

#### R040 直接文本驱动行动 ｜ P0



* 规则：玩家输入单行指令，格式 “角色 + 动作 + 目标”（如 “阿岛把花递给小满”）；只解析本宇宙角色与动作库；动作库外拒绝并给 3 个候选；执行前过 R083；一次只执行一个动作；不产生长剧情。

* 数据 / 判定：`directive{raw, actor, action, target, parsed, result}`；解析失败提示改写；执行结果写演出记录与记忆；同一指令幂等。

* 验收：合法指令 1 秒内执行；非法指令给候选；越界指令被拒。

* 来源：【原文】功能书 - F06；【补全】单行格式、候选与幂等。

#### R041 剧本视图与重演 ｜ P1



* 规则：剧本以时间线 / 卡片展示；可复制、改一句、重演该场；每次保存为新版本，保留 ≤10 版；官方版唯一，旧版只读；重演前重新校验 OOC 与关系；原版永久保留；离线可编辑但不触发重演生成。

* 数据 / 判定：`script_version{version, parent, diff, official}`；`performance` 关联版本；删除版本不删除演出；重演不覆盖原演出。

* 验收：改一句后差异可见；10 版上限生效；官方版不可被覆盖；离线编辑不丢。

* 来源：【原文】F21；【补全】版本上限、官方版与离线规则。

#### R042 拼豆道具进戏 ｜ P1



* 规则：选择玩家自拼 / 预设物件进入演出，每场 ≤5 件；物件需可进戏属性；在 beat 上绑定 “出现 / 使用 / 消失”；演出后可留在岛上或收回；同一物件可重复使用；不得改变物件属性。

* 数据 / 判定：`stage_item{performance_id, item_id, beat_id, action(show/use/hide), post_state}`；物件被删则演出用快照；超 5 件拒绝。

* 验收：道具按 beat 出现；演后可收回；物件删除后旧演出仍可播。

* 来源：【原文】F22；【补全】5 件上限、绑定与快照。

#### R043 边界松紧滑杆 ｜ P1



* 规则：三档 “严格 / 标准 / 宽松”；只允许放宽 `soft_limits`（如更外放的表达），不得放宽 `never_do`、雷区、世界硬规则、安全规则；可作用于单场或单节点；演出结束自动恢复；切档需二次确认；宽松档也要过 R083。

* 数据 / 判定：`boundary_mode{scope, level, expires_at}`；`effective_constraints = base ∩ mode`；硬层不可被 mode 覆盖；越界仍拦截。

* 验收：宽松档台词更外放但不突破硬边界；结束自动恢复；二次确认生效。

* 来源：【原文】F23；【用户裁决】硬边界永远不放宽；【补全】三档、作用域与自动恢复。

#### R044 演出录像导出 ｜ P1



* 规则：导出 1080p/30fps、≤3 分钟；只导出自己有权的 OC 与素材；含他人 OC 需对方授权；默认带 “纸上岛” 水印，可关；失败降 720p；导出中可取消；不导出私密纪念册原文。

* 数据 / 判定：`export_video{performance_id, resolution, watermark, authorization_refs[], status}`；授权缺失拒绝；取消清理临时文件；重复导出幂等。

* 验收：导出可播放；他人 OC 未授权被拦；失败有降级；取消无残留。

* 来源：【原文】F24；【补全】水印、授权与失败降级。

#### R045 演绎失败降级 ｜ P1



* 规则：任何输入都必须有可看结果：能映射则演，不能映射则 “旁白 + 角色朗读 + 静态立绘”；降级点必须在界面可见；连续 3 次失败建议拆分剧本；不出现空白舞台；失败不写 “成功演出” 记录。

* 数据 / 判定：`performance.status(degraded/failed)`；`degrade_reason`；失败可重试；重试使用同一输入；连续失败计数按剧本。

* 验收：空文本 / 乱码 / 超长均有可看结果；降级原因可见；不产生空白舞台。

* 来源：【原文】功能书 - F07；【补全】可见降级、连续失败建议与记录语义。

#### R046 演绎结果记录 ｜ P1



* 规则：每次演出写一条只追加记录，含剧本版本、场景 / 物件快照、参与 OC、时间、结果状态；可重播；删除需二次确认并软删；同一演出不重复写；记录不因剧本删除而丢失。

* 数据 / 判定：`performance_record{performance_id, script_version, snapshot_refs[], actors[], status, created_at}`；`deleted_at`；重播读记录不重新生成。

* 验收：演出后恰好 1 条；删除剧本后仍可重播；重复点击演出不重复写。

* 来源：【原文】功能书 - F08；【补全】快照、软删与幂等。

### 4.5 M4 沉淀

#### R047 纪念册时间线 ｜ P0



* 规则：纪念册是 OC 与玩家的共同记忆事实源；按时间倒序；每条含事件、参与 OC、地点、来源（演出 / 互动 / 离线 / 送礼）；可筛选角色 / 类型 / 时间；演出后自动写 1 条；同一场只保留 1 个官方版本；纪念册默认私密，不自动进入公开页。

* 数据 / 判定：`memorial_entry{universe_id, type, title, summary, refs[], actors[], visibility, official, created_at}`；引用被删时保留快照摘要；不覆盖旧条目；可按 OC 聚合。

* 验收：演出后 1 条；筛选正确；引用删除仍可读；私密不外泄。

* 来源：【原文】F25；【补全】事件类型、官方版与快照。

#### R048 关系天平与关系活地图 ｜ P0



* 规则：关系值统一为 0–100 双向（按 R014）；单事件变化 ≤20；每日无事件回落 1；双向独立；地图以 OC 为节点、关系为边，支持按类型 / 强度过滤；点击边显示事件；只展示玩家有权查看的关系。

* 数据 / 判定：`relation_state{strength_ab, strength_ba, status, last_event}`；`relation_heatmap` 由事件派生；孤立 OC 单列；不公开展示他人关系。

* 验收：送礼 / 演出改变关系且可追溯；天平双向不同；地图过滤正确。

* 来源：【原文】F26；【补全】回落、过滤与可见性。

#### R049 岛与道具改变 ｜ P1



* 规则：演出可触发预定义改变（搬家 / 换家具 / 物件损坏 / 新增装饰）；改变必须来自剧本且玩家在演出前可见提示；进入可回滚队列最近 5 次；手动编辑优先；重复播放同一演出不重复应用。

* 数据 / 判定：`island_change{type, target_id, before, after, source_performance, applied_at}`；`idempotency_key = performance_id + change_id`；回滚需确认。

* 验收：演 “搬家” 后布局真实改变；回滚 5 次可用；重播不重复。

* 来源：【原文】F27；【补全】预定义类型、提示、幂等与回滚。

#### R050 收藏图鉴 ｜ P2



* 规则：图鉴分 OC / 色号 / 演出 / 物件四册；新内容首次获得自动点亮；删除内容不回收图鉴；与角色卡册分开；显示获取时间与来源；不展示未解锁内容详情。

* 数据 / 判定：`collection_entry{type, ref_id, unlocked_at, source}`；`collection_progress` 派生；重复获得不重复计数；跨宇宙可汇总但标注来源。

* 验收：新 OC / 色 / 演出自动点亮；删除后仍显示；未解锁不剧透。

* 来源：【原文】F28；【补全】四册、来源与汇总规则。

### 4.6 M5 多宇宙

#### R051 宇宙管理、隔离、切换与归档 ｜ P1



* 规则：所有实体（OC / 关系 / 物件 / 纪念册 / 演出 / 缓存 / 记忆）必须带 `universe_id`，查询与生成默认按宇宙过滤；切换只换视图，不把 A 宇宙实体拖入 B；跨宇宙引用一律只读快照；复制必须显式 “复制到我的宇宙” 并生成新 ID；归档宇宙只读、可回访、不参与计费；删除按 R008 分级执行。

* 数据 / 判定：`universe_ref{universe_id}`；`cross_universe_ref{source_universe, target_universe, snapshot_id, mode(readonly/copy)}`；隔离测试：A 的记忆不出现在 B 的检索；归档不可写；删除前检查引用。

* 验收：切换宇宙后 OC / 物件 / 纪念册均不串；跨宇宙只读；归档可回看；删除有引用时列出。

* 来源：【原文】F29/B03/H09；【用户裁决】“宇宙必须隔离”；【补全】实体字段、只读引用与归档语义。

#### R052 宇宙解锁节奏与门控 ｜ P1



* 规则：新建宇宙需同时满足三条门控 ——① 当前宇宙主线的关键剧情节点 100% 完成；② 官方演出场次 ≥ 关键节点数 + 1 个里程碑（如 “第一次告别”）；③ 账号等级达到 L5（第 2 个）/L8（第 3 个）/L10（第 4+）；任何时刻 “未完成的新宇宙” ≤1；禁止付费 / 道具跳过门控；已建宇宙数量不限，但同时运行 / 活跃 ≤3。

* 数据 / 判定：`unlock_gate{target_universe, key_nodes_done, performances_done, milestone_id, level, unmet[]}`；`active_universes ≤3`；未达标显示缺项与进度，不提供新建入口；达标后仍需玩家确认创建。

* 验收：节点未满不能建第 2 个；只完成节点但演出不足仍锁定；同时运行第 4 个被拦；无跳过入口。

* 来源：【原文】F30/I09–I11；【用户原话】“防摊大饼”；【补全】“节点数 + 1” 公式与 L5/L8/L10 档位。

#### R053 跨宇宙客串 ｜ P1



* 规则：客人 OC 进入宿主宇宙，单场 ≤2 人；时长三选一（单场 / 1 游戏日 / 3 游戏日），到期自动返回；宿主主权五级 —— 宿主世界观卡 > 宿主角色硬禁忌 > 双方软边界交集 > 客人角色设定 > 客人原宇宙惯例；冲突时宿主卡与硬禁忌优先，其次取双方更严；文化冲突只作为候选事件，需玩家确认才发生；客串期间只共享 “共同记忆摘要”，不读写对方私密纪念册；客人不得修改宿主布局 / 关系 / 物件归属；离开时生成一份双方可见的客串记录。

* 数据 / 判定：`guest_session{guest_oc, host_universe, duration, sovereignty_log[], shared_memory_summary, status}`；`guest_boundary = host_hard ∩ guest_hard ∩ (host_soft ∩ guest_soft)`；硬层取并集（任一禁止即禁止），软层取交集（双方都允许才允许）；超 2 人拒绝；到期强制返回并留记录。

* 验收：客人不能突破宿主 `never_do`；双方软边界冲突时取更严；客串记忆不进入对方私密纪念册；到期自动返回。

* 来源：【原文】F31/I05–I08；【用户裁决】“客串边界取交集、宿主主权”；【补全】五级顺序、时长与共同记忆摘要；原 F31 标 P2，项目书要求提前，按 P1。

#### R054 宇宙图鉴 ｜ P2



* 规则：每个宇宙建成即生成唯一编号（如 `U-0001`）；记录名称、世界观卡摘要、风格标签（≤3 个，可后补）、完成度（派生，不手填）、创建时间；可只读分享；不公开私密内容；删除宇宙后编号保留不可复用。

* 数据 / 判定：`universe_codex{code, universe_id, name, card_summary, style_tags[], completion, created_at}`；完成度由节点 / 演出 / 图鉴派生；分享只读快照。

* 验收：建成自动编号；标签可补但不超 3；完成度随进度变化；删除后编号不复用。

* 来源：【原文】I04；【补全】编号格式、派生完成度与只读分享。

### 4.7 M6 社交（四层结构）

#### R055 私密宇宙与默认私密 ｜ P0



* 规则：新宇宙、新 OC、新演出、新纪念册、新物件默认 `private`；他人任何视图只能看到只读快照，不能看到边界原文、记忆原文、草稿、未公开演出；私密内容不进入搜索 / 推荐 / 广场；公开是逐条动作，不继承；关闭公开页不影响已授权的好友访问（按条目授权）。

* 数据 / 判定：`visibility` 默认 `private`；`snapshot{source_id, allowed_fields[], version}`；快照字段白名单不含 `never_do/soft_limits/memory_raw`；越权请求返回 403。

* 验收：新内容默认私密；他人视图无敏感字段；关闭公开页后好友授权仍按条目有效。

* 来源：【原文】F60/K01/J01；【用户裁决】“默认私密、先有可晒内容再谈社交”；【补全】快照字段白名单。

#### R056 好友关系、请求、分组与拉黑 ｜ P0



* 规则：加好友需双向同意；请求 7 天过期；拒绝后 24 小时冷却；好友上限 200、分组 50、单分组 20；分组只影响展示与批量授权，不影响既有授权；拉黑立即断开所有授权、停止手信与通知；解除拉黑不自动恢复授权。

* 数据 / 判定：`friend_request{from, to, status, expires_at}`；`friendship{status, groups[], since}`；`block{from, to, ts}`；拉黑为最高优先级；被拉黑方不可再发请求。

* 验收：单向请求不成为好友；过期自动失效；拉黑后岛门 / 手信立即不可用；解除拉黑需重新授权。

### 4.9 M8 AI 内核与生成

#### R074 用户 API 配置与 BYO 降级 ｜ P0



* 规则：支持保存多套配置，仅 1 套默认；配置含服务商、Base URL、模型名、密钥；必须 “测试连接” 通过才可设默认；生成前检查可用性；不可用时自动降级本地模板 / 规则，并在界面明示 “未使用你的 API”；失败不阻塞主流程。

* 数据 / 判定：`api_config{id, provider, base_url, model, key_ref, is_default, last_test}`；密钥不入配置明文（见 R076）；测试失败不可设默认；降级记录 `fallback_reason`。

* 验收：多套配置仅 1 默认；测试失败被拦；断网 / 欠费时流程可继续且明示降级。

* 来源：【原文】F04/E01；【补全】测试门禁、默认唯一与明示降级。

#### R075 多服务商适配 ｜ P0



* 规则：建立统一请求 / 响应与能力矩阵（文本 / 长文 / 流式 / JSON / 多模态）；不支持的能力显式降级，不假装成功；错误码统一映射（鉴权 / 限额 / 超时 / 内容 / 未知）；服务商差异只在适配层处理，不污染业务规则。

* 数据 / 判定：`provider_capability{provider, capabilities[], limits}`；`normalized_result{text, usage, finish_reason}`；能力缺失走降级；错误码可读。

* 验收：两家服务商同一剧本均可跑；不支持 JSON 时降级仍可解析；错误提示可操作。

* 来源：【原文】E02；【补全】能力矩阵与错误归一。

#### R076 密钥本地保存与不外泄 ｜ P0



* 规则：密钥仅存本地（加密存储），界面只显示掩码；日志、导出包、分享快照、崩溃报告一律不得包含密钥；删除配置即删密钥；换设备需重新填写；云端只同步 “配置存在” 标记，不同步密钥；密钥不进入任何提示词。

* 数据 / 判定：`key_ref{config_id, storage(local), masked}`；日志脱敏规则必须覆盖 `sk-*` 等模式；导出前扫描；删除后不可恢复。

* 验收：全量日志 / 导出 / 分享搜索不到密钥；删除配置后本地无残留；换设备需重填。

* 来源：【原文】E03；【用户约束】密钥安全；【补全】掩码、脱敏扫描与云同步边界。

#### R077 超时、限流、重试与熔断 ｜ P0



* 规则：普通请求 30 秒、长文 120 秒；429/5xx 指数退避重试 ≤2 次；401 立即停止并提示重配；连续 3 次失败熔断 10 分钟；重试必须幂等，不重复落库 / 不重复扣记忆；超时先给可读提示再降级。

* 数据 / 判定：`request_attempt{config_id, attempt, status, latency}`；`circuit{state, opened_at}`；熔断期间走模板；重试键 `idempotency_key`；超时不自动换服务商。

* 验收：429 重试后成功只落 1 条；401 不再重试；熔断 10 分钟生效；超时有降级。

* 来源：【原文】E04；【补全】时限、退避、熔断与幂等。

#### R078 长文分段与上下文记忆 ｜ P0



* 规则：超过单次上限先大纲，再分段生成；每段携带滚动摘要（世界观卡、角色卡、关系摘要、前文摘要）；段间做一致性检查；支持断点续写；10 段后角色 / 关系 / 世界观不漂移；失败保留已完成段。

* 数据 / 判定：`long_job{outline, segments[], summary_rolling, status}`；`segment{index, content, summary, consistency_check}`；超长拒绝并建议拆分；断点续写从最后成功段开始。

* 验收：10 段后核心设定不变；中断可续；已完成段不丢。

* 来源：【原文】E05；【补全】滚动摘要、一致性检查与断点续写。

#### R079 角色一致性维护 ｜ P0



* 规则：生成请求必须携带 “角色圣经”（性格、口癖、称呼、关系、知识边界、当前情绪）；输出后校验称谓 / 口癖 / 关系 / 知识边界；不一致先重写 1 次，仍不一致标记问题段落，不静默通过；关系变化必须来自事件，不得凭空。

* 数据 / 判定：`character_bible{oc_id, version}`；`consistency_check{issues[], rewrite_count, status}`；问题段落可定位；圣经版本随演出记录保存。

* 验收：10 次生成中称谓 / 口癖一致；不一致被标记；关系不凭空变化。

* 来源：【原文】E06；【补全】圣经字段、重写 1 次与段落标记。

#### R080 内容安全兜底 ｜ P0



* 规则：输入先过滤、输出再过滤；覆盖违法、色情、暴力、未成年不适、仇恨、自伤等；命中即阻断或改写，并给用户可读理由；安全策略不可被用户关闭；不回显违规原文；涉及未成年一律更严。

* 数据 / 判定：`safety_check{stage(input/output), category, action(block/rewrite), policy_version}`；策略版本化；阻断不落库；改写保留语义安全；不可绕过。

* 验收：违规输入不进入模型；违规输出不落库；用户无法关闭；理由可读。

* 来源：【原文】E07；【补全】输入 / 输出双过滤、策略版本与不可关闭。

#### R081 生成任务管理 ｜ P1



* 规则：任务状态＝排队 / 运行 / 暂停 / 完成 / 失败 / 取消；显示进度与耗时；取消 5 秒内生效；部分完成可继续；重复提交幂等；失败可重试但不重复计费；任务列表可按宇宙 / 类型筛选。

* 数据 / 判定：`generation_job{id, type, status, progress, partial_result, error, cost}`；取消清理临时结果；幂等键；失败重试沿用原输入。

* 验收：状态可见；取消 ≤5 秒；部分完成可续；重复点击不重复任务。

* 来源：【原文】E08；【补全】状态机、取消时限与幂等。

#### R082 OOC 约束前置包与四层优先级 ｜ P0



* 规则：四层约束 ——① 角色硬约束（`never_do`、雷区、知识边界）；② 创造者边界（OC 卡 `soft_limits`、关系与称呼）；③ 世界规则（世界观卡 + R029）；④ 当前场景 / 关系（在场、地点、情绪、可见性）。优先级从①到④；冲突取更严；创造者只能加严不能放宽①②；每次请求生成约束包哈希并记录；缺 OC 卡 / 世界观卡拒绝生成。

* 数据 / 判定：`constraint_pack{hash, layers[4], effective_rules[]}`；`effective = L1 ∩ L2 ∩ L3 ∩ L4`；硬层取并集（任一禁止即禁止）；软层取交集；哈希随生成记录保存，便于复现。

* 验收：四层均进入请求；硬层冲突时更严者胜；缺卡被拒；哈希可复现同一约束。

* 来源：【原文】C06/H04；【补全】四层命名、哈希与交集 / 并集算法。

#### R083 OOC 后置校验、重试与兜底 ｜ P0



* 规则：生成后先做规则校验（称谓 / 关系 / 知识 / 禁忌），再做模型校验（语义偏离）；硬禁忌命中直接拦截；软偏离改写后重检，最多 2 次；仍失败用安全模板 / 角色内拒绝兜底，兜底不再调用模型；越界内容 0 落库、0 回显原文；每次拦截写守护日志（R035）。

* 数据 / 判定：`ooc_check{stage(pre/post), issues[], action(block/rewrite/fallback), retry_count}`；`fallback_template`；重试上限 2；拦截记录关联 `constraint_pack.hash`；不把违规文本写入记忆。

* 验收：越界测试集 0 泄漏；软偏离最多改写 2 次；兜底不调用模型；日志不含量禁区原文。

* 来源：【原文】F42/C07/H06；【补全】两段校验、重试上限与兜底模板。

#### R084 玩家诱导越界与回滚 ｜ P1



* 规则：玩家用 “忽略设定 / 扮演另一个人 / 说出禁忌” 等诱导时，角色在角色内拒绝，不出戏、不复述禁忌；若已产生越界行动，支持回滚到上一节点并标记该分支无效；连续诱导 3 次冷却 10 分钟；每日记录 ≤5 条；不惩罚正常创作。

* 数据 / 判定：`induction_event{input, detection, response, rollback_ref}`；`cooldown{until}`；回滚不删除原始记录（标记 invalid）；诱导检测与内容安全并行。

* 验收：诱导被角色内拒绝；可回滚；连续 3 次冷却；正常创作不受影响。

* 来源：【原文】C08/H07；【补全】角色内拒绝、回滚与冷却。

#### R085 记忆系统 ｜ P0



* 规则：记忆分结构化（事件、关系、物件、演出）与向量（语义检索）；检索先按 `universe_id` 隔离，再按 OC / 时间 / 类型过滤，最后 Top-K 摘要；生成只带摘要不带原文；删除内容同步移除引用；冷记忆归档但可回查；不跨宇宙混检。

* 数据 / 判定：`memory{id, universe_id, oc_id, type, summary, refs[], embedding_ref, created_at, archived}`；`memory_index{universe_id, oc_id}`；删除级联；Top-K 可配；摘要长度受控。

* 验收：A 宇宙记忆不出现在 B；删除后检索不到；生成上下文只含摘要；冷记忆可回查。

* 来源：【原文】F43；【补全】隔离、Top-K、级联与冷归档。

#### R086 续写引擎 ｜ P1



* 规则：基于世界观卡 + 角色卡 + 记忆 + 当前剧本生成 3 条候选续写；每条标注 “沿用 / 转折 / 风险”；玩家采用后才写入；采用前过 R083；不采用的候选不落库、不写记忆；连续 3 次不采用不改变角色状态。

* 数据 / 判定：`continuation{candidates[3], adopted_index, ooc_check}`；未采用不持久化；采用写剧本版本；候选失败降级为模板建议。

* 验收：3 条候选可比较；未采用不污染；采用前过边界；失败有模板。

* 来源：【原文】F45；【补全】3 候选、标注、采用制与降级。

### 5.2 关键状态机



* **生成任务**：`queued → running → (paused ⇄ running) → completed | failed | cancelled`；取消 / 失败清理临时结果；`idempotency_key` 防重复；连续 3 次失败 → 熔断 10 分钟。

* **演出**：`draft → parsing → ready → running → completed | degraded | failed`；`degraded` 仍写纪念册并标降级；`failed` 不写 “成功演出”；中断可从最近场景续播。

* **好友 / 岛门**：请求 `pending → accepted | refused | expired`；岛门 `closed → granted(once/long/whitelist) → revoked | expired`；撤销 3 秒断开；拉黑覆盖一切。

* **宇宙**：`draft → active → archived → deleted`；`draft` 转 `active` 的条件＝世界观卡四项基准齐（不要求有 OC）；`archived` 只读；`deleted` 按 R008 软删 30 天。

* **删除**：`active → archived → soft_deleted(purge_at) → purged`；永久删除需名称确认；有引用未处理则拒绝。

* **客串**：`invited → active → returning → ended | cancelled`；到期 / 手动 / 宿主撤销均返回；共同记忆摘要最多 1 条。

### 5.3 全局不变量



1. 任何实体必须有 `universe_id`（账号 / 系统级对象除外），跨宇宙访问默认只读。

2. 任何生成 / 行为必须携带 `world_card_version` 与 `constraint_pack.hash`。

3. 任何关系变化必须有 `relation_event`；任何演出必须有 `performance_record`；任何公开内容必须有 `visibility_setting`。

4. 边界、记忆、草稿、密钥永不出现在公开 / 分享快照中。

5. 删除是软删优先；引用未处理不得永久删除。

## 6. 全局规则

### 6.1 可见性四档矩阵

### 6.3 OOC 四层约束与越界判定



| 层          | 内容                      | 来源         | 优先级 | 可否放宽                   |
| ---------- | ----------------------- | ---------- | --- | ---------------------- |
| L1 角色硬约束   | `never_do`、雷区、知识边界      | OC 卡（用户裁决） | 最高  | 永不                     |
| L2 创造者边界   | `soft_limits`、关系称呼、表达尺度 | OC 卡 / 玩家  | 高   | 仅 R043 单场 / 单节点，且只放宽软层 |
| L3 世界规则    | 世界观卡、语言腔调、时代、色板、官方安全规则  | 宇宙 / 系统    | 中   | 玩家可加严，不可删安全规则          |
| L4 场景 / 关系 | 在场、地点、情绪、关系状态、可见性       | 当前场景       | 低   | 按场景变化，不得反向覆盖 L1–L3     |

**越界判定**：

> 说明：四层不是 “四选一”。硬层（L1 角色硬约束、L3 中的世界硬规则 / 安全规则）之间冲突一律取更严，世界观卡是宇宙宪法，不得被角色或场景放宽；L2/L4 只能加严，不能反向覆盖。表中优先级仅用于同一层内或无法比较时的裁决顺序。



| 级别  | 定义                               | 检测        | 处置                       |
| --- | -------------------------------- | --------- | ------------------------ |
| 硬越界 | 命中 `never_do`/ 雷区 / 安全规则 / 知识边界  | 规则 + 模型双检 | 直接拦截，0 落库；必要时角色内拒绝；写守护日志 |
| 软偏离 | 语气、关系称呼、尺度偏离 `soft_limits`/ 世界规则 | 规则 + 模型   | 改写重检，最多 2 次；仍失败用安全模板     |
| 漂移  | 长文中角色 / 关系 / 设定逐渐不一致             | 分段一致性检查   | 标记问题段落，重写 1 次，仍偏标记不静默通过  |

**裁决顺序**：L1 > L2 > L3 > L4；硬层取并集（任一禁止即禁止），软层取交集（双方都允许才允许）；跨宇宙客串时再叠加宿主主权（宿主卡 > 宿主硬禁忌 > 双方软交集 > 客人设定 > 客人原宇宙惯例）。**0 泄漏是验收底线**。

## 7. 异常与降级

**原则**：任何失败必须有可见反馈（禁止静默失败）；优先保数据，其次保流程，最后保体验；降级不得伪造成功，不得越过 OOC 与可见性边界。



| 场景           | 触发            | 用户可见                     | 系统处理与降级                               |
| ------------ | ------------- | ------------------------ | ------------------------------------- |
| 启动崩溃 / 白屏    | 资源损坏、版本不匹配    | 错误页 + “安全模式 / 重试 / 导出诊断” | 安全模式禁用动画与插件；保留最近存档；诊断包脱敏、无密钥          |
| 存档写入失败       | 磁盘满、权限、文件锁    | “保存失败，已保留内存副本”           | 重试 3 次；转临时文件；提示清理；退出前再次确认             |
| 云同步冲突        | 两端并发编辑        | 冲突列表                     | 纪念册 / 演出人工选；其余按版本号 + 时间；本地副本保留；不静默覆盖  |
| 存档损坏         | 断电、坏块         | “已恢复到最近快照”               | 校验 hash；回滚最近 20 快照；仍失败进入只读导出模式        |
| API 未配置      | 首次使用          | “未接入模型，将使用模板”            | 走模板 / 规则；生成入口不阻塞；可稍后配置                |

## 8. 非功能要求

### 8.1 性能



| 项   | 要求                                                                         |
| --- | -------------------------------------------------------------------------- |
| 启动  | 冷启动 ≤5 秒进入首屏；桌宠 ≤5 秒出现                                                     |
| 沙盘  | 中档设备 8 OC ≥30fps；低档 4 OC ≥30fps；单帧逻辑 ≤16ms                                 |
| 编辑器 | 40×40 全量重绘 ≤8ms；拖拽 ≥60fps；框选命中 ≤16ms；单格归属查询 ≤1ms；100 部件 ≥30fps；单作品内存 <20MB |
| 演出  | 1080p/30fps；单场 ≤3 分钟；变速 0.5–2x 不掉帧；离线可回放                                   |
| 生成  | 首字 / 首段可感知 ≤5 秒（受服务商影响）；长文分段可续；超时按 R077                                    |
| 存档  | 自动存档不阻塞交互；快照恢复 ≤3 秒；云同步增量                                                  |

### 8.2 离线与弱网



* 无网可完成建卡、建岛、拼豆、模板生成、已生成剧本的演绎与回放；离线推演 ≤72 小时；超过按 “沉睡” 补关键事件。

* 所有写操作本地先行；联网后增量同步；冲突按 R006；离线不调用外部模型；缓存按宇宙隔离。

* 弱网下生成可取消 / 重试；不重复落库；不伪造 “已发送”。

### 8.3 隐私与数据



* 默认私密；最小采集；不采集与功能无关的个人信息；匿名可玩。

* 密钥仅本地加密；日志 / 导出 / 分享 / 诊断包全链路脱敏；云端只见 “配置存在” 标记。

* 删除分级；注销清除云端 + 本地密钥；软删 30 天；备份中的删除在周期内生效（周期需核实）。

* 可见性逐条授权；撤销即时；审计留痕；不向第三方出售 / 共享用户内容（除法律要求，需法务确认）。

### 8.4 内容安全



* 输入 / 输出双过滤；覆盖违法、色情、暴力、未成年不适、仇恨、自伤；策略不可关闭；涉及未成年更严并转人工。

* OOC 四层约束 + 前后置校验；0 泄漏；拦截不复述原文；守护日志默认私密。

* 公开内容先审后发；举报 — 处置 — 申诉闭环；版权 / 署名 / 改编标注；侵权投诉渠道（细则需核实）。

### 8.5 可靠性与兼容



* 关键路径（存档 / 授权 / 举报 / 删除）联网优先、可重试、可恢复；非关键路径可降级。

* 平台范围待 Q05 确认；当前按 Windows 桌面 + Web 管理页评估；桌宠仅桌面。

* 分辨率 1280×720 起；高 DPI 适配；键盘可达；减少动效模式；色弱可辨（标记纹理 + 文字）。

* 版本升级兼容旧存档；迁移前备份；不可逆迁移需确认；旧版本至少可导出。

### 8.6 可维护与可观测



* 所有生成 / 行为带 `constraint_pack.hash` 与 `world_card_version`，可复现；trace 保留 7 天。

* 关键指标：生成成功率、降级率、越界拦截数、存档恢复率、演出完成率、举报处置时长。

* 日志分级与脱敏；不记录密钥、边界原文、私密记忆原文；诊断包需用户确认后导出。

> 生文与演绎（R037–R046、R074–R086）整体后置，不在本期范围；但数据模型给它们留好接口（§11.2 / 附录 C）。

>

>

### 12.0 一句话

玩家拿到的不是编辑器＋文本框，而是一个**能住人的像素世界**：角色卡是身份证，衣柜是换装层，地图是舞台，事件池是内容发动机。

三条硬决策（本期的技术边界，改动前须重新评估产能）：



| 决策 | 取值                          | 为什么                               |
| -- | --------------------------- | --------------------------------- |
| 视角 | 斜俯视瓦片；角色**单朝向**，左右移动用镜像翻转   | 玩家只画一张立绘；四方向会把作画成本 ×4，且拼豆立绘没有自然背面 |
| 地图 | 地图＝瓦片级「大拼豆矩阵」，复用同一编辑器       | 一套编辑器通吃角色 / 物件 / 地图，零美术资产         |
| 穿戴 | 服装＝**稀疏 part 矩阵**，只覆盖身体外层部件 | 换装永不碰脸与头发，`never_do` 意义上的「形象不被破坏」 |

### 12.1 世界地图（X01 地图规格与渲染）



* 空间：瓦片 16×16 设备像素；默认地图 20×15 瓦片（＝320×240 逻辑分辨率）；可选 8×6 – 64×48。

* 渲染：逻辑分辨率整数倍放大（2x/3x/4x），`imageSmoothingEnabled=false`；UI 与地图同一缩放栅格，禁止 1.5x 等非整数倍。

* 角色站位：立绘 29×29 按 **1 豆＝1 设备像素** 渲染（≈1.8 瓦片），占格取 2×2 瓦片，脚点底边中点为锚；碰撞盒只取脚下 1×1；**深度排序按脚点 y**，同 y 按 x，遮挡关系正确。

* 碰撞：瓦片属性表＝可走 / 不可走 / 可交互 / 可放置；角色碰撞盒只取脚下 1×1；寻路用 A\*（BFS 兜底），不可达就近取点。

* 性能：单图 ≤64×48 瓦片时整图预渲染到离屏画布，逐帧只绘制动态层与角色；目标 30fps（中档设备）。

* 验收：1280×720 下 4x 缩放无模糊（立绘 116px 高）；角色绕树走不会穿模；同屏 8 个 OC 不掉到 30fps 以下。

### 12.2 预设地图与编辑（X02 地图预设与轻编辑）



* 预设 3 张：**草地庭院 / 小镇街道 / 雪原**（各含出生点、可行走区、2–4 个可交互点、1 个「门」格）；预设只读模板，进入世界时复制一份。

* 轻编辑（本期只做这四件）：① 单格 / 矩形替换瓦片；② 摆放与移动物件；③ 改地图尺寸（钳制 8×6–64×48，越界内容二次确认裁剪）；④ 设出生点与门格。

* 不做：自由地形绘制、多层地形、地表贴花叠加、地形自动过渡（autotile）。缺角用「素色瓦片 + 手绘边界」解决。

* 数据：`map{id, world_id, size, tiles[][]（tile_id）, tile_attr{}, objects[], spawn, gates[], version}`；`tileset{id, name, tiles[], source(preset/diy)}`。

* 验收：换瓦片后碰撞同步更新；改尺寸不丢已摆物件（越界物件进「待安置」列表）；地图导出再导入一致。

### 12.3 角色卡（X03 卡面、信息与放入世界）



* 新建：像素大手从屏幕顶部扔下一张**空白 ID 卡**，落定悬浮居中；动画 ≤1.0s，可点击 / 空格跳到终态；同一场景只允许一张卡。

* 卡面：360×520；**照片热区**（左）与**信息热区**（右）各为独立按钮，最小 44px；两热区键盘可达。

* 卡正面简版：姓名 / 性别 / 生日；点信息热区进**详情页**（性格、简介、标签、关系、今日状态、最近 3 件事）。

* 信息字段：姓名 1–12 字必填；性别＝男 / 女 / 未知 / 其他（四选一，默认未知）；生日＝月 / 日（年份可空）；简介 0–200；标签 0–6。

* 完成条件：有形象矩阵 + 有姓名。完成前卡面盖「草稿」角标，不可放入世界。

* 放入世界：完成卡后点「放入世界」，卡片以「贴到入口格」的 0.5s 动画落到目标世界；世界选择器只列当前可进入的世界。

* 生日联动：生日当天由事件池自动产出一条生日事件（见 X07），不依赖模型。

* 数据：`oc_card{oc_id, cover{matrix_id, crop_rect, ratio}, name, gender, birthday, intro, tags[], status(draft/ready)}`。

* 验收：从触发到可点 ≤1.2s；姓名 / 性别 / 生日 30 秒内填完；未完成卡不能进世界；放入后世界入口格可见该 OC。

### 12.4 衣柜与穿戴（X04 槽位、换装与手持物）



* 槽位 7 个：`head` 头饰 / `body` 上衣 / `legs` 下装 / `feet` 鞋 / `outer` 外套 / `acc` 饰品 / `hand` 手持物。

* 服装＝**稀疏 part 矩阵**：只写 `top / pants / coat / shoes / acc` 这几个部件的格子，其余格为空；穿上＝用服装矩阵替换该部件的格子，**永不写入 head/hair/eyes/mouth 的格子**（写入即拒绝并提示「服装越界」）。

* 手持物＝独立小矩阵（8×8 / 8×15 / 15×15），绑 `hand` 锚点；随手臂动作位移与翻转，**不修改角色矩阵**，脱下即完全还原。

* 换装即时预览；同槽位只能穿 1 件；换装动画＝0.2s 部件闪烁 1 次（不做逐格动画）。

* 数据：`wardrobe{oc_id, entries[{slot, matrix_id, name, source(diy/preset)}]}`；`outfit{oc_id, slot_map{head:matrix_id, ...}}`；服装可导出为图纸复用，可作 `item` 进世界。

* 验收：换上衣不影响发型与五官；脱外套后矩阵逐格还原；手持物随挥手动作跟手；同槽位换 2 件只留最新。

### 12.5 世界结构（X05 归属唯一与跨世界链接）



* 世界＝原 `universe`（1:1 岛），本期改称「世界」；世界有 `map_id`、入口格、主题色板、出生点。

* **一个 OC 只能属于一个世界**（`oc.world_id` 唯一，硬约束）；改变归属必须走「迁移」（二次确认 + 关系 / 记忆随迁）。

* 世界间**链接**不是传送：A 世界的「门」格可指向 B 世界，点击跳转只切视图；角色不能常驻他界，串门临时 ≤1 游戏日，到期自动回原世界并写一条「串门记录」。

* 世界数量：已建不限，同时 active ≤3（沿用 R004/R052 的容量口径，本期不再设等级门控，见 X12）。

* 数据：`world{id, name, map_id, palette, spawn, gates[{x,y,target_world_id}], status}`；`world_link{from_world, to_world, gate, mode(readonly)}`。

* 验收：一个 OC 不会同时出现在两个世界；点门 1 步跳转；串门到期自动返回。

### 12.6 观察与自由互动（X06 互动面、X07 日常事件池）

**X06 互动面**



* 点 OC 开底部像素面板：打招呼 / 聊天（短句）/ 送礼 / 看状态；每次互动有可见反馈并写记忆；同一 OC 每日 ≤20 次、间隔 10 秒。

* OC 之间自由互动：两个 OC 靠近（≤2 瓦片）且关系档位允许时，自动触发打招呼 / 并肩坐 / 递东西，播 2–3 秒，不打断玩家操作。

* 看状态面板：心情、今天做了什么（`behavior_trace` 摘要 3 条）、与在场 OC 的关系档位。

**X07 日常事件池（0 LLM，本期最重要的内容发动机）**



* 供给源四类：天气与时段 × 物件状态 × 关系档位 × 角色偏好 / 生日。

* 每日产出 2–4 件小事，写同一个 `event` 结构，同时喂给 `perception.weather` 与 `perception.recent_events[]`。

* 事件只用模板 + 规则拼装，不调用模型；特殊日（生日、关系加深、季节首日）走专门模板。

* 约束：事件必须过 OOC 四层过滤（沿用 R027/R082）；不得伤害 OC；不得凭空改变关系（关系变化必须有 `relation_event`）。

* 数据：`event{id, world_id, type(weather/item/relation/season/birthday), actors[], place, result, template_id, ts}`；`event_pool{world_id, recent[], cooldown{}}`。

* 验收：连续 7 天每天有 2–4 件事件且无重复模板；断网仍有事件；事件全程产生 0 次模型调用。

### 12.7 UI 像素规范（X08 全站像素风）



* 边框：9-slice，边 8px，拉伸只拉伸中段；面板＝1 底色 + 1 深描边，无渐变、无投影、无模糊。

* 字体：像素字体（Fusion Pixel 12px 等，SIL OFL，授权待核实 §Q24）；字号只用 12 / 16 / 24；禁用系统字体混排。

* 图标：16×16 / 32×32 手绘，整数倍缩放，`nearest`；不使用矢量图标。

* 圆角：一律用像素阶梯圆角（4px 阶梯 2 级），不做 CSS 圆角。

* 交互反馈：按下位移 1px + 描边反色；hover 只做桌面增强，不承担信息。

* 验收：全站 0 处抗锯齿糊边；1280×720 与 1920×1080 都不出现半像素错位。

## 附录 C：符号文本格式 SYMBOL-MATRIX v1（拼豆成灵的接口）

### C.1 设计目标

纯文本、低 token、可复算、可 diff、模型可读。矩阵是唯一真值，文本只是它的无损序列化。

### C.2 格式



```
SYMBOL-MATRIX v1

\#OC 姐姐

\#SIZE 29x29

\#PALETTE MARD38 v1

\#PART-SET hair,head,eyes,mouth,upper,lower,top,pants,coat,shoes,acc

\#COLOR

H5,H5,H5,H5,H5,H5,H5,H4,H4,H4,H4,H4,H4,H4,H4,H4,H4,H4,H4,H4,H4,H4,H5,H5,H5,H5,H5,H5,H5

...(共 29 行，每行 29 个色号)

\#PART

none,none,hair,hair,hair,hair,hair,hair,head,head,...

...(共 29 行，与 COLOR 逐格对齐)

\#END
```



* `COLOR` 段：29 行 × 29 个 MARD 色号，逗号分隔，行内无空格。

* `PART` 段：同尺寸，取 `#PART-SET` 中的 id 或 `none`；`none` = 未标部件（不可动）。

* `B2` 保留为「空白格」哨兵：数据里存 `B2`，渲染为白，`PART` 记为 `none`。

### C.3 行游程压缩（可选，长图必用）

连续同值合并为 `值×n`：



```
H5×7,H4×15,H5×7
```

841 格的双矩阵从约 1.7k token 压到约 600 token，便于直接塞进上下文。

### C.4 给模型的最小指令头（可直接粘贴）



```
你收到一个 29×29 拼豆角色矩阵。COLOR 段是每格的 MARD 色号，PART 段是该格所属部件。

可用部件与可表达动作：hair（转头/摆动）、eyes（睁闭）、mouth（口型）、head（点头/摇头）、

upper（前倾后仰）、lower（走路/站定）、shoes（迈步）、coat（飘动）。

请输出 3 场、每场不超过 6 拍的动作剧本，每拍格式：拍号 | 部件 | 动作 | 时长ms。

不要描述外观，不要新增部件，不要使用矩阵里不存在的部位。
```

### C.5 闭环

模型返回的动作序列 → 解析成 beat → 用同一张矩阵渲染：**演出来的始终是玩家画的那个 OC**，不会因为模型自由发挥而变脸。反向链路（文本 → 矩阵）由 R037/R038 承担，共同构成「文本 ⇄ 像素」的双向管线。本期不做这两条，接口先留着。
