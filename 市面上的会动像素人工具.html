有，但都是隔壁那三类，没有完全对口的
现有的东西各缺一块：要么部件不是你画的，要么系统不认识你画的部件，要么全靠你自己做。你这个「自绘部件 + 系统识型 + 套官方动效」正好在三者的缝里。
第一类：组合式捏人（部件是素材库）
最接近的是这个，也是唯一把「部件 + 官方动效」真正跑通的公开实现。
Universal LPC Spritesheet Character Generator 开源 · 仍活跃
选性别、体型、头发、衣服、护甲、武器，右边直接预览「走路」动画，导出成 spritesheet。部件分类是 body / head（含耳鼻眼胡须头发）/ torso / legs / feet / weapon / shield，每个部件都自带多方向、多动作的帧。
美术全部开源（GPL3 + CC-BY-SA3），TypeScript + WebGL 实现，换色走 GPU 调色板。
缺的那块：部件是作者画的，你只能选。想画一个自己的发型？不行。
UnitForge · RPG Maker 内置 Generator · Picrew
同一路线。UnitForge 是 8 职业 + 可换装 + 预制多动画；RPG Maker 的是有限组合；Picrew 是海量日系捏人但绝大多数是静态图。
共同的缺：都是「选」，不是「画」。
第二类：上传图自动分解（最像，但黑箱）
DotEMotion 2026.11 仍在更新
浏览器里跑。把一张角色图扔进去，自动分解成部件，再自动加上走、跑、攻击的动画，出高质量 spritesheet。
这正是你想做的事的自动化版本：图进去 → 部件出来 → 动画出来。
它的命门：靠算法猜「哪块是手臂」。图大一点、对比清楚一点猜得准；29×29 这种尺寸猜不动——腿和裤子在这尺寸上根本分不开。而且猜错了玩家没法纠正，因为系统不告诉他"我认成了什么"。
Miso Editor · PixelLab · Ludo · SpriteLab
Miso 是 3D 模型一键出 1–64 方向 spritesheet；PixelLab/Ludo/SpriteLab 是 AI 文生 sprite + 自动动画，还能出 4/8 方向。
这些是「AI 帮你按」的路线，跟你「玩家像素手绘」的主张正面冲突——生成出来不是玩家画的那只手。
第三类：通用像素编辑器（什么都能做，全靠人）
Aseprite · Piskel · Pixelorama · LibreSprite
Aseprite 是这行的标准工具（买断约 20 美元），图层 + 帧时间轴 + 洋葱皮 + tag 分组帧；Piskel 免费网页；Pixelorama 开源。
值得注意：Aseprite 圈子里已经有一套成熟的「模块化角色」做法——每个动画打一个 tag，每个要开关的部件占一个 layer。有人把它写成了教程，讲得很直白：动画＝tag，模块＝layer，两个维度交叉。
缺的那块：它不知道「这个 layer 是眼睛」。你自己知道，软件不知道。所以眨不了眼——眨眼得你自己画两张图再打 tag。

第四行是分水岭。自动分解那一类不做纠正机制——它猜错了就错了，玩家只能重传一张图再猜。
而你这套把「声明部件类型」变成建层时的一步选择，玩家说什么就是什么。这不是退步到人工，是把不确定性从算法手里拿回来。
三处该抄的，三处别抄的
该抄
LPC 的部件树 —— body / head / torso / legs / feet / weapon 这套分法跟你的 17 个几乎一一对应。拿它当校验表，看有没有漏掉该有的。
Aseprite 的 tag + layer —— 动画＝tag、模块＝layer，这套已被验证十几年。你的「动效绑层」就是它，只是内置进产品。
LPC 的 spritesheet 布局 —— 每动作固定行列，引擎切片不会乱。你的帧管理可以照这个规矩定。
别抄
LPC 的美术素材 —— GPL3 / CC-BY-SA3 双协议，且是 32×32 侧视角写实向，跟你 29×29 正俯视拼豆风完全不搭。抄规范，不抄图。
自动分解 —— DotEMotion 那套在 29×29 上会崩。像素太少，腿和裤子分不开。
AI 代笔 —— PixelLab 那类出的是「AI 画的人」，不是玩家画的人。你的核心是玩家那只手。
一句话结论
有类似的东西，但都只做对了三分之二。
你这套的独特之处不在技术，在「谁来决定这块像素是什么」。 LPC 是作者定，DotEMotion 是算法定，Aseprite 是人自己心里定但软件不知道——只有你把这一步显式地放进建层流程里。
这也解释了为什么「建层必须选部件」不是麻烦，是这套东西的地基。
