能画，但要分清「画得出来」和「动得对」
17 部件本质是一副人形骨架：一个头、一个躯干、左右各一臂、左右各一腿。凡是在这副骨架上长出来的东西……都能画。超出骨架的，画得出来但动效会不对。
能画，而且很顺
这些都是「人形骨架 + 换皮」，17 部件一个都不用改。
兽耳娘 / 兽人
兽耳与尾巴走 acc，尾巴层序拖到底。尾巴摇用 3 帧，耳朵抖摆跟头。
精灵 / 恶魔 / 天使
翅膀进 acc 拖到底，扇动用 4 帧。尖耳就是 head 里画尖。
幽灵 / 鬼
腿层可以不建——腿不是必填。acc 加「漂浮」动效，用上下 1–2 格。
人形机器人 / 机械体
关节怎么画是玩家的事。只要按人形分部件，动效照样套。
毛茸茸 / 鳞片 / 多色皮肤
都是「皮肤色」问题，head/torso 换色即可，不涉及部件结构。
独眼 / 三只眼 / 竖瞳
眼睛层上限 4 层——画 3 只眼就是 3 个眼睛层，每层都能绑眨眼。
四只手臂（蜘蛛人 / 六臂像）
arm_l × 2 + arm_r × 2，每层可以绑不同动效。但见下面「动得对」那段。
两个意外的红利
多眼白送。 同部件上限 4 层这条规则，本来是为了「头发分前后」设计的，结果让「三只眼」「四只眼」直接成立——每层独立绑眨眼，可以只眨中间那只。
多肢也白送。 同理，arm_l 两层、arm_r 两层就是四臂。而且动效按层绑，可以让第一对手臂挥手、第二对垂着——这比「多臂」这个词能想到的还灵活。
能画，但动起来会不对
这些也得说清楚，不然玩家做出来发现走路像鸭子，会以为是 bug。
四足兽（猫狗马）
能建：leg_l × 2（标成前腿左、后腿左）+ leg_r × 2。但走路动效是「左右交替」，四足是「对角步」——套上去是顺拐。要真做得对，得另做一套四足步态。
史莱姆 / 软体 / 团子
能用 torso 画一坨，但没有四肢，所有肢体动作全失效。只能呼吸 + 表情。挤压弹动要单独做。
虫 / 蜈蚣 / 多足
腿最多 4 层，蜈蚣要几十条。层数不够，而且多足波动是「波浪式」不是交替。
悬浮体 / 飞行器 / 抽象造物
没有骨架可对。能用 acc 堆形状，但一切动效都无从绑定。
不要做的事：禁止
「只允许人形」会直接违背你「不定死人物模板」的主张。
正确做法是允许建，但告诉他代价——非人形建完后，预览台里走路时给一行提示：「这套步态是按人形做的，你画的腿数不是四条，可能不对」。
能建但动不对，比不让建更好。玩家自己会判断值不值得。
架构上留个口子，几乎零成本
现在不做兽形，但要让它以后能加，不要现在把架构固定死。
角色对象里加一个字段
{ "id": "OC-01", "skeleton": "humanoid", ... }
// 现在只取 humanoid，将来可加 quadruped / blob / insect
部件表按 skeleton 分组：humanoid 组 = 现在的 17 个，以后 quadruped 组另开 15 个左右。
现在加这个字段是 0 成本——就一个字符串。等真要做兽形再补，就得回头改所有存盘文件。

一句话
兽耳娘、四臂、三只眼、幽灵——现在就能画，而且动得对。
四足兽、史莱姆、蜈蚣——能建出来，但人形动效套上去会顺拐。允许建、给提示，别禁止。
兽形骨架留着，加个 skeleton 字段，等首版真跑起来再说。
