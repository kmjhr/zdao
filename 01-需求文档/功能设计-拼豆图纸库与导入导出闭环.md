# 功能设计：拼豆图纸库与导入 / 导出闭环

> 依据文档：《纸上岛》产品设计书 v0.1（2026-11-04）
> 设计对象：拼豆图纸的持久化、复用与跨工具流转
> 目标阶段：MVP M1（拼豆编辑器 → 文导入角色提取 → 图纸）
> 状态：设计稿，待评审
> 范围：图纸文档格式、图纸库、导入、导出、旧产物兼容；不改动沙盘、演出、桌宠

---

## 0. 为什么判断是这一个功能

1. 产品书 5.2 / 5.5 / 8.1 明确要求：图纸 32×32 起步、48×48 进阶，可手动调整，AI 可批量生成新图纸，图纸是 OC 的正式形象。当前产物只有一个"能画、能导出、不能打开"的编辑器。
2. 现有产物存在唯一一个端到端断开的闭环：
   - [拼豆板编辑器原型.html](file:///d:/codex/codex-data/youxi/拼豆板编辑器原型.html) v0.7 的「导出图纸 JSON」只把文本写进 textarea，全文件没有导入入口；
   - `bead_oc29_jiejie.json` 与 `bead_oc32_jiejie.json` 使用两套不同的字段与部件词表（`B2` / `b` 空色号、`eyes+mouth` / `face` 合并五官）；
   - 「载入姐姐」是硬编码 `PRESET`，Python 生成的新图纸无法回到编辑器继续改。
3. 其他候选项不是"未闭环"，而是"未开始"：演出引擎、剧本循环尚无任何原型产物，且依赖图纸资产先成立；细节图（放大镜）回显只是编辑器内部的小缺口，不足以单独构成一个完整功能。
4. 因此本次唯一明确目标：**让每张图纸成为可保存、可再次打开、可导出备份、可被后续引擎读取的图纸文档。**

---

## 1. 功能目标与用户价值

### 1.1 功能目标

- 每张图纸是一个可命名的「图纸文档」，保存在本地图纸库，刷新或关闭后仍能继续编辑。
- 三种来源都能进入同一编辑器：编辑器手绘、Python / AI 生成的图纸、旧版编辑器导出的图纸。
- 导出格式稳定、带版本号、可校验，可被沙盘、演出、桌宠、外部脚本读取。
- 导入失败必须可定位、可解释，绝不静默丢数据。
- 修改未保存、存储配额不足、多标签页冲突等场景都有明确反馈与出口。

### 1.2 用户价值（对齐产品三条支柱）

| 支柱 | 本功能的落点 |
|---|---|
| 私人化 / 唯一性 | OC 形象是玩家资产，可保存、备份、带走，不是一次性画布 |
| 积累回报 | 图纸库是 OC 图鉴、豆色收集、宇宙资产的第一层载体 |
| AI 原生内容生长器 | AI 批量生成的图纸走同一格式进入编辑器，玩家手改后成为正式形象 |
| 确定性渲染 | 同一份矩阵在编辑器、沙盘、演出、桌宠中渲染结果一致 |

### 1.3 不做什么（本功能边界）

- 不做 PNG / 截图自动识别成图纸：V1 只认 JSON，像素识别交给 P2 评估。
- 不做「把导入图纸合并进当前图层」：V1 导入永远生成新文档，避免色号与部件冲突。
- 不做云同步、图纸市场、多人协作：属于 P2。
- 不做演出引擎、沙盘、桌宠渲染；只保证它们能读取同一份图纸文档。
- 不改变产品定位与术语：仍使用「宇宙 / OC / 图纸 / 豆色 / 色号 / 部件 / 细节图 / 锚点」。

## 2. 术语与对象

| 术语 | 定义 |
|---|---|
| 图纸文档 | 一张 OC 形象或道具的完整数据：画布尺寸、色板、图层、部件矩阵、细节图 |
| 图纸库 | 本地保存的所有图纸文档集合，带缩略图、名称、规格、更新时间 |
| 旧版平铺图纸 | `bead_oc29_jiejie.json` / `bead_oc32_jiejie.json` 这类 `color + part` 双矩阵格式，无图层 |
| 旧版编辑器导出 | v0.7 导出的 `name/cols/rows/palette/layers/details`，无格式标识、无版本号 |
| 空色号 | `empty_code`，表示该格没有豆子（透明）；不再硬编码为 `B2` |
| 部件 | `part`，每颗豆子的语义标签，用于换装、眨眼、说话、动画 |
| 细节图 | 放大镜画布中的高分辨率部件图，通过 `anchor` 挂回小人 |
| 标准档 | 产品书定义 32×32 标准、48×48 进阶；其余尺寸记为自定义 |

## 3. 用户操作流程

### 3.1 首次进入

1. 打开编辑器，自动创建一张 **32×32 空白图纸**（未命名、未保存）。
2. 右侧「我的图纸」面板显示空态：`还没有保存的图纸。新建一张 32×32，或导入 .json 图纸。`
3. 顶部标题显示 `未命名图纸 · 32×32 · 未保存`。
4. 用户开始拼豆；首次保存后，图纸出现在图纸库列表中。

### 3.2 新建图纸

1. 点击「＋ 新建」。
2. 弹出尺寸选择：`32×32（标准）`、`48×48（进阶）`、`自定义 15 / 21 / 29 / N`。
3. 选择后创建空白文档，默认一个图层，色板沿用当前宇宙色板（V1 先使用现有 17 色「青春疼痛」色板）。
4. 若当前文档有未保存修改，先走「保存并新建 / 放弃修改 / 取消」。

### 3.3 绘制与自动保存

1. 绘制、部件标注、图层操作、细节图保存、改名，都会把文档标记为「未保存」。
2. 停止操作 600ms 后自动写入图纸库；顶部未保存圆点变灰。
3. 自动保存失败（配额 / 浏览器禁用存储）时，顶部显示红色「保存失败」，并给出「导出备份」按钮。
4. 用户也可随时 `Ctrl+S` 立即保存。

### 3.4 导入图纸

1. 点击「⤓ 导入图纸」，或把 `.json` 文件拖到画布区域。
2. 拖入时显示覆盖层：`松开导入图纸（.json）`；拖离或 `Esc` 取消。
3. 解析文件 → 显示导入预览卡片：
   - 名称、尺寸、标准档 / 自定义、色号数、豆子数、图层数、细节图数；
   - 识别到的格式：`纸上岛图纸 v1` / `旧版编辑器导出` / `旧版平铺图纸`；
   - 警告列表（如合并五官、色号自动补登、图层全隐藏）。
4. 点击「导入」后才写入图纸库；点击「取消」不产生任何写入。
5. 若文档 id 已存在，弹出冲突选择：`覆盖原图纸 / 另存为副本 / 取消`，默认「另存为副本」。
6. 导入成功后成为当前文档，画布、图层面板、细节列表、色板整体刷新。
7. 导入失败时保留当前画布不变，错误弹窗列出前 5 条错误与定位，可展开查看全部。

### 3.5 切换、重命名、复制、删除

1. 图纸库列表点击某张图纸 → 切换当前文档。
2. 当前文档有未保存修改时，提示 `保存并切换 / 放弃修改 / 取消`。
3. 标题旁铅笔图标可重命名：1–20 字，允许重名，以 id 区分。
4. 列表项「⋯」菜单：`重命名 / 复制副本 / 导出 / 删除`。
5. 删除需二次确认：`删除《名称》？该操作不可撤销，建议先导出备份。`
6. 删除当前文档后，自动打开列表中最近的图纸；若库为空，则新建空白 32×32。

### 3.6 导出

1. 点击「⤒ 导出」，或 `Ctrl+Shift+E`。
2. 导出当前文档为 UTF-8、两空格缩进的 `.json`。
3. 文件名：`<安全名称>_<cols>x<rows>_<yyyyMMdd-HHmm>.json`，非法字符替换为 `_`。
4. 导出成功后 toast：`已导出《姐姐》 32×32（15 色号 · 2 图层）`。
5. 导出内容永远是规范格式，不携带编辑器临时状态（当前图层、缩放、未保存标记）。

### 3.7 刷新 / 关闭

1. `pagehide` 与页面隐藏时强制落盘一次。
2. 若仍未保存成功，`beforeunload` 弹出浏览器原生离开确认。
3. 重新打开时恢复上次打开的图纸（`activeId`）；找不到则打开最近更新的一张。

### 3.8 主流程

```
新建 32×32 → 拼豆 / 标部件 → 自动保存 → 图纸库
   → 再次打开继续改 → 导出 .json（备份 / 分享）
   → 导入 .json（自己的、朋友的、Python/AI 生成的）
   → 编辑器继续手改 → 进入沙盘 / 戏台 / 桌宠
```

### 4.2 图纸库面板

- **列表项**：缩略图（64×64，由合成图按 1–2px/格实时绘制）、名称、规格徽章（`32` / `48` / `旧版 29×29` / `自定义`）、图层与色号数、更新时间。
- **当前项**：蓝色边框 + 左侧竖条，点击切换。
- **空态**：`还没有保存的图纸。新建一张 32×32，或导入 .json 图纸。`
- **未保存当前文档**：列表顶部显示一条 `当前图纸尚未保存` 提示与「保存」按钮。
- **损坏文档**：列表项显示 `⚠ 无法读取`，点击只提示错误，不覆盖其他文档。
- **排序**：按 `updated_at` 倒序；无搜索，V1 控制在 50 张以内。

### 4.3 导入预览卡片

```
┌ 导入图纸 ────────────────────────────────┐
│ 文件名：bead_oc32_jiejie.json            │
│ 识别格式：旧版平铺图纸（color + part）    │
│ 名称：姐姐        尺寸：32×32（标准）     │
│ 色号：15          豆子：xxx               │
│ 图层：1           细节图：0               │
│ ⚠ 该图纸的「face」为合并五官，导入后      │
│   不能直接驱动眨眼 / 说话；可在部件标注   │
│   模式手动拆分。                          │
│                    [取消]  [导入]         │
└──────────────────────────────────────────┘
```

- 警告不阻塞导入；硬错误才阻塞。
- 同名文件重复拖入，仍走正常预览，不自动覆盖。

### 4.4 冲突与未保存

| 场景 | 弹窗选项 | 默认 |
|---|---|---|
| 导入 id 已存在 | 覆盖原图纸 / 另存为副本 / 取消 | 另存为副本 |
| 切换文档有未保存修改 | 保存并切换 / 放弃修改 / 取消 | 保存并切换 |
| 新建 / 修改画布尺寸有未保存修改 | 保存并新建 / 放弃修改 / 取消 | 保存并新建 |
| 删除图纸 | 删除 / 取消 | 取消 |

### 4.5 交互反馈

- **成功**：绿色 toast，2 秒自动消失。
- **信息**：灰色 toast，2 秒。
- **警告**：琥珀色 toast，5 秒；导入警告固定在预览卡片中，必须看到后再确认。
- **错误**：红色，停留到用户关闭；提供「查看详情 / 复制错误信息 / 导出当前图纸」。
- **状态行**：主面板 `modeStat` 显示当前色号、缺失色号、未标注豆子数、保存状态。
- **禁止静默失败**：任何存储、解析、下载失败都必须出现可见提示。

### 4.6 快捷键

| 快捷键 | 行为 | 说明 |
|---|---|---|
| `Ctrl+S` | 立即保存到图纸库 | 阻止浏览器默认「保存网页」 |
| `Ctrl+Shift+S` | 另存为副本 | 生成新 id，名称加「副本」 |
| `Ctrl+Shift+E` | 导出 JSON | 不拦截常用浏览器地址栏快捷键 |
| `Ctrl+Shift+O` | 打开「我的图纸」面板 | 不拦截 `Ctrl+O` 系统打开文件 |
| `Esc` | 关闭弹窗 / 取消拖入 | 有未保存修改的弹窗除外 |
| `Delete` | 删除选中图层 / 细节图 | 仅在列表项聚焦时生效，需确认 |

### 4.7 空态 / 加载态 / 异常态

| 区域 | 空态文案 | 加载态 | 异常态 |
|---|---|---|---|
| 图纸库 | 还没有保存的图纸。新建一张 32×32，或导入 .json 图纸。 | 列表骨架 3 行 | 某项显示 `⚠ 无法读取` |

## 5. 数据结构与文件格式

### 5.1 规范格式：`paperisland-bead` v1

```json
{
  "format": "paperisland-bead",
  "schema_version": 1,
  "id": "doc_7f3a2c",
  "name": "测试小人",
  "universe_id": "u_qingchun",
  "source": "manual",
  "standard": "custom",
  "cols": 3,
  "rows": 3,
  "empty_code": "X",
  "palette": {
    "X": "#F6F1E7",
    "H2": "#7B4A2F",
    "E1": "#34261C"
  },
  "layers": [
    {
      "id": "ly_1",
      "name": "图层 1",
      "visible": true,
      "color": [
        ["X", "H2", "X"],
        ["H2", "X", "X"],
        ["X", "X", "X"]
      ],
      "part": [
        ["none", "hair", "none"],
        ["hair", "none", "none"],
        ["none", "none", "none"]
      ]
    }
  ],
  "details": [],
  "created_at": "2026-11-04T08:00:00Z",
  "updated_at": "2026-11-04T08:05:00Z"
}
```

### 5.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `format` | string | 是 | 固定 `paperisland-bead` |
| `schema_version` | number | 是 | V1 = 1；大于当前版本拒绝导入并提示升级 |
| `id` | string | 是 | `doc_` + 6 位 base36；库内唯一 |
| `name` | string | 是 | 1–20 字，允许重名；空则用文件名 |
| `universe_id` | string \| null | 否 | 归属宇宙；V1 可为 null |
| `source` | enum | 是 | `manual` / `ai` / `preset` / `imported` |
| `standard` | enum | 是 | `32` / `48` / `custom`；由 `cols` 派生，不一致时以实际尺寸为准并警告 |
| `cols` / `rows` | number | 是 | 8–64，且必须相等（V1 只支持正方形） |
| `empty_code` | string | 是 | 空色号，必须在 `palette` 中；不得为 `none` |
| `palette` | object | 是 | 色号 → `#RRGGBB`；色号 1–10 位，`[A-Za-z0-9_]` |
| `layers` | array | 是 | 1–16 层；**数组顺序 = 自下而上**，最后一项为最上层 |
| `layers[].color` | string[][] | 是 | `rows × cols` 色号矩阵 |
| `layers[].part` | string[][] | 是 | `rows × cols` 部件矩阵，空为 `none` |
| `details` | array | 是 | 0–8 个放大细节图 |
| `details[].anchor` | {x,y} | 是 | 挂回小人的格坐标，必须落在 `0..size-1` |
| `created_at` / `updated_at` | string | 是 | ISO 8601 UTC；展示时转本地时区 |

> 不写入缩略图、当前缩放、当前图层等编辑器临时状态，保证文件可跨端读取。

### 5.3 规范部件词表

| part | 中文 | 渲染 / 动画用途 |
|---|---|---|
| `hair` | 头发 | 发型层、发丝摆动 |
| `head` | 头·脸 | 头部基础、肤色阴影 |
| `face` | 五官（合并） | 兼容旧图纸；不驱动眨眼 / 说话 |
| `eyes` | 眼睛 | 眨眼、视线 |
| `mouth` | 嘴巴 | 说话、表情 |
| `upper` | 上身 | 身体 |
| `lower` | 下身 | 身体 |
| `top` | 衣服 | 换装内层 |
| `pants` | 裤子 | 换装 |
| `coat` | 外套 | 换装外层 |
| `shoes` | 鞋 | 换装 |
| `acc` | 饰品 | 配件、道具挂点 |

- 未知部件标签**保留不丢弃**，导入时记为未知并警告，导出原样保留。
- `face` 是旧格式的合并五官；新绘制优先使用 `eyes` / `mouth`。

### 5.4 旧格式兼容

| 格式 | 识别条件 | 转换规则 |
|---|---|---|
| 旧版平铺图纸 | 有 `color`、`part` 二维数组，无 `layers` | `layers = [{ name:'图层 1', visible:true, color, part }]`；`details=[]` |
| 旧版编辑器导出 | 有 `layers` 数组，无 `format` | 保留图层顺序 / 可见性 / 细节图；补 `empty_code`、`id`、时间戳 |
| 规范格式 | `format === 'paperisland-bead'` | 严格校验 |

**空色号推断**（旧格式没有 `empty_code` 时，按顺序取第一个命中）：

1. `palette` 中存在 `B2` → `B2`；
2. 存在 `b` → `b`；
3. 存在 `X` → `X`；
4. 任意颜色值为 `#F6F1E7` 的色号；
5. 仍无法确定 → 硬错误，请用户选择空色号。

**旧版名称处理**：

- 旧版平铺图纸：优先用 `name`，其次文件名。
- 旧版编辑器导出：v0.7 的 `name` 恒为 `姐姐`，不可信；优先用文件名，其次 `name`。
- 规范格式：优先 `name`，空则文件名。

**自定义颜色补登**：

- 旧版 v0.7 使用自定义颜色时，矩阵里可能出现 `C0392B` 这类裸十六进制；
- 若该“色号”不在 `palette` 且匹配 6 位十六进制 → 自动补登为 `C0392B: #C0392B`，并在预览中警告「已补登 n 个自定义色号」；
- 若缺失且不是十六进制 → 硬错误，列出缺失色号与出现颗数。

### 5.5 本地存储结构

| Key | 内容 |
|---|---|
| `pi.bead.index@1` | `{ version:1, activeId, docs:[{id,name,standard,cols,rows,updatedAt,beads,layers,colors}] }` |
| `pi.bead.doc.<id>@1` | 完整规范文档 JSON |
| `pi.bead.active@1` | 最近打开的文档 id |

- 索引损坏或丢失时，扫描所有 `pi.bead.doc.*` 键重建索引。
- 单文档序列化上限 300KB；图纸库总量上限 4MB；最多 50 张。
- V1 用 `localStorage`；P1 迁移 IndexedDB，接口保持 `saveDoc / loadDoc / listDocs / deleteDoc`。
- 浏览器禁用存储或隐私模式：进入「本次会话可用，关闭后丢失」模式，顶部常驻警告。

### 5.6 文件命名与类型

- 扩展名统一 `.json`，MIME `application/json;charset=utf-8`。
- 下载使用 `Blob` + 隐藏 `<a download>`，不依赖服务端。
- 文件名安全化：`\ / : * ? " < > |` 与控制字符替换为 `_`，最长 80 字符。

## 6. 核心逻辑与算法

### 6.1 编辑器内存模型重构

当前原型以全局 `N`、`layers`、`detailList`、`PRESET` 分散管理。V1 收敛为单一 `doc`：

```js
doc = {
  id, name, schemaVersion, standard, cols, rows,
  emptyCode, palette, universeId, source,
  layers: [{ id, name, visible, color, part }],
  details: [{ id, part, size, anchor, color, part }],
  createdAt, updatedAt, dirty
}
```

- 所有 `N` 读取改为 `doc.cols`；所有 `PRESET.palette` 读取改为 `doc.palette`；所有硬编码 `'B2'` 改为 `doc.emptyCode`。
- 图层面板、色板、细节列表、尺寸标签全部由 `doc` 重新渲染。

### 6.2 导入流水线

```js
function importDoc(text, fileName) {
  // 1. 体积与编码
  if (byteLength(text) > 2 * 1024 * 1024) throw E_FILE_SIZE;

  // 2. 解析并定位语法错误
  const obj = parseJsonWithLocation(text); // 失败时给出 line / col

  // 3. 识别格式
  const kind = detectFormat(obj);
  // 'canonical' | 'legacyEditor' | 'legacyFlat' | throw E_FORMAT_UNKNOWN

  // 4. 转换 + 校验 + 归一化
  const { doc, warnings } = convertAndNormalize(obj, kind, fileName);

  // 5. 冲突处理
  if (docExists(doc.id)) return askConflict(doc); // 覆盖 / 副本 / 取消

  // 6. 提交
  saveDoc(doc);
  setActive(doc.id);
  renderAll(doc);
  showImportResult(doc, warnings);
}
```

### 6.3 校验与归一化规则

按顺序执行，任一硬错误即中止且不写入：

1. `cols` / `rows` 为整数，8–64，且 `cols === rows`，否则 `E_NON_SQUARE`。
2. 每个图层 `color` 与 `part` 的行数、列数与 `cols/rows` 完全一致，否则报具体路径，例如 `layers[1].color[4] 长度为 28，应为 29`。
3. 所有色号匹配 `^[A-Za-z0-9_]{1,10}$`。
4. 每个被使用的色号必须存在于 `palette`，或按 5.4 规则补登。
5. `palette` 的值必须是合法 `#RRGGBB`（3 位缩写自动展开）。
6. `empty_code` 必须存在且不被当作普通豆色；若缺失按 5.4 推断。
7. `layers` 数量 1–16；至少一层可见，否则自动把最底层设为可见并警告。
8. `details` 数量 0–8；`size` 8–64；`anchor` 在范围内；`part` 必须在规范词表或保留为未知。
9. `name` 去首尾空白，截断到 20 字；空则用文件名去扩展名。
10. `id` 缺失则生成；与库内重复则进入冲突流程；`created_at/updated_at` 缺失补当前时间。
11. `standard` 以实际 `cols` 为准：32 → `32`，48 → `48`，其他 → `custom`；声明不一致只警告。

**幂等性要求**：归一化后的文档导出再导入，除 `updated_at` 外必须逐字段完全一致。这是防数据漂移的核心约束。

### 6.4 图层合成规则（修正现有实现）

当前 `buildView()` 只在上层 `part !== 'none'` 时覆盖部件，导致“上层新豆子继承了下面旧豆子的部件标签”。V1 改为：

```js
for (const layer of visibleLayersBottomToTop) {
  for (each cell) {
    if (layer.color[y][x] !== emptyCode) {
      out.color = layer.color[y][x];
      out.part  = layer.part[y][x];   // 允许为 none：新豆子就是未标注
    } else if (layer.part[y][x] !== 'none') {
      out.part = layer.part[y][x];    // 仅标注层：给下层豆子补部件
    }
  }
}
```

- 颜色优先：上层有颜色即覆盖颜色与部件。
- 标注优先：上层无颜色但有部件时，只覆盖部件。
- 效果：每个最终豆子严格对应“最后一个给它上色的图层”的颜色与部件，符合“每颗豆子 = 颜色 + 部件”的产品定义。

### 6.5 自定义颜色

- 颜色选择器选中任意颜色时，不把裸十六进制写进矩阵；而是：
  1. 若 `palette` 已有同色值 → 直接使用该色号；
  2. 否则分配 `U01`、`U02`……（跳过已存在），写入 `palette`；
  3. 自动选中新色号并重绘色板。
- 色号输入框：先精确匹配，再忽略大小写唯一匹配；多义时报错「存在多个相似色号，请从色板选择」。
- 导入后重建色板，不保留上一张图纸的选中色号；若该色号不存在，回退到第一个非空色号。

### 6.6 保存与导出

- **保存**：`JSON.stringify(doc)` 写入 `pi.bead.doc.<id>@1`，同步更新索引元数据与 `updated_at`。
- **导出**：输出规范字段，不输出 `dirty`、不输出缩略图、不输出当前图层。
- **导出前检查**：若存在缺失色号、未知部件、锚点越界，先弹警告，允许「继续导出（保留问题）」或「返回修复」。
- **下载**：`Blob` + `<a download>`，完成后 toast；不打开新窗口。

### 6.7 自动保存与脏标记

- 所有写操作调用 `markDirty()`：置 `dirty=true`，600ms 防抖后 `saveDoc()`。
- 保存成功：`dirty=false`，更新标题圆点与列表时间。
- 保存失败：`dirty=true`，顶部红条 + 导出出口；不重试轰炸，最多每 10 秒重试一次。
- `pagehide` / `visibilitychange(hidden)` 立即 flush。
- 多标签页：监听 `storage` 事件；若同一 id 被其他标签页更新，提示「另一窗口已修改该图纸，当前内容未覆盖」，用户可选择「重新加载 / 另存副本」。V1 采用最后写入者不自动覆盖策略。

### 6.8 错误定位

- `JSON.parse` 失败：从其错误信息中提取字符位置，扫描原文计算行号与列号，提示 `第 3 行第 17 列附近：Unexpected token`。
- 结构校验失败：使用路径字符串定位，例如 `layers[1].part[12] 长度 27，应为 29`。
- 最多展示前 5 条，其余折叠；提供「复制错误信息」，方便用户反馈。

## 7. 异常与限制

| 代码 | 场景 | 反馈 | 处理 |
|---|---|---|---|
| `E_FILE_SIZE` | 文件 > 2MB | 红色错误 | 拒绝导入，当前文档不变 |
| `E_JSON_SYNTAX` | JSON 截断 / 语法错误 | 行列定位 | 拒绝导入 |
| `E_FORMAT_UNKNOWN` | 无 `format`、无 `layers`、无 `color` | 说明支持的三种格式 | 拒绝导入 |
| `E_NON_SQUARE` | `cols !== rows` | 显示实际尺寸 | 拒绝导入，V1 不支持矩形 |
| `E_DIMENSION` | 矩阵行列为空或不齐 | 具体路径 | 拒绝导入 |
| `E_PALETTE_MISSING` | 使用色号无颜色定义 | 列出色号与颗数 | 拒绝导入（裸十六进制除外，走补登） |
| `E_HEX_INVALID` | 色板值非法 | 显示色号与值 | 拒绝导入 |
| `E_SCHEMA_FUTURE` | `schema_version > 1` | `请升级编辑器后再打开` | 拒绝导入 |
| `E_STORAGE_QUOTA` | localStorage 满 | 红色常驻 + 导出按钮 | 内存保留，不丢当前编辑 |
| `E_STORAGE_DISABLED` | 隐私模式 / 禁用存储 | 顶部警告「关闭后丢失」 | 允许本次会话继续 |
| `W_LOSSY_FACE` | 旧图使用 `face` 合并五官 | 预览卡片警告 | 允许导入，保留 `face` |
| `W_LEGACY_NAME` | 旧编辑器导出的名称不可信 | 提示已按文件名命名 | 允许导入 |
| `W_COLOR_ADDED` | 裸十六进制补登色号 | 列出补登数量 | 允许导入 |
| `W_HIDDEN_LAYERS` | 所有图层隐藏 | 警告 | 自动显示最底层 |
| `W_UNKNOWN_PART` | 未知部件标签 | 列出标签 | 保留，提示手动复核 |
| `W_ANCHOR_OUT` | 细节图锚点越界 | 提示并清空该锚点 | 导入继续，需重新设锚点 |

**硬限制**：

- 画布 8–64 格；V1 仅正方形。
- 图层 ≤16；细节图 ≤8；色板色号 ≤64。
- 单文件 ≤2MB；图纸库 ≤50 张 / 4MB。
- 不支持自动识别 PNG、JPG、WebP 为图纸。
- 不支持矩形画布、多层合并导入、跨文档图层复制。

## 8. 验收标准

以下条目均可通过现有 JSON 与浏览器操作验证，不依赖看图：

1. **旧版 29 导入**：导入 `bead_oc29_jiejie.json` 后，文档为 29×29，`palette` 17 项，`color` 与 `part` 逐格与源文件完全一致；规格徽章显示「旧版 29×29」；无硬错误。
2. **旧版 32 导入**：导入 `bead_oc32_jiejie.json` 后，文档为 32×32（标准档），`palette` 15 项，所有非空格与部件标签逐格一致；`face` 保留并出现 `W_LOSSY_FACE` 警告。
3. **规范往返**：任意文档（≥2 图层、其中一层隐藏、≥1 细节图）导出后再导入，除 `updated_at` 外，`id`、`name`、`layers` 顺序与可见性、`palette`、`details`、`anchor` 全部深度相等。
4. **旧版编辑器导出**：将 v0.7 文本框导出的 JSON 保存为文件后导入，能识别为「旧版编辑器导出」，空色号推断为 `B2`，图层与细节图完整保留。
5. **失败不改画布**：导入截断 JSON、`cols=29/rows=28`、缺失色号三类文件，均显示带定位的错误，当前画布与图纸库均不发生任何写入。
6. **持久化**：保存一张图纸后刷新页面，图纸仍在列表；点击可打开且矩阵与保存前逐格一致；上次打开文档自动恢复。
7. **自定义颜色闭环**：用颜色选择器选 `#112233`，矩阵出现生成色号（如 `U01`），`palette` 增加 `U01:#112233`；导出再导入后颜色一致，矩阵中不存在裸 `#112233`。
8. **冲突处理**：导出文档后原样再导入，触发 id 冲突弹窗；选「另存为副本」生成新 id 且两张并存；选「覆盖」更新原文档。
9. **首启空态**：清空本地存储后打开，自动为空白 32×32；图纸库显示空态文案；点击保存后列表出现 1 项。
10. **配额异常**：模拟 `QuotaExceededError`，顶部出现红色「保存失败」，点击「导出备份」可下载当前文档；内存中的画布不变。
11. **性能**：48×48、8 图层、1 细节图的文档，本地导入到首帧 ≤1.5s，导出 ≤0.8s（本机实测记录，无网络请求）。
12. **未保存离开**：有未保存修改时刷新/关闭，浏览器出现离开确认；保存成功后确认消失。
13. **色号输入**：输入 `h2` 能选中 `H2`；输入不存在的 `Z9` 报「色号 Z9 不在当前色板」且不改变选中色。
14. **未知部件**：导入含 `part:'cape'` 的文件，画布正常显示，预览警告列出 `cape`，导出后 `cape` 保留。

## 11. 需要用户拍板的点

1. **29×29 旧图纸的定位**：作为「旧版自定义」保留，不自动放大到 32×32（放大必然改形）。推荐保持原尺寸 + 徽章提示，是否同意？
