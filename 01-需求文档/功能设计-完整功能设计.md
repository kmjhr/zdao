## 2. 全局闭环约定（补全）

原文在章节层面留白的三处，先立全局约定，后续功能不再重复：

1. **首次进入**：无账号也能本地开玩；创建宇宙后直接进入"设定即任务"，不先看功能导览；首个 OC 完成即触发第一场引导演出。详见 F01/F12。
2. **进度保存**：所有写操作自动保存，本地先落盘、云端后同步；演出、拼豆、角色卡三类高频内容必须有可恢复草稿。详见 F02。
3. **内容产出的去向**：任何 AI/玩家产出都必须有明确落点——
   - 图纸 → OC 外观 / 背包物品 / 收藏图鉴 / 广场（F10/F28/F65–F68）；
   - 演出 → 纪念册官方剧情 / 录像 / 岛与关系变化（F25/F24/F27）；
   - 记忆 → 纪念册 / 回忆碎片 / 桌宠提起（F43/F16/F39）；
   - 物品 → 背包 / 送礼 / 手信 / 进戏（F15/F63/F22）；
   - 客串与联机 → 双方纪念册（F31/F64）。

## 3. M0 · 进入与支撑（5 项）

### F01 首次进入与宇宙创建 ｜ P0

- **目标与价值**：把"空岛"变成玩家自己的宇宙；首次启动 3 分钟内完成创建并看到第一个 OC 图纸，避免空态流失。
- **操作流程**：① 启动（本地可玩，登录可选）→ 展示"世界私密"说明；② 选入口：导入文本 / 从零建 OC / 示例宇宙；③ 填宇宙名与世界观卡（题材、腔调、时代、禁忌、色板推荐）；④ 创建 universe，进入创作台；⑤ 完成 F07、F09 后回岛触发第一幕。
- **界面与交互**：三步全屏向导，右侧实时预览宇宙卡；空态给"青春疼痛 / 政谋 / 谷子日常"三张示例卡；"稍后继续"常驻；成功进入岛并弹一句"她醒了"；失败保留表单并提示原因。
- **数据/内容结构**：`universe{id, owner_id, name, world_card{genre, tone, era, taboos[]}, color_palette, status, created_at}`；`owner` 可为本地匿名 ID。
- **核心规则与边界**：宇宙名 2–20 字；世界观卡至少 3 个字段；首个宇宙免费且必须走完；同名允许、id 唯一；隐私默认"仅自己"；示例宇宙只是预填，不共享数据。
- **异常与限制**：无网可本地创建，联网后补同步；AI 推荐失败用默认色板与模板卡；重复提交幂等；不支持导入图片/PDF，只接受文本。
- **验收标准**：新用户 3 分钟内创建宇宙并看到 1 个 OC 的 32×32 图纸；中途关闭重开草稿仍在；未登录也能完成。
- **与其他功能的关系**：F02 负责保存；F06–F12 在该宇宙内工作；F29/F30 管理后续宇宙。
- **来源**：【原文】2.6、8.1；【补全】首启路径、必填字段与 3 分钟时限。

### F02 存档、云同步与进度恢复 ｜ P0

- **目标与价值**：任何时刻退出都不丢创作；换设备能继续；为"长线关系"提供可信存储。
- **操作流程**：写操作 → 3 秒防抖本地落盘 → 后台增量同步 → 冲突检测 → 玩家选择保留版本 → 继续。
- **界面与交互**：顶栏状态点（已保存 / 同步中 / 离线 / 冲突）；设置页"导出存档 / 导入存档"；冲突弹窗左右对比；离线横幅不阻塞操作。
- **数据/内容结构**：`save_snapshot{user_id, universe_id, entity_type, entity_id, version, updated_at, hash}`；本地全量快照 + 最近 200 条操作日志 + 草稿表。
- **核心规则与边界**：按实体同步；纪念册与演出只追加不覆盖；云同步需登录，未登录仅本地；删除软删 30 天；版本号单调递增，服务端时间为准。
- **异常与限制**：断网继续本地，恢复后自动补传；失败重试 3 次转手动；存储不足提示清理缓存；同一账号多端最后写入优先，但纪念册冲突必须人工选。
- **验收标准**：演出中途杀进程，重开恢复到最近节点；两端并发编辑无静默覆盖；导出存档可在另一设备完整恢复。
- **与其他功能的关系**：全局基础；F01 的宇宙、F10 的图纸、F21 的版本都依赖它；F29 切换宇宙时按 `universe_id` 隔离。
- **来源**：【原文】7.3；【补全】防抖、草稿、冲突与软删机制。

### F03 OC 状态接口 ｜ P2

- **目标与价值**：让桌宠成为第一个出口，后续动态壁纸、锁屏小组件共用同一份 OC 状态，避免重复对接。
- **操作流程**：设置开启 → 生成本地 token 与端口 → 外部程序读取 → 关闭即失效；接口只读。
- **界面与交互**：开关、端口号、token 复制、测试按钮、权限说明；关闭态注明"不影响主程序"；测试成功显示示例 JSON，失败显示原因。
- **数据/内容结构**：`GET /oc/{id}/state → {oc_id, mood, current_action, recent_memories[3], last_performance, updated_at}`；配套 `GET /oc/list`。
- **核心规则与边界**：默认关闭；只输出摘要，不输出记忆原文与私密纪念册全文；每 OC 限流 1 次/秒；token 可重置；仅监听本机。
- **异常与限制**：端口占用自动顺延；token 失效返回 401 并提示重置；主程序退出后接口不可用；不提供写接口。
- **验收标准**：开启后 1 秒内可读到情绪与最近 3 条记忆摘要；关闭后请求失败；重置 token 后旧 token 立即失效。
- **与其他功能的关系**：F38–F41 的数据源；F43 提供记忆摘要；F15/F14 产生状态变化。
- **来源**：【原文】4.3；【补全】协议、鉴权、限流与只读边界。

### F04 BYO API 绑定与降级 ｜ P1

- **目标与价值**：玩家自付模型成本、隐私可控、模型自由；平台侧不被单一模型绑定。
- **操作流程**：设置 → 选供应商或自定义 base_url → 填 key 与 model → 测试连接 → 设为默认 → 调用失败自动降级为模板。
- **界面与交互**：连接卡片（状态灯 / 模型名 / 最近调用）；密钥输入框本地加密；"测试连接"给延迟与返回样例；失败提示"本次已使用内置模板"。
- **数据/内容结构**：`api_config{provider, base_url, model, key_ref, enabled, last_test_at}`；调用日志只存耗时、token 数与结果状态，不存密钥与全文。
- **核心规则与边界**：密钥不上传明文；结构化输出失败重试 1 次后降级；每次调用附带 `universe_id` 与 OOC 边界；玩家可随时切回内置。
- **异常与限制**：401/429/超时分别提示；连续 3 次失败自动暂停该配置并提醒；不支持浏览器直连的供应商时给代理说明。
- **验收标准**：填错密钥时全流程仍可走完且提示明确；切换配置后下一次生成生效；日志中查不到明文密钥。
- **与其他功能的关系**：F06/F09/F19/F45 的调用入口；F42 在调用前后做边界校验；F05 控制缓存与频率。
- **来源**：【原文】6.4、6.5；【补全】测试连接、密钥托管与熔断。

### F05 性能与成本守护 ｜ P0

- **目标与价值**：低端设备能玩、沙盘与演出不掉帧、LLM 成本可控，保证"确定性渲染 + 模板优先"的承诺。
- **操作流程**：启动时检测设备 → 选性能档（低/中/高）→ 沙盘与演出按档位分帧、懒加载 → LLM 请求先查缓存与模板 → 按 universe 分区加载数据。
- **界面与交互**：设置页"画质 / 动画帧率 / 同屏 OC 数"；加载用骨架屏；超过 2 秒的操作显示进度与取消；自动降档时只提示一次。
- **数据/内容结构**：`perf_profile{device_tier, fps_cap, max_ocs, quality}`；`cache{key, scope, ttl, created_at}`；分区键统一为 `universe_id`。
- **核心规则与边界**：沙盘同屏 OC 上限低 4 / 中 8 / 高 12；演出单帧预算 ≤16ms；同一输入 24 小时内复用结果；离线推演不调用 LLM；缓存不跨宇宙复用。
- **异常与限制**：掉帧自动降档并记录；缓存损坏回源；设备不支持 Canvas 加速时退化为静态帧；降档不改变剧情结果，只改表现。
- **验收标准**：中档设备 8 个 OC 沙盘稳定 ≥30fps；重复生成同图纸命中缓存；断网时演出仍可回放。
- **与其他功能的关系**：横切 F13/F20/F38；F04/F45 的成本受它约束；F02 的同步也走增量。
- **来源**：【原文】7.5；【补全】档位、阈值、缓存 TTL 与降级不改剧情的原则。

## 4. M1 · 创作台（9 项）

### F06 文本导入与结构解析 ｜ P0

### F07 OC 卡与 OOC 边界编辑 ｜ P0

### F09 AI 拼豆图纸生成 ｜ P0

- **目标与价值**：用固定矩阵保证角色 100% 一致，替代"文生图逐格生成"的画风崩坏；让文字角色第一次"看得见"。
- **操作流程**：选 OC → 选规格 32×32 / 48×48 → 选风格（随宇宙色板）→ 生成分层图纸（发型/头/身体/服装/配件）→ 预览 → 接受 / 重生成 / 进编辑器微调。

- **与其他功能的关系**：F10 编辑、F11 供色板、F20 渲染读取、F28 收录。

### F46 新建角色 · 像素 ID 卡交互 ｜ P0

- **数据/内容结构**：`oc_draft{id, universe_id, status(draft/created), name, intro, tags[], cover{type(matrix/crop), matrix_id, snapshot_ref, crop_rect{x,y,w,h}, ratio}, card_layout_version, updated_at}`；创建后并入 `oc.card`，不重复存一份卡册数据。
- **核心规则与边界**：姓名必填、同名允许但提示；一张 OC 只有一张卡；卡面变更同步卡册/角色库/公开页；截取只允许本人画面；卡片不可拖拽、不可缩放，避免遮挡与布局漂移；删除 OC 时卡片软删 30 天。
- **异常与限制**：动画资源缺失直接显示终态卡；编辑器保存失败保留草稿并提示；截取时画面未加载则禁用并提示"先到岛上或戏台"；裁剪源被清理后"重新截取"改为重新截图；低端设备关闭浮动与旋转。
- **验收标准**：① 从入口触发到可点击 ≤1.2s，跳过后卡面状态一致；② 两个热区点击命中率 100%，键盘可达；③ 空态无破图，保存形象后 1 帧内更新；④ 三种裁剪比例可切换、缩放 1–4x、越界被钳制、取消可恢复；⑤ 有改动取消必出三选一，草稿可恢复；⑥ 1280×720 与 1920×1080 下卡面不溢出、缩放档正确；⑦ 新卡立即出现在卡册，封面在卡册/详情/公开页一致；⑧ 字体加载失败有回退且布局不崩。
- **与卡册/角色库的关系**：卡册是"管理入口"（按宇宙分组的卡片网格，支持草稿、搜索、排序），角色库是"OC 资料库"（卡片的详情视图），二者共用 `oc` 与 `oc.card`；F28 图鉴只做收集成就，不与卡册混为同一数据。卡片是 F07 的封面化入口、F69 公开展示柜的默认素材、F63 手信的署名卡。
- **与其他功能的关系**：F07 提供完整人设；F09/F47 提供形象与编辑；F12 把建卡纳入任务；F02 存草稿；F69/F28 消费卡面。
- **来源**：【原文】2.2（OC 卡、拼豆图纸可手动调整）、5.1–5.3（Q 版全身、32/48 矩阵、分层）、5.5（模板与自由双路径）；【补全】ID 卡交互、动画时长、裁剪、字体、卡册关系与全部阈值。

### F47 人物形象编辑器（重做）｜ P0

> 重做说明：F10 是旧编辑器条目，本节为重做版，二者不并行；冲突处以本节为准。画布上限 40×40 与书中 5.2 的 48×48 不一致，见 Q16。定位是"拼豆图纸工具 + 绘画软件"的集合体，但一格始终等于一颗豆。

- **目标与价值**：既保留拼豆"一格一豆"的确定性与可复现，又给细节党绘画软件的自由度；图层与部件标记让同一份图纸能复用到卡面、演出、表情与动态。
- **画布与尺寸**：空白画板格点对齐，一格一份，最大 40×40；提供 16/24/32/40 四档，默认 32。选尺寸发生在"新建作品/从卡面进入手动拼豆"时，先选后画；模板可预置尺寸。已有内容改尺寸时弹三选一：**居中裁剪**（超出部分裁掉，预览损失区域）、**扩展画布**（原内容居中，四周补透明）、**整数倍重采样**（仅 16→32 等整数倍可用最近邻放大；非整数倍禁用）。确认前可预览，取消不改动；每次改尺寸压入撤销栈，可一键还原。
- **网格系统（细线 1 格 / 粗线 5 格）**：画布同时提供细线与粗线两级网格。细线每 1 格一条，粗线每 5 格一条并以左上角 `(0,0)` 为固定原点，最外边框始终按粗线绘制。40×40 恰好形成 8×8 个完整大块；16/24/32 分别形成 3+1、4+4、6+2 的组合，右侧/底部不足 5 格的余块保留，不为凑整改变格数，也不居中挪动原点。粗线可独立开关（默认开），关掉后仍保留外框与细线；网格整体开关关闭时只保留画布外框，格数不变。缩放表现：<1x 只显示外框与粗线、隐藏细线；1x–2x 细线以 30% 不透明度显示；2x–4x 细线 60%；≥4x 细线 100%，可选显示行列号。线宽按屏幕像素固定（细线 1px、粗线 2px），不随缩放变粗；缩放时以画布中心为锚点，网格线与格点不得出现半像素偏移，落笔始终吸附整格。网格属于编辑辅助，不进入最终像素矩阵；可另行导出"带网格与色号"的参考图。
- **工具与快捷键**：画笔 B（单格，按住拖拽连续上色，按 Bresenham 补点防断线）、油漆桶 G（当前层同色连通区，容差 0）、橡皮 E（透明）、吸管 I（取显示合成色并映射到最近色号）、平移（空格+拖拽/中键拖拽）、缩放（滚轮，0.5x–8x）、撤销 Ctrl+Z、重做 Ctrl+Shift+Z/Ctrl+Y、图层切换 `[`/`]`、**标记模式 M（开关）**、部件打标 P、洋葱皮 O。右键拖拽=临时橡皮，松开恢复原工具；右键色板=编辑自定义色。所有操作必须有可见反馈，不允许静默失败。
- **色号体系（MARD）**：色板采用 MARD 拼豆色号，全色号可用；面板按"系列/色系"分组，并提供全部/常用/最近/收藏视图与色号搜索。色号与色值的映射**以官方或社区公开的色号表为准**，本文不写具体色号清单与 RGB 数值；导入任何色号表都必须记录来源、版本与授权说明，发布前核实。色号查询支持完整编号、前缀、忽略空格与大小写匹配：命中后定位并高亮该色块；未命中提示"未找到该色号，可切换色号表或使用自定义色"；定位后可"设为当前色"，或"直接上色"到当前选区/单格，二者都需明确确认。色号表按 `palette_version` 管理：MARD 新增色以新版本追加，旧编号保留别名；历史作品锁定创建时版本，切换/升级版本需提示影响范围，可回滚。离线内置基础色号表，联网可更新；无网络不得阻塞绘制与保存。导出/导入保留 `color_id`、色号、`palette_version` 与来源；跨版本缺色时标"缺失色号"并保留原始编号，不静默替换为近似色。
- **空色与透明色**：新建画布所有格为"空"（`color_id=null`，不携带色号，渲染棋盘格）；一旦上色，该格必须绑定有效色号，不允许"有颜色无编号"。橡皮擦出的格为"透明"（`color_id=transparent`，显式记录、参与撤销与导出 `alpha=0`）；空与透明视觉上都透出底色，但空格不写入图层像素与色号统计，透明色写入像素并计入撤销与导出。
- **标记模式（独立开关）**：工具栏"标记模式"按钮 + 快捷键 `M` 切换；`P` 仍是"把当前选区打入当前部件"。进入后光标变荧光笔、画布非标记相关层降亮 10%，顶部常驻提示"标记模式：左键涂抹加入【部件名】，右键擦除"。标记格以半透明荧光笔覆盖显示：≥1x 为 35% 填充，≥2x 加 1px 描边，<1x 只显示部件轮廓；每个部件自动分配高对比色并允许手动指定；色弱可辨采用避免红绿对立、辅以斜线/点阵纹理与清单文字标签，不依赖单一色相。标记模式与画笔/油漆桶/橡皮互斥，避免误填；已标记格退出标记模式后仍可正常上色，颜色层与标记层独立显示、各自可开关。退出方式：再按 `M`、Esc、点击按钮、切换任意上色工具或离开编辑器；重进恢复上次当前部件。标记模式内每次涂抹/擦除各记 1 步撤销，撤销只回退归属与覆盖、不回退像素；图层隐藏时其标记覆盖一并隐藏，隐藏层不可被标记，跨层部件只显示可见层部分。密集小图（16×16）用 1 格最小笔刷、轮廓优先，相邻部件以纹理区分边界。
- **图层**：新建、行内重命名、拖拽排序、显示/隐藏、不透明度 0–100%、向下合并（二次确认）、删除（至少保留 1 层，非空层确认）。当前层在面板与画布左上角双重高亮；只有当前层接收绘制，跨层查看不跨层落笔。洋葱皮为可选项：其他层以 15% 不透明度显示，只读，用于对位，默认关闭。
- **部件模型（部件 = 图层 + 格子集合的引用，同层唯一归属）**：`part{id, name(1–12 字), dictionary_type, parent_id?, layer_refs[{layer_id, cells:[{x,y}]}], pivot{x,y}, rotate_center?, visible, order, created_at}`。部件只保存"哪些格属于我"，不复制像素；像素仍归图层，改色不改归属，删层时引用同步清理。**同一图层内一个格子只能属于一个部件**；同一 `(x,y)` 在不同图层可以分别归不同部件（外套层归外套、手层归手），跨层重叠不视为冲突。不设 `exclusive_group`，也不设主归属（primary）字段；归属关系本身就是唯一事实。再次标记已被占用的格子时弹出三选一：替换原归属 / 从原部件移除后加入当前部件 / 取消；不得静默覆盖。跨层重叠按 `(x,y, layer_id)` 去重；渲染层序仍由图层顺序决定，部件不改变 z 序。父子层级最多 3 层（根组 → 子组 → 叶子），子部件随父移动/旋转/显隐，父级变换后子级保留局部坐标；删除父部件需先解绑或连带删除。
- **锚点与变换**：每个部件必须有 1 个锚点 `pivot`（格坐标，允许落在格中心或格角），默认取包围盒中心；头发默认发根、眼睛默认中心偏下、下半身默认髋部中线。`pivot` 同时作为子级变换原点与旋转中心；旋转按 90° 整数倍吸附，自由角度只做预览、保存时归整。变换只影响部件及其子级，不修改底层像素；变换结果可"应用"回矩阵（会压入撤销栈）。
- **部件词典与层级**：标准词表使用固定 ID，显示名可本地化：`head` 头 → `hair` 头发 → `bangs` 刘海；`head` → `eye_l/eye_r` 眼睛、`brow_l/brow_r` 眉毛、`nose` 鼻、`mouth` 嘴、`ear_l/ear_r` 耳；`body` 躯干 → `upper_body` 上半身 → `coat` 外套；`body` → `lower_body` 下半身 → `pants` 裤子。预留 `hand_l/hand_r` 手、`foot_l/foot_r` 脚、`accessory` 饰品（帽子/围巾/眼镜等）。"头"作为组包含头发与五官，"躯干"作为组包含上下半身；外套可作为上半身的叠加子部件，画在不同图层时同一位置可分别归属外套与上半身，不视为冲突。左右成对部件默认成对创建，允许单侧删除并标"缺侧"。自定义部件必须挂到某个标准类型或 `other`；`other` 名称在矩阵内唯一，只进个人词典（最多 20 个），不写全局词表；标准 ID 不可改名/删除；自定义部件后续可映射到标准类型，历史数据保留别名。
- **标注操作**：提供三种选区——矩形框选、画笔刷选（1/2/3 格方形笔）、魔法棒（仅当前图层同色连通区，容差 0，透明格不参与）。选择只产生选区，不改像素、不进撤销栈；"打标 / 取消标记 / 重标 / 复制到其他层"各记 1 步撤销。打标=把选区加入当前部件，无当前部件先弹"新建部件"；若选区内有格子已在**同层**归属其他部件，按"替换 / 移除后加入 / 取消"三选一，禁止同层双重归属。取消标记=从当前部件移除选区，不影响其他部件。重标=先移除再归入目标部件，合并为 1 步撤销。复制到其他层=按相同 `(x,y)` 映射到目标层，目标层对应格必须已有像素，且在该层未被占用，否则按同层冲突处理。未标注格子默认"未归属"，不自动归入头/身体；可手动"补入当前部件"，需确认。部件清单显示名称、类型、格数、跨层数、父子关系与显隐；点选后画布只高亮该部件（2px 描边 + 30% 覆盖），再次点选取消。所有归属变更与图层操作共用同一个 50 步撤销栈；删除/合并图层时引用同步清理，撤销可恢复归属与高亮。
- **与动态和导出的衔接**：动画只引用部件 ID，不直接引用像素；`animation{part_id, frames[], transform}`。眨眼=眼睛部件切帧或纵向位移 1 格；说话=嘴部 3 个口型帧；走路=下半身与腿部件交替位移；转头=头组绕 `pivot` 旋转；头发飘动=头发/刘海绕发根 `pivot` 小幅旋转。部件缺失或未标注时，动画降级为整体位移/静态，并在演绎记录标"未绑定部件"。导出默认为 PNG + JSON sidecar：JSON 必含 `parts[]`（id/name/dictionary_type/parent_id/pivot/layer_refs/cells）、`cell_membership`（按 `(layer_id,x,y)` 记录**唯一** `part_id`）、`dictionary_version`、`color_system`、`palette_version`、`artwork.size/layers/order`；可选导出每部件透明底蒙版 PNG。只导出 PNG 时提示"部件信息与色号将丢失"；导入缺字段按"未归属/未知色号"处理。导出前校验同层唯一归属：若同一层出现一格多部件，阻止导出并列出冲突格，不允许自动取舍。
- **同类产品参照**：绘画软件这一类通常提供图层、选区、洋葱皮与帧动画（Aseprite、Piskel、Pixilart 属于该类别）；拼豆图纸工具通常强调格数、色号与行列编号。本文只借鉴这些通用做法，不引用具体版本、快捷键或参数，也不假设其未公开能力。
- **与卡片的衔接**：编辑器右上"设为卡面"进入取景模式：在作品渲染上做 1:1 取景框，默认全图适配，可缩放 1–2x、拖动构图；保存 `cover.frame` 回到 F46 卡面。重新编辑并保存后，若未手动改取景则卡面自动同步；手动取景则保留构图只更新像素。与 F46 的"从当前游戏画面截取"是两条独立来源，卡面记录 `cover.type(matrix/crop)`。
- **空态与首次引导**：空白棋盘格 + 中央提示"一格一豆，先点一个颜色"；首次进入三步浮层（选尺寸→上色→标记部件），可跳过；模板入口常驻；无可撤销操作时按钮置灰。
- **数据/内容结构**：`artwork{id, universe_id, oc_id?, size, grid{minor:1, major:5, major_origin(0,0)}, color_system{name:"MARD", palette_version, source, verified}, layers[{id,name,visible,opacity,order,pixels[color_id]}], palette[{code, source, version, display_name}], parts[{id,name,dictionary_type,parent_id,pivot,rotate_center,visible,order,layer_refs[{layer_id,cells[]}]}], animations[], marker_view{show_colors, show_marks, part_colors{}}, cover_frame?, undo_limit, updated_at}`；`color_id=null` 为空，`color_id=transparent` 为透明色；同层每格至多一个 `part_id`，`cell_membership` 由 `parts` 反推。
- **核心规则与边界**：40×40 为硬上限，越界绘制忽略并给边缘抖动提示；粘贴/拖入超出部分自动裁剪；不允许无限画布；删除最后一层、删除唯一部件需确认；撤销栈上限 50 步（含改尺寸/合并/删层/标记），超出丢弃最旧；保存前校验同层唯一归属、色号有效性、`palette_version` 与部件引用。
- **异常与限制**：色号未找到、色号表版本缺失、同层归属冲突、部件重名、合并空层、保存失败均给出可读提示并保留现场；保存失败自动落本地草稿；低端设备关闭洋葱皮与实时缩略图；不支持外部图片描摹与 AI 自动描边。
- **性能**：40×40=1600 格；全量重绘 ≤8ms（中档设备），拖拽上色 ≥60fps；每层离屏 Canvas，绘制只重算脏格，合成走 requestAnimationFrame；缩略图 64×64 节流更新；单作品内存 <20MB。标注相关：1600 格框选命中 ≤16ms，部件高亮/荧光笔覆盖重绘 ≤8ms，单格归属查询 ≤1ms、万格批量查询 ≤16ms；100 个部件的清单滚动 ≥30fps。
- **验收标准**：① 四档尺寸可选，改尺寸三选一可预览/取消/撤销；② 画笔/油漆桶/橡皮/吸管与拖拽连续上色无断点，撤销重做 50 步可靠；③ 图层七项操作全部可用，当前层高亮，洋葱皮可开关；④ 5×5 粗线在 16/24/32/40 下分别呈现 3+1、4+4、6+2、8×8，粗线对齐原点、边框闭合、无半像素偏移；⑤ 缩放到 <1x/1x/2x/4x 时细线按 0/30%/60%/100% 显示，粗线独立开关生效；⑥ 同层每格只能一个部件：重复打标必弹"替换/移除后加入/取消"，无法产生同层双重归属；同位置不同层可分别归属且清单显示跨层数；⑦ 子部件随父移动/旋转/显隐，锚点旋转生效，导出前同层冲突被拦截并列出冲突格；⑧ 矩形/刷选/魔法棒三种选区均可打标、取消、重标、跨层复制，未标注格保持"未归属"；⑨ 导出 JSON 可回读全部部件、层级、锚点、跨层格与每格唯一归属，PNG 单独导出有丢失提示；⑩ 保存后卡面更新 ≤1 帧，重新编辑同步，取景可保留；⑪ 40×40 全量重绘 ≤8ms、拖拽 ≥60fps、标注与荧光笔性能达标；⑫ 新建画布全为空且无 `color_id`，上色后每格必须绑定色号；⑬ 输入已存在的 MARD 色号可定位、选中并上色，未命中给出提示且不误上色；断网可用基础色号表，导出/导入保留色号与 `palette_version`；⑭ 标记模式可用按钮与 `M` 切换，光标/画布/顶部提示明确，与上色工具互斥；荧光笔按部件分色、可手动指定、可与颜色层独立开关；退出、撤销、图层显隐行为正确；⑮ 越界、色号缺失、同层冲突、重名、保存失败均有提示且不丢稿；空态引导可完成第一张作品。
- **与其他功能的关系**：F46 卡面来源；F09 生成初稿；F11 色板；F20 可读取部件做表情/动作；F22 作品可转道具；F69 卡面公开。
- **来源**：【原文】5.2（32×32 标准、48×48 进阶、放大创作）、5.3（分层换装）、5.6（姿势与矩阵变换）；【补全】40×40 上限、四档尺寸、绘画工具、图层、部件标记、卡面取景与性能阈值；【用户新增】细线 1 格/粗线 5 格、缩放分级、部件=图层+格子集合的引用、同层唯一归属/跨层分别归属、父子层级与锚点、标准部件词典、三种选区与标注撤销、MARD 色号与空色/透明色、标记模式与荧光笔、动画引用与导出保留（冲突见 Q16，Q18 已结案，其余见 Q17/Q19/Q20/Q21）。

## 5. M2 · 岛上日常（6 项）

### F13 小岛沙盘与时间同步 ｜ P0

- **目标与价值**：让"岛是家"成立——OC 不是数值摆件，而是按自己的角色卡过日子；玩家不在时世界继续运转。
- **操作流程**：进岛 → 读取现实时间与上次状态 → 推演离线行为 → OC 按作息活动（散步/坐/做事）→ 玩家观察、缩放、切换 OC → 离岛保存。
- **界面与交互**：等距/2.5D 小岛俯视，顶部显示现实时间与天气；OC 头顶状态图标（情绪/当前行为）；点击 OC 显示名牌；空态"岛上还没有人，去创作台建一个"；加载用骨架；失败显示静态岛 + 重试。
- **数据/内容结构**：`island{universe_id, layout, objects[]}`；`oc_runtime{oc_id, position, action, mood, schedule_id, updated_at}`；作息模板 `schedule`。
- **核心规则与边界**：现实时间驱动；离线推演最多 72 小时，超出只保留关键事件；同屏活动 OC 受 F05 档位限制；位置冲突自动避让；不做体力/饥饿等重数值；不跨宇宙共享布局。
- **异常与限制**：系统时间跳变以服务端时间校正；长时间离线压缩为事件摘要；加载失败不阻塞 F14 的文字互动；低端设备降为静态背景 + 简化动画。
- **验收标准**：离线 8 小时后回岛，OC 位置与行为符合作息；切换宇宙后岛数据完全隔离；同屏 OC 数不超过档位上限。
- **与其他功能的关系**：F44 提供意图；F14/F15 在岛上发生；F18 汇总离线；F27 改变布局；F41 从桌宠回岛。
- **来源**：【原文】2.3、7.1；【补全】推演上限、时间校正、同屏上限与空态。

### F14 观察与点击互动 ｜ P0

- **目标与价值**：用低成本互动建立"她记得我"的感受；每次互动都能沉淀为记忆与关系变化。
- **操作流程**：点击 OC → 弹出互动菜单（打招呼 / 摸摸头 / 聊天 / 看状态）→ 选一项 → 短动画 + 台词 → 写入互动事件与记忆 → 关闭气泡。
- **界面与交互**：像素气泡台词停留 3 秒，可点击跳过；菜单按关系与情绪置灰不可用项；互动后 10 秒冷却；成功有表情变化；失败提示"她今天不太想说话"并保留菜单。
- **数据/内容结构**：`interaction{id, oc_id, type, ts, result_text, mood_delta, memory_id}`；聊天记录只存摘要，不存长对话全文。
- **核心规则与边界**：每 OC 每日互动上限 20 次；同一互动同日去重不重复写记忆；所有台词先过 F42；关系类型与情绪决定可用选项；MVP 不做自由多轮长聊天。
- **异常与限制**：AI 失败用模板台词；OC 不在场提示"她出门了"并给出当前位置；连续点击触发冷却；离线时不能互动。
- **验收标准**：每次互动都有可见反馈并写入时间线；重复点击不产生重复记忆；越界台词被拦截且玩家可见"她忍住了"。
- **与其他功能的关系**：F42 校验；F43 写记忆；F25 收录重要互动；F26 改关系；F40 读情绪；F39 可被桌宠提起。
- **来源**：【原文】2.3；【补全】互动类型、冷却、每日上限与"不做长聊天"的 MVP 边界。

### F15 送礼 ｜ P0

- **目标与价值**：让玩家亲手拼的豆真正进入关系与叙事，而不只是装饰；"她记得这是谁送的"是跨功能的情感钩子。
- **操作流程**：打开背包 → 选物品（DIY 优先）→ 选 OC → 确认赠送 → OC 反应动画（收下/婉拒）→ 关系天平变动 → 物品归属该 OC。
- **界面与交互**：背包网格按宇宙筛选；物品详情含来源、色号、赠予记录；赠送前二次确认；空态"还没有物品，去拼一个"；成功显示关系变化箭头；失败说明原因。
- **数据/内容结构**：`item{id, universe_id, matrix, source(diy/preset), owner}`；`gift{from_player, to_oc, item_id, ts, reaction}`；关系变化写 `relation_event`。
- **核心规则与边界**：每 OC 每日收礼上限 3；按角色卡偏好判定喜欢/无感/婉拒；已赠物品默认不可重复赠送；预设物品可重复购买；跨宇宙物品不可送；婉拒也记录事件但不加关系。
- **异常与限制**：物品不存在或已赠提示；AI 反应失败用模板；背包满时提示清理；删除 OC 时赠予记录保留为快照。
- **验收标准**：送礼后 F26 可看到关系变化；OC 后续台词会提及该礼物；物品归属与赠予记录一致；每日上限生效。
- **与其他功能的关系**：F10 产出物品；F26 消费变化；F22 可把同一物品带进演出；F63 手信跨玩家；F43 记"谁送的"。
- **来源**：【原文】2.3、7.2；【补全】上限、偏好判定、婉拒与不可重复赠送规则。

### F16 回忆碎片 ｜ P1

- **目标与价值**：制造不可预测的惊喜，让"她记得过去"被玩家看见；把旧记忆重新变成内容，延长已有素材寿命。
- **操作流程**：上岛或桌宠在线时按概率触发 → 选一条旧记忆 → OC 独白气泡或 5–15 秒小重演 → 玩家可收藏进纪念册。
- **界面与交互**：特殊像素气泡/胶片边框，区别于日常台词；小重演可跳过；右下角"收进纪念册"；触发无提示，保持惊喜；失败静默不打断。
- **数据/内容结构**：`memory_fragment{id, oc_id, source_memory_id, text, scene_ref, performance_ref, ts, saved}`。
- **核心规则与边界**：每 OC 每日 1–3 次；优先 7 天未被引用的记忆；不得引用未解锁宇宙内容；所有文本先过 F42；小重演复用 F20 的确定性渲染。
- **异常与限制**：无可引用记忆则不触发；渲染失败退化为纯文字；连续触发去重；关闭"惊喜内容"设置后只保留文字。
- **验收标准**：触发频率不超过上限；碎片可回看且能定位到原记忆；内容与角色边界一致。
- **与其他功能的关系**：F43 供记忆；F20 供小重演；F25 接收收藏；F39 桌宠也可触发。
- **来源**：【原文】2.3、2.7；【补全】概率、频率上限、优先规则与收藏去向。

### F17 人设守护日志 ｜ P1*

- **目标与价值**：把"AI 被边界拦下"从失败变成情感素材——"她张了张嘴，那句'留下来'还是咽了回去"；同时让玩家感知边界真的在工作。
- **操作流程**：AI 生成被 F42 拦截 → 记录拦截点 → 生成一段内心独白 → 写入守护日志 → 玩家查看、收藏、设为角色签名。
- **界面与交互**：时间倒序列表（时间/OC/触发场景/命中规则）；独白卡片，带"这次她忍住了"标签；可关联到对应演出；空态解释"当她说不出那句话时，会写在这里"；成功进入有轻微纸张动画。
- **数据/内容结构**：`guard_log{id, oc_id, blocked_intent, rule_hit, monologue, ts, performance_id?, saved}`。
- **核心规则与边界**：只记录真实拦截，不为凑数编造；独白不得复述雷区原文；每 OC 每日上限 5 条；玩家可删除；`never_do` 命中必须记录，`soft_limits` 命中可选记录。
- **异常与限制**：独白生成失败则展示拦截摘要；敏感内容二次过滤；删除后不参与后续检索；日志不进入公开页。
- **验收标准**：发生拦截后 100% 产生一条日志；日志可关联到演出或互动；玩家能删除且删除后不再被引用。
- **与其他功能的关系**：F42 是唯一来源；F23 松绑场次更易触发；F25 可收录；F39 桌宠可引用；F69 不公开。
- **来源**：【原文】2.3、2.8、6.2；【补全】频率上限、可删除与"只记真实拦截"的原则。

### F18 离线事件报告 ｜ P1

- **目标与价值**：给回访一个具体理由——"我不在的时候，岛上发生了什么"；用低频、短小的报告制造动森式期待。
- **操作流程**：离线 ≥2 小时 → 回归时生成报告 → 展示 1–3 件事（按时间排序）→ 点事件跳到对应 OC/岛位置 → 一键收下小奖励 → 标记已读。
- **界面与交互**：回岛弹窗"你不在的这段时间"；卡片式时间线，带缩略图；可跳过；右上角已读；无事件时显示"岛上很安静"；生成中用占位卡。
- **数据/内容结构**：`offline_report{id, user_id, universe_id, from, to, events[], read, reward_claimed}`；事件引用 `interaction/memory/island_change`。
- **核心规则与边界**：以确定性推演事件为主，最多 1 条 LLM 生成；离线 <2h 不生成；推演上限 72h；不包含未授权的好友/社交内容；每次回归只生成一份。
- **异常与限制**：生成失败用规则事件兜底；重复登录不重复生成；时区变化按服务端时间；报告只读，不可编辑历史。
- **验收标准**：离线 8 小时回归有报告，事件与沙盘状态一致；关闭后当天不再弹；点击事件能定位到正确 OC。
- **与其他功能的关系**：F13/F44 产生事件；F25 可收录重要事件；F74 通知是社交版；F15 奖励进入背包。
- **来源**：【原文】2.3、2.8；【补全】2 小时阈值、1–3 条、奖励与去重规则。

## 6. M3 · 戏台演出（6 项）

### F19 剧情输入与剧本拆分 ｜ P0

- **目标与价值**：把"写一段剧情"变成"能演的一场戏"；AI 只决定内容，引擎负责画面，保证一致与低成本。
- **操作流程**：戏台 → 输入 / 导入 / 调用续写 → 选参演 OC 与场景 → 拆分 → 预览分镜（场景/动作/台词/情绪/镜头）→ 调整 → 开演。
- **界面与交互**：左原文右分镜卡；节点可拖动排序、单条编辑；角色未匹配标红并要求补选；空态给"初遇/对峙/吻"示例；拆分中显示进度；失败保留输入。
- **数据/内容结构**：`scene{id, universe_id, title, version, nodes[{scene, actors[], action, pose, dialogue, emotion, camera, duration}]}`。
- **核心规则与边界**：每个节点至少有 1 个动作或台词；角色必须属于当前宇宙（跨宇宙客串走 F31）；AI 只输出结构化指令，不输出图片；单场 6–20 节点，超长拆分为多场。
- **异常与限制**：解析失败按段落切分兜底；角色缺失不允许开演；节点超时或无法渲染时标黄并可跳过；不支持视频/图片输入。
- **验收标准**：附录 6 个分镜能复现为 6 个节点；每个节点可在 F21 单独编辑；开演前能看到完整分镜表。
- **与其他功能的关系**：F07 提供角色；F20 执行；F21 编辑；F42 校验；F45 续写；F22 挂道具。
- **来源**：【原文】2.4、6.1、附录；【补全】节点字段、6–20 节点与超长拆分规则。

### F20 确定性舞台演出 ｜ P0

- **目标与价值**：角色 100% 一致、可复现、可回放；这是"文生漫画/舞台剧"与逐格文生图的根本差异。
- **操作流程**：开演 → 引擎按节点加载角色矩阵、姿势库、背景模板 → 播放走位/动作/台词/镜头 → 结束 → 写入 performance 与纪念册候选。
- **界面与交互**：舞台视图 + 播放/暂停/跳过/倍速；底部台词字幕；右上进度；加载骨架；资源缺失时用占位背景并提示；结束后给"看剧本 / 去纪念册 / 再演一次"。
- **数据/内容结构**：`performance{id, scene_id, scene_version, props[], result{duration, keyframes?, rendered_at}}`；`pose_library{站/坐/蹲/走/牵手/拽衣领}`；背景模板表。
- **核心规则与边界**：同一 `scene + props + 矩阵快照` 渲染结果确定；角色外观读演出开始时的 matrix 版本；背景只用模板；AI 不得实时改画面；单场 ≤3 分钟；离线可回放。
- **异常与限制**：资源缺失不阻断，用占位并记录；掉帧自动降档；中断从最近节点续播；同一演出重复播放不重复发奖。
- **验收标准**：同一剧本连续两次演出结果一致（关键帧对比）；离线可完整回放；演出记录包含 scene_version。
- **与其他功能的关系**：F09/F10 提供矩阵；F19 提供剧本；F21 重演；F22 道具；F25 沉淀；F24 导出。
- **来源**：【原文】2.4、5.6；【补全】矩阵快照、pose 清单、3 分钟上限与回放机制。

### F21 剧本视图与重演 ｜ P1*

- **目标与价值**：让玩家从"观众"变成"导演"；写→演→改→再演的循环是长期可玩性的核心。
- **操作流程**：演出结束 → 切剧本视图 → 改台词/动作/顺序 → 保存为新版本 → 重演 → 满意后"设为官方剧情" → 进纪念册。
- **界面与交互**：节点时间线 + 行内编辑；版本下拉与差异高亮；"重演"主按钮；官方版本打星；空态提示"演完第一次就能改"；保存失败保留草稿。
- **数据/内容结构**：`scene.version`、`scene.parent_version`、`scene.is_official`；`performance` 关联具体 version；版本差异只存变更节点。
- **核心规则与边界**：原版永久保留；每场最多 10 个版本；官方版本每场唯一；改动台词/动作必须再过 F42；重演不重复发首次奖励；官方版本不可直接删除，只能取消标记。
- **异常与限制**：版本冲突提示选择；节点被删导致引用失效时用快照回退；重演资源缺失用占位；离线只能改不能重演。
- **验收标准**：改一句台词后重演，差异可见且可回放；官方版本出现在 F25；版本数不超过 10。
- **与其他功能的关系**：F19/F20 的前后环节；F25 接收官方；F42 复检；F22 道具版本随剧本保存。
- **来源**：【原文】2.4、2.8（标 P0）、8.2（标 P1）、9（MVP 先只演不改）；本表取 P1，见 Q1。

### F22 拼豆道具进戏 ｜ P1

- **目标与价值**：让玩家亲手拼的豆进入叙事——"那束花"不是装饰，而是演出的一部分；创作投入直接变成情感回报。
- **操作流程**：演出前打开道具栏 → 选物品（DIY 优先）→ 绑定到节点 → 预览出现位置 → 演出中按指令出现/传递 → 演后在岛上留下或收回。
- **界面与交互**：右侧道具栏按宇宙筛选；节点挂载点用虚线框；预览小图；空态"去拼一束花"并直达 F10；绑定成功显示"将在第 3 幕出现"；失败说明原因。
- **数据/内容结构**：`performance.props[{item_id, node_id, usage(show/hold/give)}]`；`item.used_in[]`；演出结果引用道具矩阵。
- **核心规则与边界**：每场 ≤5 件；道具必须属于当前宇宙；已赠他人的道具需对方授权才能用于联机；演后默认留在场景，可一键收回；同一道具可在不同演出复用。
- **异常与限制**：道具被删除则开演前提示替换；节点缺失则自动挂到首节点并提示；道具矩阵版本变化会改变画面但不改剧本。
- **验收标准**：绑定道具在对应节点可见；演出后岛上能找到该道具；收回后背包数量恢复。
- **与其他功能的关系**：F10 产出；F20 渲染；F27 留痕；F15/F63 流转；F25 记录。
- **来源**：【原文】2.4；【补全】数量上限、授权、演后去向与复用规则。

### F23 边界松紧滑杆 ｜ P1

- **目标与价值**：日常严格、剧情高潮临时松绑；破界瞬间成为最强情感冲击，同时不让日常人设崩坏。
- **操作流程**：演出前或演出中打开滑杆 → 选严格/标准/松绑 → 选生效范围（本场/本节点）→ 二次确认风险 → 生成时放宽 `soft_limits` → 结束自动恢复。
- **界面与交互**：三档像素滑杆 + 人话说明；范围选择；本场倒计时；演出标记"松绑场次"；确认弹窗列出"不会放宽"的硬边界；成功提示"本场已放宽，结束后恢复"。
- **数据/内容结构**：`boundary_mode{scope(scene/node), level(strict/standard/relaxed), expires_at, scene_id}`；不写入角色卡永久字段。
- **核心规则与边界**：只影响 `soft_limits`；`never_do` 与 `taboos` 永不放宽；松绑仅单场单节点；仍过滤违法/伤害内容；玩家必须二次确认；结束后自动回标准。
- **异常与限制**：超时自动恢复；检测到越界立即回滚并记 F17；非演出场景不可用；联机约戏需双方同意才能松绑。
- **验收标准**：松绑场次台词更外放，但硬边界仍 0 突破；演出结束状态恢复为标准；守护日志能记录松绑中的拦截。
- **与其他功能的关系**：F42 执行；F17 记录；F20 呈现；F31/F64 需双方授权。
- **来源**：【原文】2.8、6.2；【补全】三档、范围、时限、硬边界不可动与二次确认。

### F24 演出录像导出 ｜ P1

- **目标与价值**：让演出成为可传播的作品；CP 截图/舞台剧短视频是低成本获客素材。
- **操作流程**：演出结束 → 导出 → 选分辨率/封面 → 生成视频 → 预览 → 保存本地或分享。
- **界面与交互**：导出抽屉显示进度、预计大小、取消；预览 3 秒；水印开关（默认带"纸上岛"）；失败给重试与降级选项；完成后给"打开文件夹 / 分享"。
- **数据/内容结构**：`export_job{id, performance_id, format, resolution, status, file_ref, created_at}`；导出不复刻私密记忆原文。
- **核心规则与边界**：仅导出本人演出或已获授权的联机演出；默认 1080p/30fps/≤3 分钟；不含未公开宇宙与私密纪念册信息；他人 OC 必须授权；水印可关但默认开。
- **异常与限制**：编码失败降级 720p；磁盘不足提示；导出中断可续；低端设备允许导出但预览降质。
- **验收标准**：导出文件可播放且与演出内容一致；未授权他人 OC 无法导出；水印设置生效。
- **与其他功能的关系**：F20 提供演出；F69/F65–F68 是分享去向；F64 联机需双方授权；F31 客串同理。
- **来源**：【原文】2.8；【补全】分辨率、时长、授权、水印与降级策略。

## 7. M4 · 沉淀（4 项）

### F25 纪念册时间线 ｜ P0

- **目标与价值**：让演出与关系留下痕迹，形成"官方剧情"；沉淀既是回报，也是下一次创作的素材入口。
- **操作流程**：演出设为官方或发生重要互动 → 自动写入 → 按宇宙/角色/类型筛选 → 点开回放或读文 → 导出/分享。
- **界面与交互**：时间线卡片（封面/标题/参与 OC/日期/来源标记）；顶部筛选；空态"还没有官方剧情，去演一场"；官方标记可取消；加载失败给重试。
- **数据/内容结构**：`memorial{id, universe_id, type(performance/interaction/gift/offline), content, refs[], ts, is_official, snapshot?}`。
- **核心规则与边界**：只追加不覆盖；删除需二次确认并软删；跨宇宙不混册；每场演出只能有一个官方版本；引用对象删除时保留快照。
- **异常与限制**：回放资源缺失降级为文字；同步失败本地暂存；私密内容不进入公开页；时间线不按玩家本地时区重排历史。
- **验收标准**：完成一场演出后 1 条纪念册记录；可按角色筛选；回放与当时演出一致；取消官方后不再置顶。
- **与其他功能的关系**：F20/F21 产生；F26 关联；F28 收录；F69 展示；F43 供记忆。
- **来源**：【原文】2.5；【补全】筛选、软删、快照与唯一官方规则。

### F26 关系天平与关系活地图 ｜ P0

- **目标与价值**：关系是玩家真正在养的东西；双向可视化让"A 以为的"和"B 感受的"差异被看见，事件推动演化。
- **操作流程**：打开关系页 → 看 A→B 与 B→A 双向值 → 点边看事件流 → 时间轴回放变化 → 可触发关系事件。
- **界面与交互**：天平/雷达 + 关系图；边色按类型；事件列表带来源（演出/送礼/互动）；变化用箭头动画；空态"先建两个 OC 并连一条关系"。
- **数据/内容结构**：`relation.value_ab/value_ba`；`relation_event{relation_id, delta, reason, ref_type, ref_id, ts}`。
- **核心规则与边界**：值域 -100~100；单次事件变化上限 ±20；每日自然回落 1；双向独立结算；关系类型决定事件模板；历史事件不可改，只能追加修正。
- **异常与限制**：数据缺失按 0 展示；引用失效显示摘要；关系图节点过多时聚合；跨宇宙关系不参与本宇宙天平。
- **验收标准**：送礼/演出/互动后数值变化可见且可追溯到事件；A→B 与 B→A 可不同；回落与上限生效。
- **与其他功能的关系**：F08 建边；F15/F14/F17 产生事件；F25 收录里程碑；F19 用关系写剧本。
- **来源**：【原文】2.5、2.8（关系活地图 P1）；【补全】±20 上限、每日回落、双向独立与事件流。

### F27 岛与道具改变 ｜ P1

- **目标与价值**：演了"搬家"，屋子真的换位置——世界痕迹让演出不只是看片，而是改变玩家的岛。
- **操作流程**：剧本节点标记"世界影响"（搬家/换花/留下物品）→ 演出结束应用 → 岛上可见 → 纪念册可看前后对比。
- **界面与交互**：岛布局在演出中只读；变更后弹出"岛变了"并高亮变化点；提供前后对比滑块；玩家手动改布局需确认。
- **数据/内容结构**：`island_change{id, universe_id, type, target, from, to, performance_id, ts, reversible}`。
- **核心规则与边界**：只允许预定义变更类型；跨宇宙不生效；变更可回滚最近 5 次；同一演出重复播放不重复应用；玩家手动改动优先于演出变更。
- **异常与限制**：目标对象不存在则跳过并记录；变更冲突按时间后者覆盖并提示；资源缺失用占位。
- **验收标准**：演"搬家"后屋子位置真实改变；纪念册有变更记录；回滚可恢复上一布局。
- **与其他功能的关系**：F13 载体；F20/F22 产生；F25 记录；F02 保存。
- **来源**：【原文】2.5；【补全】变更类型、回滚次数、冲突与幂等规则。

### F28 收藏图鉴 ｜ P2

- **目标与价值**：给"积累回报"一个可见容器；OC、宇宙、豆色、物品、演出的收集让长期投入有里程碑。
- **操作流程**：图鉴页分 OC/宇宙/豆色/物品/演出 → 未解锁显示剪影与条件 → 达成自动点亮 → 查看详情/分享单卡。
- **界面与交互**：网格图鉴 + 进度条 + 稀有度；点亮动画；空态说明获取方式；跨宇宙分册切换。
- **数据/内容结构**：`collection_entry{type, ref_id, universe_id, unlocked_at, progress}`；只读派生，不重复存原始内容。
- **核心规则与边界**：只记录真实获得；限定内容绝版后仍显示；不因删除 OC 而回收；跨宇宙分册；图鉴不等于卡册（卡册管 OC，图鉴管成就）。
- **异常与限制**：数据缺失显示占位；同步延迟可手动刷新；未解锁内容不泄露剧情。
- **验收标准**：新 OC/新色/新演出自动点亮；进度准确；删除内容不影响已点亮记录。
- **与其他功能的关系**：F11 豆色；F25 演出；F29 宇宙；F69 可分享单卡。
- **来源**：【原文】2.7；【补全】分类、派生数据、绝版保留与卡册区分。

## 8. M5 · 多宇宙（3 项）

### F29 宇宙管理台 ｜ P1

- **目标与价值**：多宇宙是内容可变与长期积累的入口，但必须先防"一堆空岛"；管理台负责"看得见、切得动、不过量"。
- **操作流程**：首页书架/星图 → 查看已解锁宇宙卡（进度/OC 数/最近动态）→ 进入或切换 → 新建（受 F30 限制）。
- **界面与交互**：星图节点 + 书架列表双视图；当前宇宙高亮；锁定宇宙显示条件；空态引导建首个宇宙；切换有 0.3s 过场；加载失败单卡重试。
- **数据/内容结构**：`universe.status(locked/active/archived)`；`user_universe_progress{user_id, universe_id, progress, last_visited_at}`；所有实体带 `universe_id`。
- **核心规则与边界**：同时活跃宇宙建议 ≤3；切换不丢状态；删除宇宙需先导出确认；锁定宇宙不可进入；归档宇宙只读但可回访。
- **异常与限制**：单卡加载失败不影响其他宇宙；锁定态点击给解锁条件；数据迁移失败回滚并提示。
- **验收标准**：切换宇宙后创作台/岛/纪念册数据完全隔离；锁定卡不可进入；活跃数超限时给出提示。
- **与其他功能的关系**：F01 创建；F30 解锁；F31 客串；F25 分册；F02 分区保存。
- **来源**：【原文】2.6；【补全】活跃上限、归档态、双视图与隔离验收。

### F30 宇宙解锁节奏 ｜ P1

- **目标与价值**：宁可 3 个深宇宙，不要 10 个空岛；用关键剧情作为门槛，让新宇宙是奖励而不是逃避。
- **操作流程**：完成当前宇宙关键剧情（官方演出 ≥3 且主线节点完成）→ 解锁提示 → 新宇宙引导 → 旧宇宙保留"引力事件"拉回。
- **界面与交互**：进度条命名为"宇宙引力"；达成时星图点亮动画；未达成显示具体条件与差多少；新宇宙入口先预览世界观卡。
- **数据/内容结构**：`unlock_rule{from_universe, conditions[], to_universe}`；`progress` 由 F25/F20 派生，不单独维护。
- **核心规则与边界**：关键剧情=官方演出 ≥3 + 主线节点完成；暂不支持付费跳过；解锁后旧宇宙仍可回访；同一账号解锁顺序固定。
- **异常与限制**：条件判定延迟可手动刷新；数据不足按未达成；跨宇宙事件不重复发解锁奖励。
- **验收标准**：达成条件后即时解锁；未达成无法新建下一宇宙；旧宇宙回访入口始终存在。
- **与其他功能的关系**：F29 入口；F25 条件来源；F31 解锁后的内容；F20 演出计数。
- **来源**：【原文】2.6；【补全】"官方演出 ≥3 + 主线完成"的可判定条件与不可付费跳过。

### F31 跨宇宙客串 ｜ P2

- **目标与价值**：世界观冲突本身就是戏；让旧宇宙的 OC 进入新宇宙，制造"引力"与新鲜感。
- **操作流程**：选 A 宇宙 OC → 发起客串到 B → 双方主人授权（涉及他人时）→ 计算边界交集 → 生成客串剧本 → 演出 → 进双方纪念册。
- **界面与交互**：客串邀请卡；边界交集预览（列出保留/冲突项）；冲突点标红；客串场次打标；空态说明"需要两个已解锁宇宙"。
- **数据/内容结构**：`crossover{id, from_universe, to_universe, oc_ids[], boundary_intersection, scene_id, approved_by[], ts}`。
- **核心规则与边界**：边界取交集（更严）；`never_do` 取并集；客串 OC 外观可保留原色或随 B 色板（需确认）；不改变原宇宙关系，除非双方同意；单次 ≤2 个客串 OC。
- **异常与限制**：交集为空则禁止并列出冲突点；授权超时自动取消；目标宇宙锁定不可客串；客串演出不触发 B 宇宙主线解锁。
- **验收标准**：客串演出中双方边界均未被突破；成品在双方纪念册可见；交集为空时无法开演。
- **与其他功能的关系**：F29 宇宙；F19 剧本；F23 松绑需双方同意；F64 联机；F42 校验。
- **来源**：【原文】2.6、2.8；【补全】交集算法、人数上限、授权超时与不触发解锁。

## 9. M6 · 社交（15 项）

### F60 私密宇宙与默认私密 ｜ P0

- **目标与价值**：先有可晒的东西，才谈社交；所有内容先在私密层生长，社交只是逐条出口。
- **操作流程**：创建宇宙/OC/剧情/纪念册/演出/物件 → 默认 `private` → 需要外露时逐条进入 F72 → 选档位 → 生成快照 → 出现在好友圈/广场/公开页。
- **界面与交互**：宇宙首页常驻"仅自己可见"；分享入口二次确认；关闭分享不影响岛内使用；批量变更显示影响范围。
- **数据/内容结构**：`visibility{target_type, target_ref, level, conditions, repost_allowed}`；所有实体带 `universe_id`；对外只读 `public_snapshot`。
- **核心规则与边界**：不存在"创建即公开"；纪念册、记忆原文、OC 边界字段永不进入快照；私密内容不进入搜索、推荐与任何他人视图。
- **异常与限制**：未登录可私密使用；同步失败只影响云端；误公开可撤回，但已保存到本地的图片不可追溯并提示。
- **验收标准**：新内容默认私密；未公开不出现在任何他人视图；OC/纪念册/演出均带 `universe_id`；关闭分享不影响私密内容可用。
- **与其他功能的关系**：F01/F02 建宇宙与存档；F72 四档；F69 公开出口；F73 处置越界公开。
- **来源**：【用户定】四层结构①、"默认公开"作废；【推导补全】快照边界与撤回提示。

### F61 好友关系、请求、分组与拉黑 ｜ P0

- **目标与价值**：把"持续看作品"与"进岛许可"分开；好友必须双方同意，关注不等于好友。
- **操作流程**：搜索/邀请码/公开页 → 发送申请（≤50 字）→ 对方同意/拒绝 → 设分组与备注 → 解除好友或拉黑。
- **界面与交互**：好友列表、请求箱、分组管理、备注（仅自己可见）、拉黑入口常驻；空态给邀请码；批量请求提示验证。
- **数据/内容结构**：`friendship{user_a, user_b, status, since}`；`friend_request{from, to, message, status, expires_at}`；`follow{from, to, muted}`；`block{owner, blocked, reason}`；`friend_group`。
- **核心规则与边界**：好友双向、需同意；关注单向、只覆盖公开内容；请求 7 天过期；拒绝后 24h 冷却；备注 ≤12 字；好友 200 / 待处理 50 / 分组 20；拉黑即时生效，双方不可搜索、申请、进岛、评论、引用；解除拉黑只回"已解除"，不恢复好友。
- **异常与限制**：达上限拒绝并给清理入口；重复申请幂等；被拒方不收到结果通知；对方注销显示"已注销"；批量请求触发验证码。
- **验收标准**：好友必须双向同意；请求 7 天过期、拒绝后 24h 冷却；备注仅自己可见；拉黑后双方不可搜索/申请/进岛/评论/引用；解除拉黑不恢复好友。
- **与其他功能的关系**：F60 私密；F62 岛门；F63 手信；F71 陌生人入口；F74 通知。
- **来源**：【用户定】好友圈；【推导补全】上限、冷却、关注与好友分离。

### F62 岛门授权与串门 ｜ P0

- **目标与价值**：像现实串门，而不是公开逛街；进岛永远需要主人授权。
- **操作流程**：选好友 → 选宇宙 → 设授权粒度（一次性/长期/白名单）→ 勾区域 → 选在场模式与访客权限 → 访客进岛 → 离开留痕。
- **界面与交互**：岛门开关（默认关）、授权卡片、区域勾选、在场三选一（在场/隐身观察/离岛）、只读与互动开关、访客状态条、踢出按钮、访问记录。
- **数据/内容结构**：`island_gate{owner, guest, universe_id, mode(once/long/whitelist), areas[], presence, scopes(read/interact/gift), expires_at}`；`visit{id, host, guest, universe_id, entered_at, left_at, actions[], kicked}`。
- **核心规则与边界**：按宇宙分别授权，好友不自动全开；卧室、纪念册、未公开演出默认不可进；只读参观为默认，可互动（点击 OC/送礼/留言）单独授权；任何模式都不能编辑布局、带走物件、改关系；撤销或踢出 3 秒内断开；踢出后 24h 不可再申请该岛；访问留痕保留 30 天，主人可清空。
- **异常与限制**：主人离线默认拒绝（可按授权自动接待）；跨宇宙需分别授权；权限变更即时生效；访问中断开不写半条记录。
- **验收标准**：岛门默认关闭；授权粒度含一次性/长期/白名单；区域范围可选；主人可选在场或隐身观察；只读与可互动分开；撤销 3 秒内断开并留痕；踢出立即生效。
- **与其他功能的关系**：F61 好友；F63 手信；F13 岛；F74 通知来访；F73 处置越权访问。
- **来源**：【用户定】岛门；【推导补全】授权粒度、区域、在场模式与留痕。

### F65 图纸市场 ｜ P1

- **界面与交互**：每条内容的可见性标签、条件编辑器、权限开关、批量修改二次确认、变更记录；默认值固定为"私密"。
- **数据/内容结构**：`visibility{target_type, target_ref, level, conditions, repost_allowed}`；`share_link{token, target, visibility, expires_at, revoked_at}`。
- **核心规则与边界**：四档即时生效；每条内容独立，父子不自动继承（宇宙公开不等于纪念册公开）；可见性与评论/复制/借用/转发权限一致；转发默认关闭，开启后仅允许原样转发并保留署名与来源；作者撤销后新转发失效；私密/好友内容不因转发变成公开；站外二次发布需单独授权。
- **异常与限制**：已保存到本地的图片不可追溯并提示；撤销后链接 404；批量修改失败整体回滚。
- **验收标准**：四档即时生效；可见性与评论/复制/转发权限一致；转发默认关闭，开启后仅原样转发并署名；撤销后新转发失效。
- **与其他功能的关系**：F60 默认私密；F69 公开页；F65–F68 广场；F73 处置违规转载。
- **来源**：【用户定】四档与"要可以转"；【推导补全】条件类型、权限联动与撤销语义；语义待确认见 Q22/Q1。

### F73 举报—审核—处置—申诉 ｜ P0

- **目标与价值**：让骚扰、盗用、冒充有明确出口与时限，不让创作者自生自灭。
- **操作流程**：公开页/市场/回放/评论触发举报 → 生成受理编号 → 24h 初审 → 48h 处置（L1–L4）→ 7 天内可申诉 → 结果通知。
- **界面与交互**：举报入口四处可达、举报人保密、进度查询、申诉表单、处置记录；未成年与敏感内容标记转人工。
- **数据/内容结构**：`report{id, reporter, target_type, target_ref, reason, status, handled_at}`；`appeal{id, report_id, appellant, text, status, result}`。
- **核心规则与边界**：L1 提示 / L2 内容下架 / L3 账号限权 / L4 封禁或移交；恶意举报限流；L3/L4 人工复核并留审计；处置与申诉记录可查。
- **异常与限制**：被举报内容先隐藏再审；证据不足驳回并说明；申诉期间不重复处置同一事由。
- **验收标准**：公开页/市场/回放/评论可举报；24h 初审、48h 处置；L1–L4；7 天申诉；记录可查；未成年与敏感内容转人工。
- **与其他功能的关系**：F69 公开页；F65–F68 广场；F71 名片冒充；F72 转载越权。
- **来源**：【原文】3.1；【用户定】举报处置保留；【推导补全】SLA、四级处置与申诉；法务口径见 Q22/Q8/Q9。

### F74 通知聚合与离线降级 ｜ P1

- **目标与价值**：让社交提醒可预期；离线时不假装成功、不伪造动态。
- **操作流程**：产生通知 → 按类型聚合 → 免打扰判断 → 推送或应用内展示 → 离线写入队列 → 联网按时间合并。
- **界面与交互**：通知中心（好友请求/手信/来访/约戏邀请/评论点赞/举报结果）、免打扰设置、聚合卡片、同步状态条。
- **数据/内容结构**：`notification{id, user, type, refs[], aggregated_count, read, muted}`；`sync_queue`。
- **核心规则与边界**：同一对象 24h 合并 1 条；举报结果必达；免打扰默认 23:00–08:00（仅静音推送）；安全类通知不受限；点赞、留言草稿、分组备注本地先行；拉黑、撤销授权、踢出、撤销分享联网优先，离线置灰不假装成功；动态不可用显示缓存并标"可能延迟"。
- **异常与限制**：发布失败保留草稿可重试；重复提交幂等；推送失败降级为应用内。
- **验收标准**：通知按类型聚合、免打扰不推送；离线本地先行、联网按时间合并；动态不同步标"可能延迟"；拉黑/撤销授权/踢出联网优先。
- **与其他功能的关系**：F61 请求与拉黑；F62 来访；F63 手信；F64 邀约；F73 处置结果。
- **来源**：【用户定】通知降级保留；【推导补全】聚合窗口、免打扰与同步策略。

## 10. M7 · 桌宠（4 项）

### F38 桌宠窗口与像素动画 ｜ P2

- **目标与价值**：岛是家，桌面是散步；把 OC 带出岛，常驻桌面形成日常陪伴与回访钩子。
- **操作流程**：设置开启桌宠 → 选 OC → 生成透明置顶窗口 → 拖拽/缩放 → 待机动画循环。
- **界面与交互**：无边框透明窗；右键菜单；托盘图标；多显示器记忆位置；全屏游戏可自动隐藏；缩放 0.5x–2x；位置与置顶可设。
- **数据/内容结构**：`pet_window{oc_id, position, scale, always_on_top, opacity, monitor_id}`；动画由矩阵局部变换 + 帧插值生成，不手绘。
- **核心规则与边界**：置顶可关；不遮挡任务栏关键区域；同一 OC 只允许一个桌宠窗；动画零手绘复用拼豆矩阵；低端设备降帧。
- **异常与限制**：窗口丢失从托盘恢复；渲染失败退化为静态立绘；权限不足提示；重启恢复上次位置与缩放。
- **验收标准**：开启后 5 秒内出现桌宠；可拖动/缩放；重启位置保留；全屏自动隐藏生效。
- **与其他功能的关系**：F03 状态接口；F39/F40/F41 能力；F05 性能；F47 矩阵。
- **来源**：【原文】4.1、4.2、4.3；【补全】窗口参数、缩放范围、托盘恢复与单实例规则。

### F39 桌宠记忆同步与"提起" ｜ P2

- **目标与价值**：桌宠不是通用皮套，而是"记得岛上一切"的 OC；突然提起旧事是最自然的回访钩子。
- **操作流程**：读取 OC 状态 → 按事件/随机触发 → 气泡提起岛上剧情或关系 → 点击气泡回岛。
- **界面与交互**：像素气泡；频率设置；免打扰时段；点击气泡跳转；空态用通用问候；失败静默。
- **数据/内容结构**：`pet_mention{oc_id, memory_id, text, ts, clicked}`；只读 F03 的摘要。
- **核心规则与边界**：每日 ≤5 次；优先未提及记忆；必须过 F42；不泄露私密纪念册全文；同一记忆 3 天内不重复提起。
- **异常与限制**：无记忆则通用问候；接口断开用缓存最近 3 条；免打扰时段不弹；点击跳转失败回岛首页。
- **验收标准**：岛上新增演出后桌宠会提及；点击可回岛；频率与免打扰生效。
- **与其他功能的关系**：F03 状态；F43 记忆；F25 纪念册；F38 窗口；F41 回岛。
- **来源**：【原文】4.2；【补全】频率、去重、免打扰与缓存降级。

### F40 桌宠情绪可视化与哄好 ｜ P2

- **目标与价值**：把岛上事件的影响带到桌面；低落时趴桌角、被哄好后恢复，情绪成为可感知的关系反馈。
- **操作流程**：岛上事件改变 mood → 桌宠表现变化 → 玩家摸摸头/送道具 → 情绪回升 → 台词反馈。
- **界面与交互**：情绪图标/姿态（低落趴桌角、开心转圈）；哄好动画；心情说明；冷却提示；不显示具体数值给玩家。
- **数据/内容结构**：`oc.mood{value, label, updated_at}`；`mood_event{oc_id, delta, reason, ref, ts}`。
- **核心规则与边界**：mood 由事件驱动，不允许玩家直接设值；每日自然回归基线；哄好有冷却；低落不触发惩罚/断功能。
- **异常与限制**：状态不同步以岛为准；接口失败显示最近缓存；连续哄好收益递减。
- **验收标准**：演出/互动后情绪变化在桌宠可见；哄好后数值回升且可被 F03 读到；冷却生效。
- **与其他功能的关系**：F14/F15 产生；F03 输出；F38 表现；F13 岛状态。
- **来源**：【原文】4.2；【补全】基线回归、冷却、收益递减与"不惩罚"原则。

### F41 桌宠交互与回岛 ｜ P2

- **目标与价值**：轻交互 + 一键回岛，让桌面成为岛的入口；多只同屏的 CP 互动自带传播性。
- **操作流程**：右键菜单（摸摸头/送道具/表演一段/回岛/切换 OC）→ 执行 → 即时反馈 → 回岛打开对应宇宙沙盘。
- **界面与交互**：右键菜单；多只同屏编排（对视/偷看/吃醋）；快捷键；动作 ≤5 秒；失败给静态反馈；回岛为主按钮。
- **数据/内容结构**：`pet_action_log{oc_id, action, ts, result}`；`pet_group{oc_ids[], layout}`。
- **核心规则与边界**：同时最多 3 只；动作过 F42；表演一段复用姿势库不生成新剧情；回岛为默认主入口；跨宇宙 OC 不同屏。
- **异常与限制**：多只位置冲突自动错位；动作失败退化为静态；OC 被删除则桌宠移除并提示。
- **验收标准**：右键任一项都有即时反馈；回岛一次点击进入正确宇宙；多只同屏不重叠。
- **与其他功能的关系**：F38 窗口；F39/F40 状态；F13 岛；F15 道具；F20 姿势库。
- **来源**：【原文】4.2；【补全】菜单项、3 只上限、动作时长与回岛语义。

## 11. M8 · AI 内核（4 项）

### F42 OOC 边界校验引擎 ｜ P0

- **目标与价值**：所有 AI 行为/对话/剧情先过边界再输出；让"守人设"成为系统能力，而不是提示词运气。
- **操作流程**：生成请求 → 组装边界（角色卡 + `never_do` + `taboos` + `soft_limits` + 当前模式）→ 生成前约束 → 生成后检测 → 命中则重写/拦截 → 记录守护日志。
- **界面与交互**：正常时无感；命中时给"她忍住了"轻提示；设置页可查看规则与最近拦截；不向玩家暴露内部提示词全文。
- **数据/内容结构**：`boundary_check{oc_id, input_ref, output_ref, hit_rule, action(retry/block/rewrite), ts, performance_id?}`。
- **核心规则与边界**：两段式校验（生成前+生成后）；`never_do` 硬拦；`soft_limits` 仅可按 F23 单场放宽；同一输出最多重写 2 次；仍失败转模板；跨宇宙取交集。
- **异常与限制**：校验服务失败按保守拦截并提示；误杀可在设置中申诉；敏感内容二次过滤；校验不通过不得静默放行。
- **验收标准**：构造越界输入 0 泄漏；每次拦截有日志；正常输入抽样误杀率可接受；关闭网络仍走本地规则。
- **与其他功能的关系**：F07 提供边界；F14/F19/F31/F64/F38–F41 调用；F17 消费拦截；F23 调整松紧。
- **来源**：【原文】6.2；【补全】两段式、重试上限、保守失败与误杀申诉。

### F43 记忆系统 ｜ P0

- **目标与价值**：OC 记得发生过什么，且成本可控；结构化事件 + 向量检索混合，避免全量历史进上下文。
- **操作流程**：事件发生 → 结构化写入（谁/何时/何地/何事/情绪）→ 生成摘要与向量 → 检索（时间衰减+相关度）→ 供演出/桌宠/回忆碎片引用。
- **界面与交互**：玩家可见"她的记忆"列表；可删除/置顶重要记忆；显示来源与时间；空态"还没有共同记忆"。
- **数据/内容结构**：`memory{id, oc_id, event{type, actors[], place, summary, emotion}, embedding, importance, ts, refs[]}`。
- **核心规则与边界**：结构化优先，向量仅辅助检索；上下文只带 Top-K 摘要；共同记忆可进纪念册；删除记忆同步移除引用；跨宇宙记忆不混检。
- **异常与限制**：向量失败退化为关键词检索；记忆过多转冷层归档；删除后不再被提起；敏感内容不写摘要。
- **验收标准**：新事件可被下一次生成引用；检索延迟可接受；删除后不再出现在演出/桌宠；Top-K 不超预算。
- **与其他功能的关系**：F14/F15/F20 产生；F16/F39 消费；F25 收录；F42 过滤；F44/F45 读取。
- **来源**：【原文】6.3；【补全】字段、Top-K、删除同步与冷层归档。

### F44 行为引擎 ｜ P0

- **目标与价值**：OC 日常自主，但以零成本模板为主；只有特殊事件才调 LLM，保证"岛一直活着"又不烧钱。
- **操作流程**：读角色卡 + 当前状态 + 现实时间 → 状态机选意图（作息模板）→ 特殊事件才调 LLM → 输出动作/位置 → 沙盘执行。
- **界面与交互**：玩家只看结果；可选调试面板显示当前意图与来源（模板/LLM）；异常时有"她今天有点不一样"提示。
- **数据/内容结构**：`behavior_intent{oc_id, intent, target, source(template/llm), ts}`；`schedule` 作息模板。
- **核心规则与边界**：模板优先；同一 OC 意图切换有最小间隔；关系/情绪影响权重；不得离开岛边界；离线推演不调 LLM。
- **异常与限制**：LLM 超时用模板；状态缺失用默认作息；意图冲突按优先级；不产生需要玩家实时响应的强制事件。
- **验收标准**：离线推演 72 小时行为合理；常规日 0 次 LLM 调用；特殊事件才出现 LLM 来源标记。
- **与其他功能的关系**：F13 执行；F18 汇总；F42 校验；F43 读记忆；F40 改情绪。
- **来源**：【原文】6.1、6.5；【补全】意图字段、最小间隔、离线零调用与优先级。

### F45 续写引擎 ｜ P1

- **目标与价值**：内容持续生长——新剧情/新事件/新图纸/离线报告，让玩家不必每次从零写；同时保持世界观一致。
- **操作流程**：选续写类型 → 输入世界观卡 + 记忆摘要 → 生成 3 条候选 → 玩家选/改 → 采用后落到对应模块。
- **界面与交互**：候选卡片；重生成；"采用"主按钮；来源标注"AI 续写"；空态说明会基于哪些记忆；失败给模板候选。
- **数据/内容结构**：`generation_job{id, type, universe_id, input_refs[], outputs[], adopted_id, ts}`。
- **核心规则与边界**：必须基于世界观卡与已发生记忆；不得擅自引入未设定角色（可建议但需确认）；每条候选过 F42；采用后才写入实体，未采用不污染数据。
- **异常与限制**：失败降级模板事件；超时提示；候选重复自动去重；跨宇宙续写需双方授权。
- **验收标准**：生成内容可被采用并出现在岛/纪念册；未采用不产生数据；角色与世界观不越界。
- **与其他功能的关系**：F19 剧本；F18 报告；F09 图纸；F42 校验；F43 记忆。
- **来源**：【原文】6.1；【补全】3 条候选、采用制、未采用不落库与跨宇宙授权。
