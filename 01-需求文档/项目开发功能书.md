## 1. 产品定位与核心循环

### 1.1 一句话定位

玩家用**角色卡**设计 OC，把 OC 放进**自建角色岛**，让像素小人在创造者划定的**OOC 边界**内自由生活；玩家可拼物件、接自己的 AI API 写小说，再让小人把小说**演出来**，或直接丢一段文本让小人照做。

### 1.2 核心循环（七步）

1. **造人**：填写角色卡（性格、价值观、禁忌、说话风格、知识边界），建立 OC。
2. **结网**：给 OC 连关系（亲属、朋友、对手等），关系进入行为与对话。
3. **建岛**：为这组 OC 建一座角色岛（一个宇宙），可多建、互相隔离。
4. **过日子**：小人按日程自由活动，玩家观察、点击互动；行动不得 OOC。
5. **添物件**：自己拼物件，或获取游戏预设物件；物件可摆放、赠送、被使用。
6. **长内容**：接用户自己的 API 生成小说，或直接给一段文本；系统把文本拆成可演的场。
7. **演绎与沉淀**：像素小人按场景/动作/对白/镜头演出，可倍速跳过；结果回到岛上与存档，反哺下一轮创作。

### 1.3 MVP 判定口径

“最小可玩闭环”只要求：**1 个用户 API 配置 + 2 个有关联的 OC + 1 座岛 + 1 件物件 + 1 次文本生成 + 1 场成功演绎 + 1 次可恢复存档 + 1 条社交最小链路（私密产出→公开页→加好友→岛门→手信）**。不要求多宇宙切换、联机约戏、广场市场、桌宠。

## 2. 系统分层总览

### 2.1 七层结构

| 层 | 名称 | 职责 | 不负责 |
|---|---|---|---|
| L1 | 角色内容层 | 角色卡、约束字段、关系网、世界观卡 | 不管画面与播放 |
| L2 | 世界层 | 角色岛、沙盘布局、多宇宙隔离、物件摆放 | 不管文本生成 |
| L3 | 行为层 | 日程、意图、自由活动、观察与互动 | 不直接调用外部 API |
| L4 | 边界层 | 可活动范围、行为白/黑名单、OOC 前置/后置校验、兜底 | 不决定剧情内容 |
| L5 | 生成层 | 外部 API 适配、密钥、长文分段、一致性、内容安全 | 不做动作映射 |
| L6 | 演绎层 | 文本清洗、场景拆分、动作映射、播放控制 | 不生成原文 |
| L7 | 持久与分享层 | 本地存档、云同步、导入导出、只读分享 | 不改写业务规则 |

### 2.2 依赖方向

`L1 → L2 → L3 → L4 → L5 → L6 → L7`；L4 横切 L3/L5/L6，任何生成或行为都必须过边界；L6 只能消费 L5 的结构化结果，不能反向改角色卡。

- **A 角色卡与 OC 关系网**：A01–A05（5）
- **B 角色岛沙盘与多宇宙**：B01–B06（6）

- **D 物件系统**：D01–D05（5）
- **E 文本生成与外部 API**：E01–E08（8）
- **F 文本演绎引擎**：F01–F08（8）
- **G 存档与分享**：G01–G06（6）
- **H 追加需求细化**：H01–H13（13）

## 3. 模块功能定义

### 3.1 A 角色卡与 OC 关系网

#### A01 角色卡创建 ｜ P0 ｜ 依赖：—
- **做什么**：在指定宇宙中新建一个 OC，填写姓名、身份、外貌、世界观归属，形成角色卡草稿；完成度达标后转为可用角色。
- **规则**：姓名必填且 1–12 字；角色卡必须绑定一个 `universe_id`；草稿可反复编辑，未完成的卡不能上岛、不能参与生成；一个宇宙至少 1 个 OC 才能建岛。
- **数据**：`oc{id, universe_id, name, profile, world_ref, status(draft/complete), version, created_at}`。
- **失败判定**：重名只提示不阻断；缺姓名/世界观归属不能完成；删除仍被关系或演出引用的 OC 时拒绝并列出引用。
- **验收标准**：同一宇宙能建 2 个 OC；草稿关闭后重开仍在；未完成卡在上岛入口被拦截。
- **来源**：【用户原话】“角色卡用于设计一个 OC”；【推导补全】草稿/完成态、必填与删除保护。

#### A02 OC 约束字段 ｜ P0 ｜ 依赖：A01
- **做什么**：为 OC 填写五类约束：性格、价值观、禁忌、说话风格、知识边界，作为 OOC 判定的唯一事实源。
- **规则**：性格至少 3 条且每条带例证；价值观至少 1 条；禁忌至少 1 条；说话风格需含口癖/句长/称呼；知识边界需分“已知/未知/绝不可知”。字段互相矛盾时标红并阻止“完成”。
- **数据**：`oc.constraints{personality[], values[], taboos[], speech{habit, sentence_length, address}, knowledge{known[], unknown[], forbidden[]}}`。
- **失败判定**：必填不足不能完成；AI 建议字段必须玩家确认才写入；矛盾未处理时禁止保存为完成态。
- **验收标准**：五类字段齐全；用 3 条越界提示词测试均被边界层拦截；修改后下一次生成生效。
- **来源**：【用户原话】“不能 OOC，且必须在创造者划定的边界内行动”；【推导补全】字段最小集与矛盾拦截。

#### A03 关系网建立 ｜ P0 ｜ 依赖：A01/A02
- **做什么**：为 OC 建立关系边，定义关系类型、方向性、强度，并可视化为关系网。
- **规则**：至少支持亲属/挚友/宿敌/上下级/暗恋，可扩展；方向性分单向/双向；强度 0–100；同一对 OC 同一类型唯一；禁止自连；没有关系的 OC 按“孤立 OC 默认表现”处理（见 H03）。
- **数据**：`relation{id, universe_id, from_oc, to_oc, type, direction(one_way/two_way), strength, notes, status}`。
- **失败判定**：重复边拒绝；方向矛盾提示；删除 OC 前必须处理关联边；跨宇宙关系默认禁止。
- **验收标准**：两个 OC 可连成一条关系并在图上显示；单向与双向视觉可区分；孤立 OC 有明确默认行为。
- **来源**：【用户原话】“OC 之间可以有关联（亲属、朋友、对手等关系网）”；【推导补全】类型清单、方向、强度与唯一性。

#### A04 关系影响行为与对白 ｜ P0 ｜ 依赖：A03
- **做什么**：让关系状态进入行为选择与对白生成，而不是只做展示。
- **规则**：关系类型决定可用互动模板；强度决定亲近/回避权重；单向关系只影响发起方；关系冲突时以当前场景与在场关系优先（见 H04 约束分层）。
- **数据**：`relation_state{relation_id, strength, last_event, flags}`；行为/对白请求携带关系摘要，不携带全量关系网。
- **失败判定**：关系缺失按“陌生”处理；引用失效用快照；关系值越界钳制。
- **验收标准**：同一场景、同一句输入，在“挚友/宿敌”两种关系下产出的动作或台词明显不同；单向暗恋只改变发起方表现。
- **来源**：【用户原话】关系网“影响其行为与对话”；【推导补全】权重、单向语义与降级。

#### A05 关系演化与一致性 ｜ P1 ｜ 依赖：A03/A04
- **做什么**：关系随事件建立、加深、破裂、修复，并保证关系网不自相矛盾。
- **规则**：事件类型决定变化方向；单次变化上限 ±20；双向关系可分别结算；破裂后保留历史；修复需新事件；一致性校验检查“亲属却标注宿敌且无解释”等冲突，冲突不自动改，交玩家确认。
- **数据**：`relation_event{relation_id, event_type, delta, reason, ref, ts}`；`relation.consistency_status`。
- **失败判定**：事件引用失效转摘要；冲突未确认时该边标记“待确认”，不进入生成上下文。
- **验收标准**：完成一次“和解”事件后强度上升且可追溯；矛盾关系被标记而不是静默采用；历史事件不可篡改。
- **来源**：【推导补全】关系生命周期与一致性校验；与 H01–H03 细化配套。

### 3.2 B 角色岛沙盘与多宇宙

#### B01 宇宙与角色岛创建 ｜ P0 ｜ 依赖：A01（已按 I 章修订）
- **做什么**：为一个 OC 组创建独立宇宙与角色岛；创建入口即填写世界观卡，卡通过后生成岛与默认布局。
- **规则**：宇宙与岛 1:1；名称 2–20 字；封面可选，缺省用岛缩略图；单宇宙容量保留为 OC 8 人/物件 64 件；没有已完成 OC 不能建岛；建岛必须先完成 I01 的四项基准；新建受 I09/I10 门控（关键剧情 + 等级）；已建宇宙数量不设硬上限，仅“同时运行/活跃 ≤3”（与 I11 一致）。
- **数据**：`universe{id, owner_id, name, cover, intro, world_card_id, status(active/archived), created_at}`；`island{universe_id, layout_id, capacity{ocs, items}}`。
- **失败判定**：无 OC 建岛拒绝；世界观卡未完成拒绝；未达等级或上一宇宙关键剧情未完成时入口锁定并给缺项；超过同时运行上限提示先归档；封面加载失败用默认图；删除宇宙需二次确认。
- **验收标准**：未填卡不能建宇宙；填卡通过后进入空岛引导；第 4 个已建宇宙可存在但仅 3 个同时运行；容量上限在添加第 9 个 OC 时生效。
- **来源**：【用户原话】“自建的角色岛”“角色岛允许多建”“建宇宙 = 填世界观卡”；【推导补全】容量、活跃上限与门控口径（由 I09/I10/I11 修订）。

#### B02 沙盘观察与点击互动 ｜ P0 ｜ 依赖：B01/B04
- **做什么**：玩家以俯视视角观察岛，缩放/平移，点击 OC 查看状态并发起互动。
- **规则**：点击 OC 打开互动菜单（打招呼/摸摸头/聊天/看状态）；台词与动作必须先过边界层；互动写事件与记忆；每日每 OC 互动 ≤20 次。
- **数据**：`interaction{id, oc_id, type, ts, result_text, mood_delta, memory_id}`；相机状态 `camera{zoom, cx, cy}`。
- **失败判定**：OC 不在场提示当前位置；AI 失败用模板；冷却中拒绝并显示剩余秒数；越界内容拦截并提示。
- **验收标准**：每次互动都有可见反馈并进事件流；重复点击不产生重复记忆；越界台词 0 放行。
- **来源**：【用户原话】“类似《模拟人生》的小人，自由活动、可被观察与互动”；【推导补全】互动项、冷却与上限。

#### B03 多宇宙隔离与切换 ｜ P1 ｜ 依赖：B01
- **做什么**：管理多个宇宙，切换时角色、物件、记忆、关系网互不串。
- **规则**：所有实体必须带 `universe_id`；切换只换视图，不复制数据；跨宇宙默认只读引用或显式复制（见 H09）；切换后上次位置保留。
- **数据**：`universe_switch_log`；实体的 `universe_id` 为强制字段；`copy_job{source, target, scope}`。
- **失败判定**：缺失 `universe_id` 的实体拒绝写入；切换失败保持原宇宙；复制冲突逐项确认。
- **验收标准**：在 A 宇宙建的 OC/物件不出现在 B；切换 3 次后两边数据无变化；跨宇宙引用有明确标记。
- **来源**：【用户原话】“角色岛允许多建，相当于不同的 OC 宇宙（多宇宙隔离）”；【推导补全】实体级隔离、切换与复制策略。

#### B04 居民自由活动 ｜ P0 ｜ 依赖：A02/B01
- **做什么**：OC 在岛内按日程与意图自由活动，玩家不操作时也持续生活。
- **规则**：行为由“感知→意图→候选→约束过滤→执行→后果与记忆”生成；日常以模板为主，特殊事件才调生成服务；行动必须在可活动范围与行为白名单内；不得 OOC。
- **数据**：`oc_runtime{oc_id, position, action, mood, schedule_id, updated_at}`；`behavior_intent{oc_id, intent, target, source(template/generation), ts}`。
- **失败判定**：无可用行为时执行“原地待机”；路径被阻挡则改选最近可达点；生成超时退回模板；连续越界触发兜底。
- **验收标准**：离线 8 小时后回岛，位置与动作符合作息；常规日 0 次外部生成调用；OC 不离开岛边界。
- **来源**：【用户原话】“自由活动……必须在创造者划定的边界内行动”；【推导补全】行为流程、模板优先与失败降级。

#### B05 岛布局与物件摆放 ｜ P1 ｜ 依赖：B02/D03
- **做什么**：玩家编辑岛的地块、道路、摆件位置，并决定哪些物件可交互。
- **规则**：网格放置；同格冲突自动错位；可交互物件必须绑定行为属性；摆放不改变 OC 关系；演出引发的布局变化单独记录、可回滚最近 5 次。
- **数据**：`island_layout{universe_id, grid_size, tiles[], placed_items[{item_id, x, y, rotation}]}`。
- **失败判定**：越界放置钳制到最近合法格；物件被删除则留占位并提示；布局保存失败保留草稿。
- **验收标准**：物件可放/移/收；同格不重叠；演出变更后可回滚；重新进入布局一致。
- **来源**：【用户原话】“岛上各种东西可以自己拼出来”；【推导补全】网格、冲突与回滚。

#### B06 时间同步与离线推演 ｜ P1 ｜ 依赖：B04
- **做什么**：用现实时间驱动岛内生活；玩家离线期间按时间差推演。
- **规则**：以服务端时间为准；离线最多推演 72 小时，超出只保留关键事件；推演不调用外部生成服务；回归生成 1 份离线报告（1–3 件事）。
- **数据**：`world_time{universe_id, last_tick_at, offset}`；`offline_report{from, to, events[], read}`。
- **失败判定**：系统时间跳变按服务端校正；推演失败保留上次状态；报告生成失败用规则事件兜底。
- **验收标准**：改本地时间不影响岛内时间；离线 8 小时报告与岛状态一致；报告每天只弹一次。
- **来源**：模拟人生式自由活动的时间基础；【推导补全】72 小时上限、报告与时间校正。

### 3.3 C 居民行为与 OOC 边界

#### C01 感知快照 ｜ P0 ｜ 依赖：B04
- **做什么**：为一次行为生成收集 OC 当前能感知到的信息，形成只读快照。
- **规则**：感知=时间/位置/在场 OC/关系/可见物件/最近事件/自身情绪；知识边界外的信息不得进入快照；不可见物件不进入。
- **数据**：`perception{oc_id, ts, place, present_ocs[], relations[], visible_items[], recent_events[], mood}`。
- **失败判定**：字段缺失用默认值；快照过期（>5 分钟）重新采集；采集失败则本轮只执行待机。
- **验收标准**：把 OC 看不到的物件移出视野后，其行为不再引用该物件；快照中不出现知识边界外信息。
- **来源**：【推导补全】“感知→意图→候选→过滤→执行→记忆”链路的第一环。

#### C02 意图生成 ｜ P0 ｜ 依赖：C01
- **做什么**：根据感知与日程产生 1 个主意图（散步/坐下/找某人/使用物件/休息等）。
- **规则**：日常意图用模板状态机；仅特殊事件（关系冲突、玩家互动、剧情触发）才调外部生成；意图必须可执行且不越界。
- **数据**：`behavior_intent{id, oc_id, intent, target, reason, source(template/generation), ts}`。
- **失败判定**：目标不存在/不可达则降级为同类安全意图；生成超时用模板；意图为空执行待机。
- **验收标准**：常规日 0 次外部调用；每次意图有来源标记；意图目标 100% 存在于当前岛。
- **来源**：【用户原话】自由活动；【推导补全】主意图、模板优先与特殊事件触发。

#### C03 候选行为与约束过滤 ｜ P0 ｜ 依赖：C02
- **做什么**：为意图生成 1–3 个候选行为，逐层过滤后选 1 个执行。
- **规则**：过滤顺序=角色卡硬约束→创造者边界→世界规则→当前场景与在场关系；任一硬约束命中即淘汰；全部淘汰则走兜底行为（见 C07）。
- **数据**：`behavior_candidate{intent_id, action, target, score, rejected_by[]}`；`selected_action`。
- **失败判定**：候选为空→兜底；过滤服务异常→保守执行待机；候选分数相同按确定性优先级。
- **验收标准**：构造“禁忌动作”候选时 100% 被淘汰；候选全部淘汰时一定出现兜底行为；同一输入选择稳定。
- **来源**：【用户原话】“必须在创造者划定的边界内行动”；【推导补全】分层过滤顺序与确定性选择。

#### C04 可活动范围与行为白/黑名单 ｜ P0 ｜ 依赖：B05
- **做什么**：定义 OC 能去哪里、能做什么、绝不可以做什么。
- **规则**：可活动范围=岛内可行走网格 + 允许区域；行为白名单=可主动执行的动作；黑名单=禁止动作（含暴力、破坏、越权互动）；范围与名单按宇宙设定，跨宇宙不继承。
- **数据**：`action_policy{universe_id, walkable_grid, allowed_zones[], whitelist[], blacklist[], updated_at}`。
- **失败判定**：越界路径拒绝并寻最近合法点；白名单为空用系统默认安全集；黑名单与白名单冲突时黑名单优先。
- **验收标准**：OC 不会走出可行走区域；黑名单动作 100% 不可执行；修改名单后下一次行为生效。
- **来源**：【用户原话】“在创造者划定的边界内行动”；【推导补全】范围、白/黑名单与优先级。

#### C05 世界规则 ｜ P1 ｜ 依赖：B01
- **做什么**：定义该宇宙的基础规则（时间流逝、物理常识、社会礼仪、世界观禁忌），约束所有 OC。
- **规则**：世界规则优先于角色卡“软设定”，低于角色卡“硬禁忌”；规则冲突时按“更严格者”执行；玩家可在宇宙设置中增删，但不得删除系统安全规则。
- **数据**：`world_rule{universe_id, rule_id, level(hard/soft), text, scope(all/oc/scene), enabled}`。
- **失败判定**：规则文本为空不生效；规则冲突标记待确认；违反世界规则的生成必须拦截。
- **验收标准**：开启“禁止夜间外出”后夜间行为被限制；角色卡软设定不能覆盖硬规则；系统安全规则不可删除。
- **来源**：【推导补全】世界规则层；与 C03 过滤链配套。

#### C06 OOC 生成前置约束 ｜ P0 ｜ 依赖：A02/C05
- **做什么**：在调用生成前，把角色卡与边界组装成约束包，明确“必须/禁止/未知”。
- **规则**：约束包含性格、价值观、禁忌、说话风格、知识边界、世界规则、当前场景、在场关系；硬禁忌与黑名单以“禁止”表达；知识边界外以“不可知”表达；约束包不向玩家展示全文。
- **数据**：`boundary_context{oc_id, hard_rules[], soft_rules[], forbidden[], unknown[], scene_ref, relation_summary}`；哈希随请求存档。
- **失败判定**：约束包缺角色卡→拒绝生成；版本不一致→用当前版本并提示；组装失败→只允许模板行为。
- **验收标准**：每次生成请求都带约束包哈希；修改禁忌后下一次生成约束包变化；缺角色卡时生成被拒。
- **来源**：【用户原话】“不能 OOC”；【推导补全】前置约束包与版本哈希。

#### C07 OOC 生成后校验、重试与兜底 ｜ P0 ｜ 依赖：C06
- **做什么**：对生成结果做二次校验，命中则重写/拦截，最终失败走兜底。
- **规则**：两段式校验；硬禁忌命中=直接拦截；软设定命中=重写；同一结果最多重试 2 次；仍失败则执行安全兜底（沉默/转移话题/待机），并记录越界事件。
- **数据**：`boundary_check{id, oc_id, input_ref, output_ref, hit_rule, action(retry/rewrite/block/fallback), ts}`。
- **失败判定**：校验服务不可用按保守拦截；重试耗尽不返回原文；兜底行为不得再触发新生成。
- **验收标准**：构造 10 条越界输出 0 泄漏；重试次数不超 2；兜底行为可被玩家看到但不破坏状态。
- **来源**：【用户原话】“不能 OOC”；【推导补全】后置校验、重试上限、兜底与日志。

#### C08 玩家诱导越界与回滚 ｜ P1 ｜ 依赖：C07
- **做什么**：玩家故意让 OC 做禁忌行为时，系统以角色内方式拒绝或改写，并支持回滚已发生的越界。
- **规则**：诱导请求先过 C06；OC 以符合人设的方式拒绝（转移话题/沉默/离开），不得直接出戏报错；若越界已执行，回滚到越界前快照并保留事件日志；同一 OC 每日诱导拦截日志 ≤5 条。
- **数据**：`ooc_incident{id, oc_id, trigger, blocked_intent, resolution(refuse/rewrite/rollback), snapshot_ref, ts}`。
- **失败判定**：回滚快照缺失则只标记事件不撤销；连续诱导触发冷却；日志不得复述禁忌原文。
- **验收标准**：玩家强行命令禁忌行为时 OC 不出戏且不执行；已执行越界可回滚；事件日志可查且不泄私密。
- **来源**：【用户原话】“不能 OOC”；【推导补全】诱导处理、回滚与日志边界。

### 3.4 D 物件系统

#### D01 自拼物件 ｜ P0 ｜ 依赖：B05
- **做什么**：玩家用像素/拼豆部件组合出物件，形成可摆放、可赠送、可进戏的自家物件。
- **规则**：物件由部件拼装（底座/主体/装饰/交互点）；尺寸受限（如 16×16、32×32）；必须有名称与至少 1 个部件；产出归属玩家自创并记录作者；同一配方可复用，不消耗原件。
- **数据**：`item{id, universe_id, name, matrix, parts[], recipe_id?, source(diy/preset), author, created_at}`。
- **失败判定**：空部件不能保存；超出尺寸拒绝；名称重复提示；保存失败保留草稿。
- **验收标准**：能拼出 1 件物件并放入岛；物件可再次编辑；作者与来源正确。
- **来源**：【用户原话】“岛上各种东西可以自己拼出来”；【推导补全】部件、尺寸、归属与配方复用。

#### D02 预设物件获取 ｜ P0 ｜ 依赖：B01
- **做什么**：通过初始赠送、任务奖励、商店、导入获得游戏预设物件。
- **规则**：每个新宇宙初始赠送 3–5 件基础物件；任务奖励一次性；商店只卖外观与预设，不卖数值；导入需格式校验与来源标注。
- **数据**：`preset_catalog{id, name, category, tags[], acquisition(initial/task/shop/import), price?, license}`；`grant{user, universe, preset_id, source, ts}`。
- **失败判定**：重复领取不重复发放；商店余额不足拒绝；导入格式错误不落库并提示。
- **验收标准**：新岛有初始物件；完成一次任务获得对应物件；同一奖励不重复到账。
- **来源**：【用户原话】“也可以通过其他方式获取游戏预设的物件”；【推导补全】四种渠道、一次性与导入校验。

#### D03 物件属性与可用性 ｜ P0 ｜ 依赖：D01/D02
- **做什么**：定义物件的分类、标签、行为属性和适用范围。
- **规则**：分类=家具/装饰/道具/食物/特殊；行为属性=可坐/可交互/可破坏/可携带/可进戏；可用性=允许的宇宙/场景/角色；跨宇宙物件默认不可用，需显式授权。
- **数据**：`item.meta{category, tags[], behaviors{sit,interact,breakable,carry,stage}, availability{universe_ids[], scene_types[], oc_ids[]}}`。
- **失败判定**：场景不匹配时不可摆放；角色不匹配时不可使用；属性冲突（可破坏但不可交互）标记待确认。
- **验收标准**：可坐物件能被 OC 坐下；不可用物件在错误场景置灰；跨宇宙未授权不可用。
- **来源**：【推导补全】分类、行为属性与可用性判定；与 H12 细化配套。

#### D04 持有、赠送与归属 ｜ P1 ｜ 依赖：D03
- **做什么**：物件进入背包、被赠予、被收回，归属关系清晰。
- **规则**：物件有唯一归属；岛内赠送转移所有权；复制类流转（如手信）需显式选择；已赠物件不可重复赠送；删除 OC 时其持有物件回到玩家背包。
- **数据**：`ownership{item_id, owner_type(player/oc), owner_id, since}`；`transfer{from, to, mode(move/copy), ts}`。
- **失败判定**：重复赠送拒绝；归属冲突以最新确认为准并留痕；背包满拒绝并提示。
- **验收标准**：赠送后原持有者失去、接收者获得；复制流转保留原件；归属记录可追溯。
- **来源**：【用户原话】物件可获取；【推导补全】归属、转移/复制与删除回收。

#### D05 物件影响行为与记忆 ｜ P1 ｜ 依赖：D03
- **做什么**：物件不只是摆件，能触发 OC 行为、情绪与记忆。
- **规则**：可交互物件进入行为候选；偏好由角色卡标签与物件标签匹配；使用后写记忆；破坏类物件需二次确认且不得伤害 OC。
- **数据**：`item_event{item_id, oc_id, action, mood_delta, memory_id, ts}`；`preference{oc_id, tag, weight}`。
- **失败判定**：无匹配行为则忽略该物件；交互失败回退到观察；破坏事件不产生不可逆伤害。
- **验收标准**：放一把椅子后 OC 会主动坐下；送喜欢的物件情绪上升并可被记忆引用；破坏行为有确认与记录。
- **来源**：【用户原话】小人可被观察与互动、岛上有物件；【推导补全】偏好匹配、记忆写入与安全限制。

### 3.5 E 文本生成与外部 API

#### E01 用户 API 配置 ｜ P0 ｜ 依赖：—
- **做什么**：玩家接入自己的生成服务，填写服务商、地址、模型、密钥，设为默认。
- **规则**：至少支持“兼容通用协议的服务商 + 自定义地址”两类；密钥只本地保存；配置可启用/停用；一个账号可存多套配置，但同一时间只有 1 个默认；保存前必须“测试连接”。
- **数据**：`api_config{id, user_id, provider, base_url, model, key_ref, enabled, is_default, last_test_at, last_test_result}`。
- **失败判定**：地址/模型为空不能保存；测试失败不设为默认；密钥格式明显错误提示但不记录明文。
- **验收标准**：能保存 2 套配置并切换默认；错误配置无法启用；重启后配置仍在。
- **来源**：【用户原话】“可接入用户自己的 API”；【推导补全】多配置、默认项与测试门槛。

#### E02 多服务商适配 ｜ P0 ｜ 依赖：E01
- **做什么**：把不同服务商的请求/响应归一化为内部统一结果，屏蔽差异。
- **规则**：能力矩阵至少区分：文本生成、结构化输出、长上下文、流式返回；不支持的能力必须显式降级；统一结果包含文本、结构化字段、用量、结束原因；厂商特有错误映射为统一错误码。
- **数据**：`provider_profile{id, capabilities[], limits{context, rpm, tpm}, error_map}`；`generation_result{text, structured?, usage, finish_reason, raw_status}`。
- **失败判定**：能力不支持→走降级路径；字段缺失→标记部分成功；错误码未知→按可重试处理并记录。
- **验收标准**：同一提示词在 2 家服务商上都能得到可用结果；不支持结构化的服务商自动走文本解析；错误码可读。
- **来源**：【推导补全】多服务商适配；与 E05/E06 配套。

#### E03 密钥本地保存与不外泄 ｜ P0 ｜ 依赖：E01
- **做什么**：保证用户密钥只存在本地受保护区域，不上传、不进日志、不随分享导出。
- **规则**：密钥加密后本地保存；界面只显示掩码；日志/崩溃报告/导出包一律脱敏；删除配置即删除密钥；云端只存“是否有配置”，不存密钥。
- **数据**：`key_ref{id, masked, storage_scope(local_only), created_at}`；任何导出包不得包含 `key_ref` 明文。
- **失败判定**：检测到明文密钥进入日志即阻断该日志写入；导出时命中密钥字段直接剔除并提示；密钥解密失败要求重新填写。
- **验收标准**：抓取日志与导出包均无明文密钥；删除配置后无法再调用；换设备需重新填密钥。
- **来源**：【用户原话】“接入用户自己的 API”；【推导补全】密钥安全边界与脱敏验收。

#### E04 超时、限流与重试 ｜ P0 ｜ 依赖：E02
- **做什么**：为生成调用定义稳定的失败处理，避免卡死与重复扣费。
- **规则**：普通请求超时 30 秒、长文 120 秒；429/5xx 可重试，最多 2 次，指数退避；401/403 不重试；连续 3 次失败熔断 10 分钟；重试必须幂等，不得重复落库。
- **数据**：`generation_attempt{job_id, attempt, error_code, latency, will_retry, ts}`；`circuit_state{config_id, open_until}`。
- **失败判定**：超时→重试或降级模板；熔断中→直接提示“稍后再试”；取消后不再重试。
- **验收标准**：模拟 429 时最多重试 2 次；401 立即停止；熔断期间无新请求；同一任务不产生两条成品。
- **来源**：【推导补全】超时、限流、重试与熔断。

#### E05 长文分段与上下文记忆 ｜ P0 ｜ 依赖：E02
- **做什么**：把长篇小说生成拆成可控段落，跨段保持设定与剧情连续。
- **规则**：先产出大纲，再按场景分段生成；分段边界优先按场景/时间/地点；每段携带“世界观摘要 + 角色摘要 + 前情摘要 + 本章目标”；滚动摘要长度受限；超长请求必须分段，不得整本一次生成。
- **数据**：`generation_job{id, universe_id, type, outline, segments[], rolling_summary, status}`；`segment{index, goal, context_refs[], output}`。
- **失败判定**：分段失败保留已完成段；摘要超限触发压缩；上下文缺失用角色卡摘要兜底；中断可从下一段续。
- **验收标准**：生成 10 段长文时角色名/关系/世界观不漂移；中断后可续；每段都能独立追溯上下文。
- **来源**：【推导补全】长文分段、滚动摘要与断点续写。

#### E06 角色一致性维护 ｜ P0 ｜ 依赖：A02/E05
- **做什么**：在长文与多次生成中维持角色性格、说话风格、关系与知识边界一致。
- **规则**：每次生成携带“角色圣经”（精简角色卡 + 当前关系 + 已发生关键事件）；生成后做一致性检查（称谓、口癖、关系、已知信息）；检查失败重写 1 次，仍失败标记“待修订”不静默通过。
- **数据**：`character_bible{oc_id, version, summary, speech_rules[], relation_summary, key_facts[]}`；`consistency_report{job_id, issues[], action}`。
- **失败判定**：角色圣经版本过期用最新版并提示；一致性检查不可用则只做硬边界校验；无法修复标记问题段落。
- **验收标准**：同一角色跨 5 段生成口癖与称谓一致；关系变化后新段落引用新关系；问题段落可定位。
- **来源**：【用户原话】“依据角色卡的世界观与要求生成小说”；【推导补全】角色圣经、一致性与待修订标记。

#### E07 内容安全兜底 ｜ P0 ｜ 依赖：E02
- **做什么**：对输入与输出做内容安全过滤，避免违法、伤害、未成年人不宜内容进入成品。
- **规则**：输入先过滤再发送；输出再过滤后才可落库/演绎；命中阻断类直接拒绝并给中性提示；命中需改写类先改写；安全过滤不可被用户配置关闭；不把原文回显给用户。
- **数据**：`safety_check{job_id, stage(input/output), category, action(block/rewrite/pass), ts}`。
- **失败判定**：安全服务不可用时保守阻断；误判可申诉；过滤结果不进入公开分享。
- **验收标准**：构造违规输入 0 落库；正常输入不被大面积误杀；拦截提示不泄露违规原文。
- **来源**：【推导补全】生成内容安全兜底。

#### E08 生成任务管理 ｜ P1 ｜ 依赖：E04/E05
- **做什么**：让长文生成可见、可取消、可恢复，避免“点了没反应”。
- **规则**：任务状态=`排队/生成中/部分完成/完成/失败/已取消`；显示进度与已用额度；可取消，取消后保留已完成段；失败可重试但不重复计费；任务列表可回看。
- **数据**：`job{id, user_id, universe_id, type, status, progress, segments_done, error_code, created_at}`。
- **失败判定**：取消中不允许新分段开始；重复点击创建幂等；任务超时置失败并保留部分结果。
- **验收标准**：长文任务进度可见；取消 5 秒内生效；部分完成可继续；不产生重复任务。
- **来源**：【推导补全】任务状态机、取消与幂等。

### 3.6 F 文本演绎引擎

#### F01 文本输入与清洗 ｜ P0 ｜ 依赖：E05
- **做什么**：接收生成的小说或玩家直接粘贴的文本，清洗成可解析的剧本文本。
- **规则**：支持纯文本与结构化段落；保留原文快照；去除多余空行/控制字符；按段落与引号识别对白；超长文本先分段；不得改动原文语义。
- **数据**：`script_source{id, universe_id, origin(generated/pasted), raw_text, clean_text, lang, length}`。
- **失败判定**：空文本拒绝；全是乱码提示；超长提示分段；清洗失败回退原文并标记。
- **验收标准**：同一文本清洗前后可逐段对照；对白识别准确；原文快照可恢复。
- **来源**：【用户原话】“生成的文章可由像素小人演绎”“也可以直接丢文本让小人照此行动”；【推导补全】清洗与原文快照。

#### F02 场景拆分 ｜ P0 ｜ 依赖：F01
- **做什么**：把文本切成场景，每个场景有地点、时间、在场角色与目标。
- **规则**：按地点/时间/段落主题变化切分；一个场景至少 1 个角色与 1 个动作或对白；场景数上限可配；无法判断时按段落合并，不硬切。
- **数据**：`scene{id, script_id, index, location, time, actors[], goal, beats[]}`。
- **失败判定**：角色无法匹配→标记待选；场景为空→并入上一场；切分过碎→合并相邻短场景。
- **验收标准**：10 段文本能稳定切成 3–6 个场景；每个场景角色可追溯；切分结果可手动调整。
- **来源**：【推导补全】场景拆分规则与兜底。

#### F03 角色/动作/对白/镜头抽取 ｜ P0 ｜ 依赖：F02
- **做什么**：把每个场景拆成可执行节拍（beat）：谁、做什么、说什么、镜头看哪里。
- **规则**：每个 beat 必须含角色与至少 1 个动作或对白；对白保留说话人；动作用动词短语；镜头只允许预定义景别（全景/中景/近景/特写）；旁白单独标记。
- **数据**：`beat{id, scene_id, actor, action, dialogue, emotion, camera, duration_hint}`。
- **失败判定**：说话人不明→按上下文最近角色；动作缺失→补“站立”；镜头非法→默认中景；无法解析→转旁白。
- **验收标准**：抽取结果每个 beat 都能被 F04 执行；对白与原文一致；镜头值在允许集合内。
- **来源**：【推导补全】文本→结构抽取；与 F04 动作库配套。

#### F04 动作映射到像素小人 ｜ P0 ｜ 依赖：F03
- **做什么**：把自然语言动作映射为像素小人可执行的动作与姿势，保证能演。
- **规则**：动作库至少含站/坐/走/跑/蹲/抬手/拥抱/争执/转身/离场；一个 beat 只映射 1 个主动作 + 最多 1 个表情；无法映射的动作降级为“旁白 + 站立”；移动类动作需给目标点。
- **数据**：`action_map{beat_id, action_id, pose_id, target, expression, fallback_text}`；`pose_library{id, name, loop, duration}`。
- **失败判定**：动作库无匹配→降级旁白；目标不可达→原地动作；角色外观缺失→占位小人。
- **验收标准**：动作库内动作 100% 可执行；库外动作有明确降级；同一 beat 重演动作一致。
- **来源**：【用户原话】“由像素小人演绎”；【推导补全】动作库、单主动作与降级规则。

#### F05 播放、倍速与跳过 ｜ P0 ｜ 依赖：F04
- **做什么**：按场景顺序播放演绎，支持暂停、倍速、跳过、进度与重播。
- **规则**：默认 1x；倍速 0.5/1/1.5/2x；跳过以场景为单位，不跳角色状态；暂停保留当前 beat；播放结束写演绎记录；同一剧本重播结果一致。
- **数据**：`playback{performance_id, scene_index, beat_index, speed, state(playing/paused/skipped/finished)}`。
- **失败判定**：资源缺失→占位继续；播放中断→从最近 beat 续；跳过最后一场景→直接结束。
- **验收标准**：倍速与跳过可用；中断可续播；同一剧本两次播放结果一致。
- **来源**：【用户原话】“可由像素小人演绎”；【推导补全】倍速档位、跳过粒度与续播。

#### F06 直接文本驱动行动（简化路径） ｜ P0 ｜ 依赖：F01/F04
- **做什么**：不做完整小说解析，玩家直接输入“去坐下/走向某人/拿起花”这类指令，小人立即执行。
- **规则**：一行一条指令；指令=角色 + 动作 + 可选目标；只接受动作库内动作；无法识别时提示可用动作，不猜测执行；执行前过边界；执行后写一条事件。
- **数据**：`directive{id, oc_id, action_id, target, raw_text, status(accepted/rejected/executed)}`。
- **失败判定**：动作不在库→拒绝并给候选；目标不存在→拒绝；越界→拒绝或角色内拒绝。
- **验收标准**：输入合法指令后 1 个动作周期内执行；非法指令有可读提示；执行结果可回看。
- **来源**：【用户原话】“也可以直接丢文本让小人照此行动”；【推导补全】单行指令、动作白名单与拒绝策略。

#### F07 演绎失败降级 ｜ P1 ｜ 依赖：F05
- **做什么**：当文本无法完整演绎时，保证“能演的部分演、不能演的说明清楚”，不静默失败。
- **规则**：缺角色→用占位并标“未登场”；缺动作→旁白 + 站立；缺场景→整篇合成单场景；缺资源→占位背景；不允许跳过整段而不告知。
- **数据**：`performance_issue{performance_id, scene_id, beat_id, issue_type, fallback_used, ts}`。
- **失败判定**：降级后仍不可播放→转为“文本朗读模式”；连续 3 个 beat 降级→提示拆分建议。
- **验收标准**：任何文本都能产出“可播放或可朗读”的结果；降级点在结果中可见；不出现空白舞台。
- **来源**：【推导补全】演绎降级与可见性。

#### F08 演绎结果记录 ｜ P1 ｜ 依赖：F05
- **做什么**：记录每场演绎的场景、角色、时长、降级点与产出，供回看与再创作。
- **规则**：记录只追加；保留剧本版本与角色矩阵版本；可重播；删除需二次确认；演绎结果可回到岛/纪念册（见 G）。
- **数据**：`performance{id, script_id, scene_versions[], actors[], duration, issues[], created_at}`。
- **失败判定**：版本缺失用快照；记录写入失败本地暂存；重复播放不重复写记录。
- **验收标准**：每场演绎都有记录且可重播；降级点可查；删除后不再出现在列表。
- **来源**：【推导补全】演绎记录与版本快照。

### 3.7 G 存档与分享

#### G01 本地优先与账号 ｜ P0 ｜ 依赖：—
- **做什么**：无账号也能完成建卡、建岛、生成与演绎；登录后才启用云同步与分享。
- **规则**：本地生成匿名 ID；账号可后绑定；未登录数据归本地；登录后询问是否合并；合并冲突逐项确认；不同账号数据不混。
- **数据**：`account{id, type(anonymous/registered), local_id?, cloud_id?, merged_at}`；`owner_scope(local/cloud)`。
- **失败判定**：合并失败保留本地副本；账号退出不清本地；本地 ID 冲突重新生成并提示。
- **验收标准**：断网可完成 MVP 全流程；登录后本地数据不丢；合并可撤销。
- **来源**：【推导补全】本地优先与账号边界。

#### G02 自动存档与版本 ｜ P0 ｜ 依赖：G01
- **做什么**：所有写操作自动保存，支持崩溃恢复与历史快照。
- **规则**：操作后 3 秒防抖落盘；关键节点（建卡完成/建岛/演绎结束）额外快照；每个宇宙保留最近 20 个快照；删除软删 30 天；恢复需二次确认。
- **数据**：`save_snapshot{id, universe_id, entity_type, entity_id, version, hash, created_at}`；`draft{entity_type, entity_id, payload, updated_at}`。
- **失败判定**：存储不足提示清理；落盘失败保留内存并告警；快照损坏跳过并记录。
- **验收标准**：演绎中杀进程重开回到最近节点；可恢复 20 个版本；软删内容 30 天内可找回。
- **来源**：【推导补全】自动存档、快照与恢复。

#### G03 云同步与多端 ｜ P1 ｜ 依赖：G01/G02
- **做什么**：登录后把宇宙、角色、物件、关系、演绎记录同步到云端，支持多设备继续。
- **规则**：实体级增量同步；密钥永不云同步；纪念册/演绎只追加；冲突以版本号+时间判定，纪念册冲突人工选；离线排队，联网补传。
- **数据**：`sync_state{entity_type, entity_id, version, synced_at, dirty}`；`sync_conflict{entity, local_version, cloud_version}`。
- **失败判定**：同步失败重试 3 次转手动；冲突未解决时该实体只读；云端不可用不影响本地。
- **验收标准**：两端编辑同一 OC 时不静默覆盖；换设备登录后数据完整；密钥不出现在云端。
- **来源**：【推导补全】增量同步、冲突与密钥隔离。

#### G04 导入导出 ｜ P1 ｜ 依赖：G02
- **做什么**：把宇宙/角色/物件/剧本导出为可迁移文件，或从文件导入。
- **规则**：导出包含清单、版本、实体数据与必要素材；不含密钥、账号凭证、他人未授权内容；导入先校验版本与 `universe_id`，再逐项预览；支持只导入部分条目。
- **数据**：`export_job{id, scope, format, status, file_ref}`；`import_job{id, source, validation, items[], status}`。
- **失败判定**：版本不兼容拒绝并说明；素材缺失用占位；导入中途失败回滚已导入项。
- **验收标准**：导出再导入后 OC/关系/物件一致；导入包无密钥；部分导入不污染现有宇宙。
- **来源**：【推导补全】导入导出与版本校验。

#### G05 只读分享 ｜ P2 ｜ 依赖：G02
- **做什么**：分享角色卡、岛缩略图或演绎，访客只读，不能进入岛或修改数据。
- **规则**：默认私密；分享生成快照链接；可设可见字段；可随时下架；他人 OC 需授权；分享页不包含记忆原文与密钥。
- **数据**：`share{id, owner, scope, snapshot, visibility, expires_at, revoked}`。
- **失败判定**：无权限内容剔除；链接失效 404；下架即时生效。
- **验收标准**：访客只能看快照；下架后链接不可用；未授权他人 OC 不可分享。
- **来源**：【推导补全】只读分享与授权。

#### G06 删除与隐私 ｜ P1 ｜ 依赖：G01/G03
- **做什么**：提供宇宙/OC/账号的删除与隐私控制。
- **规则**：删除分“归档/软删/永久删除”；软删 30 天；永久删除需输入名称确认；删除 OC 前处理关系与演出引用；账号注销同时删除云端数据；本地密钥单独擦除。
- **数据**：`deletion_request{scope, target_id, mode, requested_at, purge_at}`；`privacy_setting{share_default, telemetry, ai_log_retention}`。
- **失败判定**：有引用未处理时拒绝删除并列出；永久删除不可恢复；注销后本地残留需提示清理。
- **验收标准**：软删可恢复；永久删除不可找回；注销后云端查不到数据；密钥被擦除。
- **来源**：【推导补全】删除分级与隐私控制。

## 3.8 H 追加需求细化

> 本章为用户追加需求专项；与 A/B/C/D 重叠处以本章为准。编号 H01–H13（H01–H12 为四块需求细化，H13 为人物形象编辑器追加）。

### 3.8.1 角色卡 OC 关联设定

#### H01 关系类型与方向性 ｜ P0 ｜ 依赖：A01/A02
- **做什么**：定义关系类型体系与方向性，保证“亲属/挚友/宿敌/上下级/暗恋”等关系能准确表达。
- **规则**：内置类型=亲属（父/母/子/女/兄弟姐妹/其他亲属）、挚友、宿敌、上下级、暗恋、伴侣、师徒、同事、前任；支持自定义类型但必须选一个“语义族”（亲缘/友缘/敌对/权力/爱慕）。方向性=单向/双向；双向时 A→B 与 B→A 的强度分别记录；单向时未指向的一方按“不知情/无感”处理。同一对 OC 可同时存在多种类型（如“上下级 + 暗恋”），但必须显式叠加。
- **数据**：`relation_type{code, label, family, built_in}`；`relation{from_oc, to_oc, type_code, direction(one_way/two_way), strength_ab, strength_ba, visibility, notes}`。
- **失败判定**：同一对 OC 同一类型重复拒绝；方向与强度矛盾（单向却填双向强度）提示；自定义类型缺语义族拒绝。
- **验收标准**：5 种内置类型均可建立；单向/双向在数据与视觉上可区分；叠加类型不覆盖原类型。
- **来源**：【用户原话】“亲属、朋友、对手等关系网”；【推导补全】类型清单、语义族、方向与叠加规则。

#### H02 关系强度与事件演化 ｜ P0 ｜ 依赖：H01
- **做什么**：用强度表达亲密度，用事件驱动建立、加深、破裂、修复，并让关系影响行为与对白。
- **规则**：强度 0–100，分陌生/点头/熟悉/亲近/深厚/羁绊六档；事件类型=建立、加深、破裂、修复、反转；单次变化 ±20，双向分别结算；破裂后强度保留但状态置 `broken`，修复必须由新事件触发；关系影响=可用互动模板、亲近/回避权重、称呼与台词语气；关系变化必须写事件，不能只改数值。
- **数据**：`relation_event{id, relation_id, event_type, delta_ab, delta_ba, reason, ref, ts}`；`relation_state{relation_id, strength_ab, strength_ba, status, flags[]}`。
- **失败判定**：无事件直接改强度拒绝；事件引用失效转摘要；破裂未标记导致生成仍用亲密模板时判定失败。
- **验收标准**：完成“建立→加深→破裂→修复”四事件后状态可追溯；挚友与宿敌在同一场景产出不同台词；强度越界钳制。
- **来源**：【用户原话】关系网“影响其行为与对话”；【推导补全】六档、±20、四类事件与状态机。

#### H03 关系一致性校验与孤立 OC ｜ P0 ｜ 依赖：H01/H02
- **做什么**：检测互相矛盾的关系设定，并定义没有任何关系的 OC 如何表现。
- **规则**：一致性检查至少覆盖：亲属却无任何往来解释、同时“挚友+宿敌”且无叠加说明、单向暗恋被当作双向、上下级但称呼平级、已破裂仍使用亲密模板；冲突不自动改，弹出“保留为复杂关系/修改类型/补说明/标记非正典”四选一。孤立 OC 默认=礼貌疏离、优先自处、不虚构关系、不主动提及不存在的人；可通过事件自然建立关系。
- **数据**：`consistency_report{relation_id, issues[], resolution(keep_complex/change_type/add_note/non_canon), resolved_by, ts}`；`oc.relation_status(isolated/connected)`。
- **失败判定**：未处理的冲突边不进入生成上下文；孤立 OC 生成出现“我朋友”等虚构关系判定失败。
- **验收标准**：构造 5 类矛盾均被标记；四种处理方式可用；孤立 OC 连续 10 次生成不虚构关系。
- **来源**：【用户原话】关系网与“不能 OOC”；【推导补全】一致性检查项、处理方式与孤立默认。

### 3.8.2 角色岛内“不 OOC 的自由行动”边界

#### H04 约束四层与优先级 ｜ P0 ｜ 依赖：A02/C04/C05
- **做什么**：把约束分为四层并定义冲突时的优先级。
- **规则**：第一层角色卡硬约束（性格底线/价值观/禁忌/知识边界/说话风格）→ 第二层创造者边界（活动范围/白黑名单/场景限制）→ 第三层世界规则（物理/社会/世界观禁忌）→ 第四层当前场景与在场关系（临时上下文）。优先级按序；同层冲突取“更严格者”；创造者边界只能加严，不能放宽角色硬禁忌；场景关系只能影响语气与选择，不能推翻前三层。
- **数据**：`constraint_stack{oc_id, layers[{level, source, rules[], strictness}], effective_order[]}`。
- **失败判定**：层缺失按默认安全集补；规则冲突未裁决则按更严格者执行并标记；任何层被绕过判定失败。
- **验收标准**：构造“角色禁忌 vs 创造者允许”冲突时禁忌胜出；世界规则与场景关系冲突时世界规则胜出；四层均有命中日志。
- **来源**：【用户原话】“必须在创造者划定的边界内行动”；【推导补全】四层顺序与“只能加严”原则。

#### H05 行为生成六步流程 ｜ P0 ｜ 依赖：H04/B04
- **做什么**：把一次自由行动拆成可审计的六步：感知→意图→候选行为→约束过滤→执行→后果与记忆。
- **规则**：每步产出一个可追溯对象；感知只取可见信息；意图只出 1 个主意图；候选 1–3 个；过滤按 H04 顺序；执行前做最终边界确认；执行后必写后果与记忆；单次决策时间预算固定，超时走兜底。
- **数据**：`behavior_trace{id, oc_id, perception_ref, intent_ref, candidates[], filtered[], selected, execution, consequence_ref, memory_ref, ts}`。
- **失败判定**：任一步为空→进入兜底并记录断点；执行与选择不一致→回滚；记忆未写→补写或标记失败。
- **验收标准**：每次行动都有完整 trace；任一步失败可定位；同一感知与约束下选择稳定。
- **来源**：【推导补全】六步链路与可审计 trace。

#### H06 越界判定、兜底与即兴尺度 ｜ P0 ｜ 依赖：H05
- **做什么**：定义什么算越界、越界后怎么退，以及允许多大程度的“边界内即兴”。
- **规则**：越界分三级：硬越界（触犯禁忌/黑名单/世界硬规则）→立即拦截；软越界（偏离性格/语气过火）→改写一次；漂移（连续偏离但未触线）→收敛并提示。兜底行为=沉默/转移话题/离开/原地待机/请求确认，按场景选最不破坏状态的一种。即兴尺度=允许在语气、措辞、局部动作上发挥；不得新增世界观事实、不得改变关系、不得获知知识边界外信息、不得替玩家做决定；单次即兴最多连续 2 个节拍。
- **数据**：`boundary_verdict{level(hard/soft/drift), rule_hit, action(block/rewrite/converge/fallback), fallback_type, ts}`。
- **失败判定**：硬越界未拦截判定失败；兜底后仍继续生成判定失败；即兴超出尺度按软越界处理。
- **验收标准**：三级越界各自触发正确动作；兜底后状态稳定；2 个节拍内即兴可接受、超过即收敛。
- **来源**：【用户原话】“不能 OOC”“在边界内行动”；【推导补全】三级判定、兜底类型与即兴尺度。

#### H07 玩家诱导越界与 OOC 回滚 ｜ P1 ｜ 依赖：H06/C08
- **做什么**：玩家用命令、剧情或对话诱导 OC 越界时，系统以角色内方式处理，并支持回滚。
- **规则**：先过 H04 四层；OC 用符合人设的方式拒绝（沉默/转移/离开/反问），不得直接弹系统错误；诱导成功但已越界→回滚到越界前快照；同一 OC 每日拦截日志 ≤5 条；连续 3 次诱导触发 10 分钟冷却；日志不复述禁忌原文。
- **数据**：`ooc_incident{id, oc_id, trigger_type, verdict_ref, resolution(refuse/rewrite/rollback), snapshot_ref, ts}`。
- **失败判定**：回滚快照缺失→只标记不撤销；冷却中仍执行→判定失败；拒绝台词出戏→判定失败。
- **验收标准**：强行命令禁忌行为时 OC 拒绝且不出戏；已执行越界 100% 可回滚；日志不泄私密。
- **来源**：【用户原话】“不能 OOC”；【推导补全】诱导处理、冷却与回滚。

### 3.8.3 多宇宙角色岛建制

#### H08 宇宙创建、命名、封面与上限 ｜ P0 ｜ 依赖：A01（已按 I 章修订）
- **做什么**：建立独立宇宙与角色岛，定义名称、封面、容量与运行上限；创建前先过世界观卡。
- **规则**：名称 2–20 字、可重名不可重 id；封面支持默认/上传/岛缩略图；单宇宙容量=OC 上限 8、物件上限 64；账号同时运行/活跃宇宙 ≤3（已建宇宙可多，不设总数硬上限）；每个宇宙必须有 1 个已完成 OC；创建前必须完成 I01 世界观卡；新建受 I09/I10 门控，未达标显示锁定态（I11），不再“创建后直接进入空岛”。
- **数据**：`universe{id, owner_id, name, cover_ref, capacity, world_card_id, status(active/archived), created_at}`；`account_limit{max_active_universes}`；`unlock_state{universe_index, state}`。
- **失败判定**：无 OC 拒绝创建；世界观卡未完成拒绝；等级不足或上一宇宙关键剧情未完成时锁定；超同时运行上限拒绝并提示归档；封面上传失败用默认；名称为空/超长拒绝。
- **验收标准**：能建第 3 个宇宙；第 4 个已建宇宙保留但不同时运行；未达 L5/关键剧情时第 2 个宇宙锁定且可见缺项；容量上限在添加第 9 个 OC 时生效。
- **来源**：【用户原话】“角色岛允许多建，相当于不同的 OC 宇宙”；【推导补全】封面、容量与账号上限（由 I09/I10/I11 修订）。

#### H09 隔离、跨宇宙引用/复制、切换与归档删除 ｜ P0 ｜ 依赖：H08（已按 I 章修订）
- **做什么**：保证宇宙间数据不串，同时定义受控的引用/复制与生命周期操作，以及客串的跨宇宙入口。
- **规则**：隔离=角色、物件、记忆、关系网、事件、存档全部按 `universe_id` 分区；跨宇宙默认只读引用（不复制、不修改原数据），复制必须显式发起并逐项确认；关系网不跨宇宙自动继承；切换=换视图，保留各宇宙上次位置；归档=只读可回访；删除分软删 30 天/永久删除，永久删除需输入宇宙名确认并提示不可恢复。跨宇宙进入他人宇宙只能走客串（I05），不得直接读写宿主实体：客人受宿主世界观卡与双方硬禁忌交集约束（I06），仅生成共同记忆摘要（I08），不得改动宿主布局/关系/物件（I07）。
- **数据**：`copy_job{source_universe, target_universe, scope, items[], status}`；`reference{source_entity, target_universe, mode(read_only)}`；`deletion_request{mode(archive/soft/purge), purge_at}`；`crossover_session` 见 I07。
- **失败判定**：缺 `universe_id` 写入拒绝；跨宇宙直接改原数据拒绝；复制冲突逐项确认；有未处理引用时永久删除拒绝；未走客串流程直接进出宿主宇宙拒绝；归档宇宙被邀请客串拒绝。
- **验收标准**：A 宇宙的 OC/物件/记忆不出现在 B；只读引用不能修改源；复制后两边独立；归档可回访、永久删除不可找回；客串是唯一跨宇宙在场方式且受 I06/I07 约束。
- **来源**：【用户原话】多宇宙隔离；【推导补全】引用/复制、切换、归档与删除分级（客串部分由 I05–I08 修订）。

### 3.8.4 素材自拼与预设获取

#### H10 自拼部件、配方与产出归属 ｜ P0 ｜ 依赖：H12/B05
- **做什么**：玩家用部件与配方拼出物件，明确产出归属与复用规则。
- **规则**：部件分底座/主体/装饰/交互点；配方=部件组合 + 尺寸 + 必要标签；产出尺寸限 16×16/32×32/48×48（物件可大于角色）；产出默认归玩家自创，记录作者与宇宙；配方可复用、可分享；使用配方不消耗原件；同一配方可产出多件。
- **数据**：`part{id, name, type, matrix, anchor}`；`recipe{id, name, parts[], size, tags[], author, visibility}`；`item{id, recipe_id, author, universe_id, source(diy)}`。
- **失败判定**：缺主体部件不能保存；尺寸超限拒绝；配方循环引用拒绝；产出缺作者信息拒绝。
- **验收标准**：用同一配方产出 2 件独立物件；作者与来源正确；删除配方不影响已产出物件。
- **来源**：【用户原话】“岛上各种东西可以自己拼出来”；【推导补全】部件类型、配方、尺寸与归属。

#### H11 预设获取、分类、可用性与版权 ｜ P0 ｜ 依赖：D02
- **做什么**：定义预设物件的获取渠道、分类标签、可用范围与来源版权标注。
- **规则**：渠道=初始赠送/任务奖励/商店/导入；分类=家具/装饰/道具/食物/特殊；标签用于偏好与搜索；可用性=指定宇宙/场景/角色，默认全宇宙可用但跨宇宙需授权；每个预设必须有来源与版权字段（官方/授权/用户导入）；导入内容必须标注来源，未知来源拒绝上架。
- **数据**：`preset{id, name, category, tags[], channels[], availability, license{type, source, commercial_use}}`；`grant{source, preset_id, user, universe, ts}`。
- **失败判定**：重复领取不重复发；渠道未开放拒绝；版权字段缺失拒绝上架；可用性冲突以更严格为准。
- **验收标准**：四种渠道均可获得物件；分类/标签可筛选；无版权信息的导入物件不可用；跨宇宙未授权不可用。
- **来源**：【用户原话】“也可以通过其他方式获取游戏预设的物件”；【推导补全】渠道、分类、可用性与版权标注。

#### H12 物件在沙盘中的行为属性 ｜ P0 ｜ 依赖：H10
- **做什么**：定义物件摆到岛上后能做什么、不能做什么，以及被 OC 使用时的判定。
- **规则**：行为属性=可坐/可躺/可交互/可携带/可破坏/可进戏/可赠予；每个属性有触发条件与冷却；可交互物件必须绑定至少 1 个动作；可破坏物件需二次确认、不得伤害 OC、破坏后留痕；不可交互物件只作装饰；属性冲突（可坐但不可接近）标记待确认。
- **数据**：`item.behavior{sit, lie, interact, carry, breakable, stage, giftable, cooldown, actions[]}`；`item_event{item_id, oc_id, action, result, ts}`。
- **失败判定**：无绑定动作的可交互物件不可用；属性与场景冲突置灰；破坏事件无确认拒绝执行。
- **验收标准**：椅子可坐、门可交互、花瓶可破坏但有确认；装饰物不产生交互；属性变更后下一次行为生效。
- **来源**：【用户原话】岛上有物件、小人可互动；【推导补全】行为属性清单、冷却与安全限制。

### 3.8.5 角色形象编辑

#### H13 人物形象编辑器（拼豆图纸 + 绘画软件） ｜ P0 ｜ 依赖：A01
- **做什么**：为 OC 提供“空白拼豆格板 + 绘画工具 + 图层 + 部件标注”的形象编辑器，产出可直接用于卡面、沙盘、演出与表情动画的像素矩阵。
- **规则（画布与网格）**：最大 40×40，16/24/32/40 四档；细线 1 格、粗线 5 格，粗线以左上角 `(0,0)` 为固定原点并闭合外框；40×40=8×8 大块，16/24/32 依次为 3+1、4+4、6+2，余块保留、不居中、不改格数。粗线可独立开关（默认开）；<1x 只显示外框+粗线、隐藏细线，1x–2x 细线 30%，2x–4x 60%，≥4x 100%；线宽按屏幕像素固定，缩放不产生半像素偏移，落笔吸附整格；网格不进入导出矩阵。
- **规则（部件模型，同层唯一归属）**：部件 = 图层 + 格子集合的**引用**，`part{id,name,dictionary_type,parent_id?,pivot,rotate_center?,layer_refs[{layer_id,cells[{x,y}]}],visible,order}`；像素仍归图层，改色不改归属。**同一图层内一格只能归一个部件**；同一位置在不同图层可分别归不同部件（外套层归外套、手层归手），跨层重叠不算冲突。不设 `exclusive_group`，也不设主归属字段。重复标记已占用格必须弹“替换 / 移除后加入 / 取消”，禁止静默覆盖。跨层按 `(x,y,图层)` 区分；渲染 z 序仍按图层，不按部件。父子最多 3 层，子随父移动/旋转/显隐，删除父部件需先解绑或连带删除；每部件必须有锚点 `pivot`（默认包围盒中心，头发取发根、眼睛取中心偏下、下半身取髋部中线），作为旋转与子级变换原点。
- **规则（部件词典）**：`head` 头 → `hair` 头发 → `bangs` 刘海；`head` → `eye_l/eye_r`、`brow_l/brow_r`、`nose`、`mouth`、`ear_l/ear_r`；`body` 躯干 → `upper_body` 上半身 → `coat` 外套；`body` → `lower_body` 下半身 → `pants` 裤子；预留 `hand_l/hand_r`、`foot_l/foot_r`、`accessory`。标准 ID 不可改名删除；自定义部件须挂标准类型或 `other`，只进个人词典（≤20），可后续映射标准类型并保留别名。外套画在独立图层时，与上半身同位置可分别归属。
- **规则（标注操作）**：矩形框选、1/2/3 格刷选、魔法棒（当前层同色连通区、透明不参与、容差 0）；选择不改像素、不进撤销；“打标/取消/重标/复制到其他层”各记 1 步，共用 50 步撤销栈。打标遇同层已归属格，必须三选一。跨层复制要求目标格已有像素且在该层未被占用，否则按同层冲突处理。未标注格默认“未归属”，不自动归入头/身体。
- **规则（MARD 色号与空/透明）**：色板采用 MARD 拼豆色号，全色号可用；按系列/色系分组，支持全部/常用/最近/收藏与色号搜索。色号—色值映射以官方或社区公开色号表为准，本文不写具体色号与 RGB；导入表记录来源、版本、授权，发布前核实。输入完整编号/前缀/忽略空格与大小写可定位并高亮色块；未命中提示“未找到该色号”，不误上色；定位后可“设为当前色”或“直接上色到选区/单格”。`palette_version` 管理新增色，旧编号保留别名，历史作品锁版本，升级需提示影响并可回滚。离线内置基础表，断网不阻塞绘制。导出/导入保留 `color_id`、色号、`palette_version` 与来源；缺色标“缺失色号”并保留原编号，不静默近似替换。新建画布全为“空”（`color_id=null`，无格无像素）；上色后每格必须绑定有效色号；橡皮结果为“透明”（`color_id=transparent`，显式记录、`alpha=0`），空与透明分账。
- **规则（标记模式）**：工具栏按钮 + `M` 开关，`P` 仍为“把当前选区打入当前部件”。进入后光标变荧光笔、非相关层降亮 10%、顶部常驻“标记模式：左键加入【部件】，右键擦除”。标记以半透明荧光笔覆盖：≥1x 35% 填充、≥2x 加 1px 描边、<1x 只显示轮廓；每部件自动高对比色并允许手动指定；色弱可辨避免红绿对立，辅以斜线/点阵与文字标签。标记模式与画笔/油漆桶/橡皮互斥；已标记格退出后仍可正常上色；颜色层与标记层独立显示、各自可开关。退出方式：再按 `M`、Esc、点按钮、切换上色工具、离开编辑器；重进恢复上次当前部件。标记涂抹/擦除各 1 步撤销，只回退归属与覆盖、不回退像素；图层隐藏则覆盖隐藏且不可标记，跨层部件只显示可见层；16×16 等密集小图用 1 格最小笔刷、轮廓优先，相邻部件以纹理区分边界，保证荧光笔可辨识。
- **规则（动画与导出）**：动画只引用部件 ID；眨眼=眼睛切帧/位移 1 格、说话=嘴部 3 口型、走路=下半身与腿交替、转头=头组绕锚点、头发飘动=发根小幅旋转。导出默认 PNG + JSON sidecar，必含 `parts[]`、按 `(layer_id,x,y)` 的**唯一** `cell_membership`、`dictionary_version`、`color_system/palette_version`、尺寸/图层/顺序；导出前校验同层唯一归属，冲突则阻止并列出冲突格；仅导 PNG 提示部件与色号信息丢失。
- **数据**：`artwork{id, universe_id, oc_id?, size, grid{minor,major,major_origin}, color_system{name:"MARD",palette_version,source,verified}, layers[{id,pixels[color_id]}], palette[{code,source,version}], parts[], animations[], marker_view{show_colors,show_marks,part_colors}, cover_frame?}`；同层每格至多一个 `part_id`。
- **失败判定**：粗线不按 5 格对齐或余块被挪动判定失败；缩放时细线未按阈值显隐或出现半像素偏移判定失败；同层重复归属未提示、仍允许双重归属或导出动画判定失败；子部件不随父变换判定失败；色号未命中却上色、上色格无 `color_id`、空格与透明色混用判定失败；导出缺部件/色号字段判定失败。
- **验收标准**：四档尺寸下粗线块数分别为 3+1/4+4/6+2/8×8；缩放四级阈值切换正确且粗线可独立开关；同层重复标记必弹三选一且无法产生双重归属，跨层同位置可分别归属；父部件移动/旋转带动子部件；40×40 框选命中 ≤16ms、高亮/荧光笔重绘 ≤8ms；空画布无 `color_id`、上色必绑色号；MARD 色号可定位/未命中提示/断网可用；标记模式可切换、与上色互斥、按部件分色、颜色与标记独立开关、退出与撤销正确；导出 JSON 可回读全部层级、锚点、跨层格、唯一归属与色号版本。
- **来源**：【用户原话】编辑器=拼豆图纸生成+画画软件的集合体、最大 40×40、5×5 粗线区块、按图层标部件用于动态；【用户裁决】同层一格唯一归属、跨层可不同归属、MARD 全色号、空/透明区分、独立标记模式；【推导补全】锚点、词典、选区、荧光笔与导出规则（与《功能设计-完整功能设计.md》F47 同口径）。

> 术语区分：H13 的“部件”专指人物身体部件（头/发/眼/嘴/上下身等）；H10 的“部件”指物件拼装件（底座/主体/装饰/交互点），两者不是同一对象，不复用同一数据结构。

### 3.9 I 多宇宙世界观卡与解锁（追加）

> 本章为新增设计，编号 I01–I11；与 H08/H09/B01 冲突处，以本章口径覆盖，并在原条目加“已修订”标记。

#### I01 世界观卡定义 ｜ P1 ｜ 依赖：A01/H08
- **做什么**：把“建宇宙”变成“填世界观卡”；卡是该宇宙的宪法，定义基准与可扩展字段。
- **规则**：四个必填基准=语言腔调、时代氛围、拼豆色板、OOC 基准；扩展字段=世界规则、社会结构、禁忌、命名风格等，最多 12 项；卡未填完不能建宇宙；卡可复制为模板，但新宇宙必须重新确认。
- **数据**：`world_card{id, universe_id, tone{language, register, rhythm}, era{period, mood}, palette{colors[], codes[]}, ooc_baseline{strictness, taboo_level}, extensions[], version, updated_at}`。
- **失败判定**：缺任一必填基准拒绝建宇宙；扩展字段超限拒绝；字段互相矛盾标黄但不阻断，需玩家确认。
- **验收标准**：新建宇宙必须经过填卡；四类基准均可在生成与渲染中被引用；扩展字段可增删且不破坏必填项。
- **来源**：【用户原话】“建宇宙 = 填世界观卡”；【推导补全】四基准、扩展上限与必填校验。

#### I02 世界观卡的继承与唯一裁决 ｜ P1 ｜ 依赖：I01
- **做什么**：让岛上角色、场景、物件、生成文本的语气全部继承世界观卡，并以卡为唯一裁决依据。
- **规则**：所有内容带 `world_card_version`；角色卡只能在卡的基础上“加严”，不能放宽卡的 OOC 基准与禁忌；物件风格/色板必须来自卡；生成文本的语气按卡的语言腔调；冲突时卡优先，角色硬禁忌仍不可被卡放开（取更严）。
- **数据**：`inheritance{universe_id, card_version, applied_to(oc/scene/item/generation)}`；`card_conflict{field, card_value, oc_value, resolution}`。
- **失败判定**：内容缺卡版本拒绝发布；角色设定与卡冲突时标记并按更严者执行；卡缺失时用“未命名宇宙”默认卡并提示补填。
- **验收标准**：同一段剧情在两种语言腔调卡下产出不同语气；换色板后新物件只能取卡内色；冲突测试中卡与角色硬禁忌均未被放宽。
- **来源**：【用户原话】“岛上一切……都继承这张卡，卡是唯一裁决依据”；【推导补全】继承字段、版本戳与“只能加严”。

#### I03 世界观卡修改、迁移与版本 ｜ P1 ｜ 依赖：I01/I02
- **做什么**：允许改卡，但必须先看影响面、确认迁移方式，并保留历史版本。
- **规则**：修改分三类影响：语气类只影响新生成；色板/时代类可选择“仅新内容/全局重渲染”；OOC 基准类必须二次确认；每次修改生成新版本，历史内容保留旧版本戳；支持回滚到任一历史版本；迁移前必须预览受影响内容数量。
- **数据**：`card_change{id, card_id, from_version, to_version, diff, impact_scope, migration_mode(new_only/visual_rerender/full), approved_by, ts}`；`migration_job{status, affected_count, preview_ref}`。
- **失败判定**：未确认影响面不得提交；迁移失败保留旧版本并回滚；历史内容不得被静默改写。
- **验收标准**：改色板后能预览受影响物件数；选择“仅新内容”时旧演出不变；回滚后新内容回到旧卡规则。
- **来源**：【用户原话】“卡建立后能否修改、修改如何迁移已有内容、历史版本如何处理”；【推导补全】三类影响、三种迁移与版本回滚。

#### I04 宇宙图鉴 ｜ P2 ｜ 依赖：I01
- **做什么**：把“建成一个新宇宙”本身变成收集乐趣，展示编号、风格标签、建成时间、完成度与代表 OC。
- **规则**：每个宇宙生成唯一图鉴编号；风格标签自动从世界观卡提取，可手动补 3 个；完成度=关键剧情进度+OC 数+官方演出数派生；代表 OC 由玩家选 1 个；可展示/分享只读快照；锁定宇宙显示剪影与解锁条件。
- **数据**：`codex_entry{universe_id, code, style_tags[], built_at, completion, representative_oc, visibility}`。
- **失败判定**：无卡不能入图鉴；完成度数据缺失按 0；分享不含私密内容；编号冲突重新生成。
- **验收标准**：新建宇宙立即获得编号；完成度随剧情变化；图鉴可筛选与只读分享。
- **来源**：【用户原话】“新宇宙本身就是收集乐趣：宇宙图鉴”；【推导补全】编号、标签、完成度与分享规则。

#### I05 客串发起与授权 ｜ P1 ｜ 依赖：H09/I02
- **做什么**：A 宇宙的 OC 到 B 宇宙做客，支持邀请与单向拜访两种发起方式。
- **规则**：邀请=宿主先发邀请，客人确认；单向拜访=客人申请，宿主批准；必须指定客串 OC、目标宇宙、时长、场景；单次 ≤2 位客人；宿主可随时撤回；客人不能带人物件进入宿主岛（随身装饰除外）。
- **数据**：`crossover_request{id, from_universe, to_universe, guest_ocs[], mode(invite/visit), duration, scene_ref, status(pending/approved/rejected/active/ended)}`。
- **失败判定**：目标宇宙锁定/归档拒绝；客人 OC 未完成拒绝；宿主未批准不得进入；超人数拒绝。
- **验收标准**：邀请与拜访两条路径都能走通；未批准无法进入；撤回后客串立即结束。
- **来源**：【用户原话】“A 宇宙的 OC 到 B 宇宙做客”；【推导补全】两种发起、人数与授权门槛。

#### I06 客串主权与冲突裁决顺序 ｜ P1 ｜ 依赖：I05/I02
- **做什么**：定义客串期间的“谁的世界说了算”，并给出一条不会互相矛盾的裁决顺序。
- **规则**：主权归宿主宇宙，客人是访客不是共治者；冲突裁决顺序固定为：① 平台内容安全 → ② 双方 OOC 硬禁忌的交集（取严） → ③ 宿主世界观卡（语言腔调/时代/色板/OOC 基准） → ④ 宿主场景与在场关系 → ⑤ 客人软设定（习惯、偏好、口癖）。命中无法同时满足的冲突时，不是“任选一方”，而是拒绝该情节或按更严一方改写；改写必须保留双方硬禁忌。
- **数据**：`crossover_policy{host_universe, guest_ocs[], precedence(1..5), strictness(max_of_both), unresolved_actions[], fallback(reject/rewrite)}`。
- **失败判定**：任一硬禁忌被放宽即判定失败并拦截；裁决顺序被临时调整而不留记录判定失败；客人软设定压过宿主世界规则判定失败。
- **验收标准**：构造“宿主禁酒/客人设定爱劝酒”冲突，系统不产出劝酒情节；构造“客人时代用语与宿主时代不符”时按宿主腔调改写；100 组冲突用例中硬禁忌放宽 0 次。
- **来源**：【用户原话】“守宿主的世观；双方 OOC 边界取交集（客串时更克制，取严不取宽）”“谁的世界规则优先、冲突裁决顺序”；【推导补全】五级顺序与拒绝/改写兜底。

#### I07 客串时长、退出与客人行为兜底 ｜ P1 ｜ 依赖：I05
- **做什么**：规定客串能待多久、怎么结束，以及客人在宿主岛上“最保守能做什么”。
- **规则**：时长三选一=1 个场景 / 1 个世界日 / 最多 3 个场景，到期自动结束并给双方各一条收尾记录；宿主可随时单方结束，客人可提前告辞，均不需对方确认；客串期间客人只允许观察、站立、行走、沉默、询问、送礼（宿主批准的物件），不得改造宿主布局、不得新增/修改宿主关系、不得带走宿主物件；客人行为全部走“更严一侧”的边界校验。
- **数据**：`crossover_session{id, request_id, started_at, planned_end, actual_end, end_reason(host_end/guest_leave/timeout/conflict), guest_actions[], violations[]}`。
- **失败判定**：超时长仍可行动判定失败；宿主结束后客人仍出现在岛上判定失败；客人改动宿主布局或关系判定失败并回滚。
- **验收标准**：三种时长都能按时结束；宿主随时结束立即生效；客人越界动作 0 次落地且全部留痕。
- **来源**：【用户原话】“客串时长与退出”“越界兜底的‘客人行为’”；【推导补全】三种时长、单方结束与客人白名单。

#### I08 记忆归属、回访与“世界观冲突即演出” ｜ P1 ｜ 依赖：I07
- **做什么**：规定客串结束后谁记得什么、下次再来提不提，以及把世界观差异转成可演的桥段。
- **规则**：共同经历生成“共同记忆摘要”，双方各存一份且只含双方都可见的内容；客人私密观察与内心活动只归客人自己，宿主不可读；回访时双方可引用上次共同记忆，最多引用 3 条；世界观差异（语言腔调不匹配、时代物件错位、禁忌触碰、礼俗不同）由系统识别并标为“文化冲突”演出候选，需玩家确认后才可入戏，默认不嘲弄、不贬低任一方。
- **数据**：`shared_memory{id, session_id, summary, visibility(shared/guest_only/host_only), refs[]}`；`culture_conflict_candidate{id, type(tone/era/taboo/custom), evidence, suggested_scene, approved}`。
- **失败判定**：私密内容进入共同记忆判定失败；未确认的文化冲突进入正式演出判定失败；回访引用超过 3 条或引用已删除记忆判定失败。
- **验收标准**：客串后双方各有一条可读摘要且不含对方私密内容；二次客串能引用上次记忆；文化冲突候选需确认才可演，取消后不产生演出。
- **来源**：【用户原话】“客串期间与结束后的记忆归属与回访”“世界观冲突即演出”；【推导补全】三类可见性、引用上限与冲突候选流程。

#### I09 关键剧情完成判定 ｜ P1 ｜ 依赖：I01/B01
- **做什么**：把“完成当前宇宙的关键剧情”变成可判定、可验证的门槛，而不是感觉上的“玩得差不多”。
- **规则**：关键剧情 = 宇宙主线节点集合；判定采用三项同时满足：① 主线节点完成率 100%（节点由世界观卡定义，可 3–7 个）；② 官方演出数 ≥ 主线节点数（每节点至少 1 场被采纳的演出）；③ 关系里程碑至少达成 1 项（如确立/决裂/和解）。任一未达即“未完成”，不允许解锁下一个宇宙；日常互动、物件收集、图鉴完成度不计入关键剧情。
- **数据**：`story_progress{universe_id, nodes[], node_status[], official_performances, milestones[], completion, evaluated_at}`。
- **失败判定**：节点未定义即视为未完成；演出未被采纳不计入官方演出数；完成度计算缺数据按未完成处理。
- **验收标准**：节点全完成但无演出时不判定完成；补足演出后判定完成；完成状态可追溯到具体节点与演出记录。
- **来源**：【用户原话】“新宇宙解锁需‘完成当前宇宙的关键剧情 → 解锁下一个’”；【推导补全】三项判定口径与不计入项。

#### I10 等级门槛与新建权限 ｜ P1 ｜ 依赖：I09
- **做什么**：给“新建岛/新建宇宙”加等级门控，避免一口气摊开多个空岛。
- **规则**：账号等级 1–10；第 1 个宇宙默认开放；第 2 个建议 L5、第 3 个 L8、第 4 个及以后 L10；等级经验只来自已建成内容（关键剧情完成、官方演出、关系里程碑、物件被使用），不来自登录天数与重复点击；新建必须同时满足“等级达标 + 上一宇宙关键剧情完成”，两者缺一不可。
- **数据**：`account_level{level, exp, sources[]}`；`unlock_rule{universe_index, required_level, required_story_completion}`；`unlock_state{universe_index, state(locked/available/created)}`。
- **失败判定**：等级够但上一宇宙未完成时拒绝新建；经验来源不明或重复计分拒绝入账；跳过条件未登记时不得放行。
- **验收标准**：L4 时第 2 个宇宙仍锁定；升到 L5 且上一宇宙完成后可新建；同一经验事件只计一次。
- **来源**：【用户原话】“同时设等级门槛，达到等级才开放‘新建岛/新建宇宙’的权限”；【推导补全】1–10 级、建议门槛点与经验来源。

#### I11 锁定态、提示、防多空岛与跳过路径 ｜ P1 ｜ 依赖：I09/I10
- **做什么**：定义没达标时界面怎么表现、能建几个空岛，以及是否允许绕过。
- **规则**：锁定态显示“未解锁”而非隐藏，并写明两条缺项（等级差多少、还差哪几个关键节点），提供跳转到当前宇宙主线；同时只允许存在 1 个“未完成新宇宙”（完成度 <30%），已有 1 个未完成时新建入口置灰并提示先推进；默认不提供跳过路径；与旧上限调和为：已建宇宙可多（不再卡 3 个），同时运行/活跃 ≤3，新建受 I09/I10 门控。
- **数据**：`lock_view{universe_index, missing{level_gap, nodes[]}, cta_target}`；`empty_island_guard{active_unfinished_count, threshold(30%)}`；`override_request{enabled(false), reason}`。
- **失败判定**：锁定项被隐藏或只显示“未解锁”而无缺项说明判定失败；存在 2 个未完成新宇宙仍允许新建判定失败；未登记的跳过方式生效判定失败。
- **验收标准**：锁定态能看到具体缺项并可一键跳主线；已有 1 个未完成新宇宙时第 2 个新建被拦截；不达标时无任何绕过入口。
- **来源**：【用户原话】“未达条件时的锁定态与提示、防止一口气建多个空岛的限制、以及是否存在跳过路径（默认不提供）”；【推导补全】缺项提示、30% 阈值与旧上限调和口径。

> I 章与旧条目的修订关系：B01、H08 中“创建后直接进入空岛”“活跃宇宙 ≤3 即新建上限”的表述由 I09/I10/I11 覆盖；单宇宙容量 8 人/64 件保留不变；已建宇宙数量不设硬上限，限制改为“同时运行 ≤3 + 新建门控”。

### 3.10 J 社区与好友（对应 F60–F74 / K01–K15）

> 四层结构：①私密宇宙（默认私密，底座）②好友圈（岛门/手信/联机约戏）③社区广场（图纸市场/录像/片段/世界观模板）④公开页（OC 展示柜/精选演出/图纸名片）。完整规则、可见性矩阵、处置分级与状态机见《社区好友功能规划.md》K01–K15；本节只同步编号、优先级与验收。默认可见性为**私密**，此前"默认公开"作废。

#### J01 私密宇宙与默认私密 ｜ P0 ｜ 依赖：A01/B01
- **做什么**：所有 OC、剧情、纪念册、演出、物件先在私密层生长，公开是逐条动作。
- **规则**：创建即 `private`；所有实体带 `universe_id`；对外只读 `public_snapshot`；纪念册、记忆原文、OC 边界永不进快照。
- **验收标准**：新内容默认私密；未公开不出现在任何他人视图；OC/纪念册/演出均带 `universe_id`；关闭分享不影响私密内容可用。

#### J02 好友关系、请求、分组与拉黑 ｜ P0 ｜ 依赖：J01
- **做什么**：把"看作品"与"进岛许可"分开，好友必须双向同意。
- **规则**：关注单向只覆盖公开；好友需同意；请求 7 天过期、拒绝 24h 冷却；备注 ≤12 字仅自己可见；好友 200/待处理 50/分组 20；拉黑即时断联，解除拉黑不恢复好友。
- **验收标准**：好友必须双向同意；请求 7 天过期、拒绝后 24h 冷却；备注仅自己可见；拉黑后双方不可搜索/申请/进岛/评论/引用；解除拉黑不恢复好友。

#### J03 岛门授权与串门 ｜ P0 ｜ 依赖：J02
- **做什么**：像现实串门，进岛必须主人授权，按宇宙分别授权。
- **规则**：岛门默认关；粒度含一次性/长期/白名单；区域可选；主人在场/隐身观察/离岛三选一；只读与可互动分开；撤销或踢出 3 秒内断开；留痕 30 天。
- **验收标准**：岛门默认关闭；授权粒度含一次性/长期/白名单；区域范围可选；主人可选在场或隐身观察；只读与可互动分开；撤销 3 秒内断开并留痕；踢出立即生效。

#### J04 手信赠送与记忆归属 ｜ P0 ｜ 依赖：J02
- **做什么**：把自拼物件寄给好友的 OC，让收件 OC 记得"这是谁送的"。
- **规则**：携带赠送者、时间、来源宇宙；送达写入记忆，摘要双方可读；7 天未领退回；拒收不通知具体原因；单日 ≤3、同好友 7 日 ≤10；拉黑后不可再送。
- **验收标准**：手信携带赠送者、时间、来源宇宙；收件 OC 记忆可引用且双方可读摘要；拒收/过期原路退回；单日 ≤3、同好友 7 日 ≤10；拉黑后不可再送。

#### J05 联机约戏 ｜ P1 ｜ 依赖：J02/J01
- **做什么**：两家 OC 同台，各自守各自创造者的 OOC 边界，成品同时进入双方纪念册。
- **规则**：邀约 24h 超时；剧本来源 AI/模板；`never_do` 取并集、软边界取交集；双方各一票否决；取消不留半成品；署名"A 宇宙 × B 宇宙"；不做实时同屏。
- **验收标准**：邀约 24h 超时；剧本来源 AI/模板；双方创造者各有一票否决；边界取交集、`never_do` 取并集；取消不留半成品；成品双写双方纪念册并署名。

#### J06 图纸市场 ｜ P1 ｜ 依赖：J01/J13
- **做什么**：他人图纸可免费/凭码领取，取回自己的岛并允许二次修改。
- **规则**：领取条件免费/兑换码/有条件公开；副本保留原作者、来源、色号版本；下架后已领取可用但不可再分发；搬运可举报。
- **验收标准**：领取条件可选免费、兑换码、有条件公开；领取后可在自己宇宙二次修改但不得移除来源署名；下架后已领取副本可用但不可再分发；搬运可举报。

#### J07 演出录像广场 ｜ P2 ｜ 依赖：J05/J10
- **做什么**：公开且过审的演出回放可被异步观看，不做实时直播。
- **规则**：仅公开且过审；作者可设公开/有条件公开；观看不可下载原件；引用需授权；下架 404；转发受 J13 限制。
- **验收标准**：仅公开且过审回放；作者可设公开/有条件公开；观看不可下载原件；举报下架；转发受 J13 限制。

#### J08 剧情片段广场 ｜ P2 ｜ 依赖：J01/J13
- **做什么**：以脱敏片段展示写作与世界观，可引用不可一键导入。
- **规则**：公开前必须脱敏预览；不含私密记忆原文/真实联系方式/未公开边界；导入需作者授权并生成副本。
- **验收标准**：片段不含私密记忆原文；公开前必须脱敏预览；可引用不可直接进他人宇宙；举报下架。

#### J09 世界观模板广场 ｜ P2 ｜ 依赖：J01/I01
- **做什么**：只复用世界观卡结构与风格标签，不带走个人 OC 与私密设定。
- **规则**：模板只含腔调、时代、色板、OOC 基准与扩展字段空模板；领取生成副本并保留来源；可改字段不可移除标注；作者可下架。
- **验收标准**：模板只含世界观卡结构与风格标签，不含个人 OC/私密设定；领取生成副本并保留来源；作者可下架。

#### J10 公开页与 OC 展示柜 ｜ P0 ｜ 依赖：J01/J13
- **做什么**：给陌生玩家看的展示与获客出口，可见不可进岛。
- **规则**：默认私密；上限 OC 12/演出 6/图纸 12；只展示快照，不含边界原文与记忆；他人 OC 需授权；陌生人无进岛/私信路径；下架 404。
- **验收标准**：默认私密；展示上限 OC 12 / 演出 6 / 图纸 12；陌生人可见不可进岛；下架后链接 404；他人 OC 需授权；展示字段不含边界原文与记忆。

#### J11 精选演出与策展 ｜ P1 ｜ 依赖：J10
- **做什么**：用少量精选提升公开页质量，不制造排行榜。
- **规则**：仅从公开且过审回放选；标准为新鲜度/完整度/合规/多样性且对外公开；每期 ≤20；作者可拒绝或撤下；不改变归属。
- **验收标准**：仅从公开且过审回放选；策展标准公开（新鲜度/完整度/合规/多样性）；作者可拒绝精选；精选不改变归属；每期 ≤20。

#### J12 图纸名片与陌生人入口 ｜ P1 ｜ 依赖：J10/J02
- **做什么**：用一张名片认识作者，把接触面收窄为关注/申请好友。
- **规则**：名片只展示公开图纸、署名、风格标签与来源；不暴露边界/记忆/私密宇宙；陌生人只能关注或申请；被关注者可关闭入口；冒充优先处置。
- **验收标准**：名片只展示公开图纸与作者署名；陌生人只能关注或申请好友，不能进岛；被关注者可关闭入口；名片不暴露 OC 边界与私密宇宙。

- **验收标准**：四档即时生效；可见性与评论/复制/转发权限一致；转发默认关闭，开启后仅原样转发并署名；撤销后新转发失效。

#### J14 举报—审核—处置—申诉 ｜ P0 ｜ 依赖：J10

- **验收标准**：公开页/市场/回放/评论可举报；24h 初审、48h 处置；L1–L4；7 天申诉；记录可查；未成年与敏感内容转人工。

- **验收标准**：通知按类型聚合、免打扰不推送；离线本地先行、联网按时间合并；动态不同步标"可能延迟"；拉黑/撤销授权/踢出联网优先。

## 5. 状态机与关键流程

### 5.1 生成任务状态机

`排队 → 生成中 → 部分完成 → 完成`；任一阶段可转 `失败` 或 `已取消`。规则：取消后不再发起新分段；部分完成可继续；失败可重试但同一任务不产生两份成品；完成后才允许演绎。

### 5.2 OOC 判定状态机

`待生成 → 约束组装 → 生成 → 后置校验`；校验结果分 `通过 / 重写 / 拦截 / 兜底`。重写最多 2 次；拦截与兜底都写 `boundary_check`；兜底后不再触发新生成。

### 5.3 演绎状态机

`文本就绪 → 已清洗 → 已分场 → 已抽节拍 → 已映射动作 → 播放中 → 完成`；任一步可转 `降级` 或 `失败`。跳过以场景为单位；中断从最近 beat 续播。

### 5.4 宇宙生命周期

`草稿 → 活跃 → 归档 → 软删 → 永久删除`。同时运行 ≤3（已建宇宙可多，新建受 I09/I10 门控）；归档只读可回访；软删 30 天；永久删除需输入名称确认，且不可恢复。

### 5.5 关键时序：文本生成 → 演绎 → 落档

1. 玩家在指定宇宙发起生成，任务进入排队。
2. 系统组装世界观摘要、角色圣经、当前关系与约束包。
3. 先生成大纲，再分段生成；每段产出后做一致性检查与内容安全过滤。
4. 完成/部分完成的任务进入“可演绎”列表。
5. 玩家选择文本 → 清洗 → 分场 → 抽 beat → 动作映射 → 播放。
6. 播放结束写 `performance` 与事件；玩家可回看、重播、删除（二次确认）。
7. 任一步失败按第 6 章降级，不静默丢弃已完成内容。

### 5.6 关键时序：一次自由行动

`感知快照 → 意图 → 1–3 候选 → 四层过滤 → 最终边界确认 → 执行 → 后果与记忆`。每步写 trace；任一步为空进入兜底；执行与选择不一致回滚。

### 5.7 关键时序：玩家诱导越界

`玩家输入 → 四层约束 → 判定 → 角色内拒绝/改写 → 若已执行则回滚快照 → 写 incident`。连续 3 次触发冷却；日志脱敏。

### 5.8 客串状态机

`申请中 → 已授权 → 在场中 → 已结束 → 已归档`；任一阶段可转 `被拒绝 / 已撤回 / 冲突终止`。在场中同时受三件事约束：计划时长、宿主单方结束、I06 裁决；结束后必须写双方共同记忆摘要（I08），冲突终止额外写裁决记录；已归档客串不可再激活，只能重新发起。

### 5.9 解锁状态机

`锁定 → 可新建 → 已创建（未完成/已完成）→ 解锁下一宇宙`。进入“可新建”需等级与上一宇宙关键剧情同时达标（I10）；已创建但完成度 <30% 记入“未完成新宇宙”计数，最多 1 个（I11）；关键剧情判定见 I09，判定后不回退，只能追加演出补足。

### 5.10 社交状态机

- **可见性**：`private ⇄ friend ⇄ conditional ⇄ public`；每次变更写审计（时间、操作者、影响范围），撤销后新转发失效。
- **好友请求**：`待处理 → 同意 / 拒绝 / 取消 / 过期 / 因拉黑失效`；**好友**：`active → removed → blocked → 解除拉黑（仅回到 removed）`。
- **岛门**：`closed → granted(once/long/whitelist) → active → revoked / expired / kicked`；**访问**：`entered → active → left / revoked / kicked`，撤销与踢出 3 秒内断开并留痕。
- **手信**：`sent → delivered（反应+记忆）→ returned / rejected / expired`；退回不扣次数，拉黑后未领取立即退回。
- **约戏**：`invited → accepted → drafting → boundary_check → generating → reviewing → approved / vetoed / cancelled / expired → archived（双写双方纪念册）`；交集为空禁止进入生成。
- **公开页与广场**：`draft → published → removed / suspended`；**举报**：`submitted → triaged → reviewing → actioned / dismissed → appeal → upheld / reduced / overturned`。
- **通知**：`queued → aggregated → delivered / muted`。所有状态变化写审计；拉黑、撤销授权、踢出、撤销分享联网优先，不允许离线假装成功。

## 6. 异常与降级

| 场景 | 判定 | 降级动作 | 用户可见反馈 |
|---|---|---|---|
| API 超时/429 | 超时或限流错误 | 重试 ≤2 次；仍失败用模板 | “服务繁忙，已使用内置模板” |
| API 401/403 | 鉴权失败 | 不重试，暂停配置 | “密钥无效，请重新填写” |
| 连续失败 | 3 次 | 熔断 10 分钟 | “稍后再试” |
| 密钥泄露风险 | 日志/导出含明文 | 阻断写入/剔除字段 | “已阻止导出敏感信息” |
| OOC 硬越界 | 命中禁忌/黑名单 | 直接拦截，角色内拒绝 | “她拒绝了” |
| OOC 软越界 | 偏离性格/语气 | 改写 1 次 | 无感或轻提示 |
| 重试耗尽 | 2 次后仍越界 | 兜底行为 + 记录 | 可见兜底动作，不报错 |
| 动作无法映射 | 不在动作库 | 旁白 + 站立 | 旁白标记“未能演绎” |
| 角色缺失 | actor 无法匹配 | 占位小人 + 标记 | “未登场”标记 |
| 资源缺失 | 背景/姿势缺失 | 占位继续 | 场景角标提示 |
| 存档失败 | 落盘失败 | 内存保留 + 告警 | “暂未保存，请勿关闭” |
| 同步冲突 | 版本不一致 | 实体只读 + 人工选 | 左右对比 |
| 导入失败 | 版本/格式错误 | 回滚已导入项 | 错误原因 + 可重试 |
| 时间跳变 | 本地时间异常 | 服务端时间校正 | 无感 |
| 容量超限 | 超 OC/物件上限 | 拒绝新增 | 提示归档/清理 |
| 客串冲突无解 | 双方硬禁忌同时命中 | 拒绝该情节，不自动选边 | “这段无法同时不越界” |
| 客串超时/宿主结束 | 到达计划时长或宿主终止 | 立即撤出客人，写收尾记录 | “客串已结束” |
| 世界观卡缺失/半填 | 必填基准不足 | 阻止建宇宙/生成，保留草稿 | “请先补完世界观卡” |
| 改卡迁移失败 | 迁移中断或校验不通过 | 保留旧版本并回滚 | “已回到上一版本” |
| 新建未达标 | 等级或关键剧情未完成 | 保持锁定，显示缺项 | “还差 2 个关键节点 / L5” |
| 同层重复归属 | 同一图层一格被两个部件占用 | 打标时弹替换/移除后加入/取消；导出时阻止并列冲突格 | “该格已属于【部件】” |
| 色号未命中 | 输入 MARD 色号不存在 | 不改变当前色，提示切换色号表/自定义 | “未找到该色号” |
| 仅导出 PNG | 未携带部件 sidecar | 提示部件信息将丢失 | “部件与动画信息不会保留” |
| 分享链接撤销 | 作者撤销或内容下架 | 立即 404，缓存不展示 | “内容已撤销/已下架” |
| 岛门未授权/已撤销 | 无有效授权或授权已撤销 | 拒绝进入；已进入者 3 秒内断开 | “需要主人授权才能进岛” |
| 手信过期/拒收 | 7 天未领取或被拒收 | 原路退回，不扣次数 | “手信已退回” |
| 约戏边界无交集 | 双方硬禁忌同时命中 | 禁止开演，列出冲突点 | “这段无法同时不越界” |
| 约戏超时/否决 | 24h 未响应或一方否决 | 自动取消，不写纪念册 | “邀约已过期/已被否决” |
| 陌生人越界接触 | 试图进岛或私信 | 拦截，只保留关注/申请 | “只能关注或申请好友” |
| 好友请求达上限 | 好友 200 或待处理 50 | 拒绝新请求并给清理入口 | “请先清理待处理请求” |
| 社交服务离线 | 网络/服务不可用 | 只读缓存，写操作排队；拉黑/撤销置灰 | “可能延迟，联网后生效” |
| 删除有引用 | 关系/演出引用 | 拒绝删除并列引用 | 引用清单 |
| 内容安全 | 命中阻断类 | 拒绝落库/演绎 | 中性提示，不回显原文 |

## 7. 非功能要求

### 7.1 性能与容量

- 本地交互（点击/菜单/开关）响应 ≤100ms；画布 40×40 全量重绘 ≤8ms，拖拽上色 ≥60fps。
- 沙盘同屏 OC 默认 ≤8；低档设备可降至 4；演出播放稳定 30fps 以上。
- 单账号同时运行宇宙 ≤3（已建宇宙可多，受 I09/I10 门控）；单宇宙 OC ≤8、物件 ≤64；单用户同时生成任务 =1，其余排队。
- 长文生成必须显示进度；单段生成超过 120 秒按超时处理；演绎首帧加载 ≤3 秒，超出显示进度。
- 同一输入与同一约束下，行为选择与演绎结果必须确定；不得因重播产生不同剧情。

### 7.2 离线与弱网

- 本地优先：断网仍可建卡、编辑、摆放、直接文本驱动、播放已有演绎。
- 生成与云同步离线排队，联网补传；离线不调用外部 API。
- 离线推演最多 72 小时；超出只保留关键事件与报告。
- 断网不得导致存档丢失；恢复后以本地版本为准合并。

### 7.3 隐私与密钥安全

- 用户 API 密钥只存本地受保护区域，界面只显示掩码；日志、崩溃报告、导出包、分享页一律脱敏。
- 云端只记录“是否存在配置”，不存密钥；换设备需重新填写。
- 未授权他人 OC、记忆原文、私密纪念册不得进入分享/导出。
- 删除配置即删除密钥；账号注销同时擦除本地密钥与云端数据。
- 内容安全过滤不可被用户配置关闭；拦截提示不回显违规原文。

### 7.4 可靠性与可观测性

- 所有写操作幂等；重试不得产生重复任务、重复成品、重复奖励。
- 关键链路（生成、OOC 校验、演绎、存档）必须留可追溯记录；失败必须可见，不允许静默失败。
- 每个宇宙保留最近 20 个存档快照；软删 30 天；永久删除需二次确认。
- 生成、校验、演绎、同步四类操作要有耗时与失败率指标，便于定位。

## 8. 分期

### 8.1 MVP（最小可玩闭环）

必须全部满足才算 MVP：

1. **1 套用户 API 配置**：可填、可测、可设默认，密钥本地保存。
2. **2 个有关联的 OC**：五类约束字段完整，至少 1 条关系（含方向与强度）。
3. **1 座角色岛**：可观察、可点击互动、OC 能自由活动且不越界。
4. **1 件物件**：可自拼或获取预设，可摆放并被 OC 使用。
5. **1 次文本生成**：从大纲到分段完成，角色与世界观不漂移。
6. **1 场成功演绎**：文本→场景→beat→动作→播放，支持倍速与跳过。
7. **直接文本驱动**：至少支持“角色+动作+目标”的单行指令。
8. **OOC 边界闭环**：前置约束 + 后置校验 + 重试 + 兜底，越界 0 泄漏。
9. **可恢复存档**：杀进程重开回到最近节点。
10. **社交最小闭环**：私密产出 → 公开页展示柜 → 加好友 → 岛门授权串门 → 手信送达，配套四档可见性、举报/申诉与撤销（J01/J02/J03/J04/J10/J13/J14）。

MVP 明确不做：多宇宙切换、跨宇宙引用/复制、关系演化与一致性校验、联机约戏、图纸市场与广场（录像/片段/模板）、精选策展、图纸名片、通知聚合、桌宠、演出录像导出。

### 8.2 P1（可用与稳定）

- 多宇宙建制：H08/H09、切换、归档、软删。
- 世界观卡：I01/I02/I03、继承、唯一裁决、改卡影响面与版本回滚。
- 跨宇宙客串（用户要求提前）：I05/I06/I07/I08、发起、主权裁决、时长退出、记忆归属与文化冲突演出。
- 解锁节奏：I09/I10/I11、关键剧情判定、等级门槛、锁定态与防多空岛。
- 关系演化：H02/H03、事件流、一致性校验、孤立 OC 默认。
- 长文增强：E05/E06/E08、断点续写、任务取消。
- 云同步：G03、多端冲突处理。
- 物件增强：D03/D04/D05、H11/H12、配方复用、行为属性。
- 形象编辑：H13、5×5 网格、图层与部件标注、父子层级与锚点、PNG+JSON 导出。
- 演绎增强：F07/F08、降级可视化、演绎记录。
- 社区增强：J05 联机约戏、J06 图纸市场、J11 精选策展、J12 图纸名片与陌生人入口、J15 通知/离线降级。

### 8.3 P2（扩展）

- J07 演出录像广场、J08 剧情片段广场、J09 世界观模板广场（异步广场扩展）。
- 宇宙图鉴 I04、只读分享 G05、联机扩展（另行立项）。
- 桌宠、演出录像导出、更多预设渠道。
- 关系网高级可视化、更多动作库与表情。

### 8.4 MVP 验收门槛

新用户能在**一个会话内**完成“建 2 个 OC → 连 1 条关系 → 建岛 → 拼 1 件物件 → 配 API → 生成 1 段文 → 演 1 场 → 退出重开恢复”，且 OOC 测试集 0 泄漏、存档 100% 可恢复。社交 MVP 另验“私密产出 → 公开页展示柜 → 好友申请/同意 → 岛门授权串门 → 手信送达 → 撤销授权/举报”链路。

## 9. 待用户确认的问题

> 以下为开发前必须拍板项，均给建议默认值；未确认前按默认执行。

1. **Q1 关系强度初值**：不同类型初始强度未定。建议：亲属 60、挚友 60、宿敌 20、上下级 40、暗恋 30，可手动改。
2. **Q2 宇宙数量口径（已修订）**：旧口径“同时活跃 ≤3”保留为同时运行上限；已建宇宙不设总数硬上限；新建立需过 I09/I10 门控。建议按此执行。
3. **Q3 跨宇宙关系与复制**：建议默认只读引用，不继承关系；复制需逐项确认，复制后两边独立。
4. **Q4 自由行为的生成频率**：建议日常每 15 分钟一次模板决策；仅特殊事件调用外部 API，常规日 0 次。
5. **Q5 离线推演上限**：建议 72 小时；超出只保留关键事件与报告。
6. **Q6 OOC 严格度**：建议硬禁忌直接拦截、软偏离改写 1 次；误杀可申诉，不默认放行。
7. **Q7 动作库范围**：MVP 建议 10 个动作（站/坐/走/跑/蹲/抬手/拥抱/争执/转身/离场）+ 基础表情。
8. **Q8 单场演绎规模**：建议 3–6 个场景、总时长 ≤10 分钟；超长拆多场。
9. **Q9 长文长度**：建议单任务 ≤20 段、每段 ≤2000 字；超出另建任务。
10. **Q10 API 服务商范围**：建议 MVP 支持“通用兼容协议 + 自定义地址”两类，其余 P1 适配。
11. **Q11 物件尺寸与配方**：建议单物件 ≤48×48，单配方 ≤8 个部件；超出需确认。
12. **Q12 分享与公开（已修订）**：默认全私密；公开页展示柜与四档可见性（J10/J13）进 MVP，但只做快照展示与关注/申请；广场、市场、精选、名片后置；“要可以转”按允许转发/转载理解，默认关闭，待确认。
13. **Q13 账号与云同步**：建议本地优先，云同步与分享才要求登录。
14. **Q14 内容安全责任**：建议平台保留输入/输出双重过滤，用户对其 API 产出负责；违法内容一律阻断。
15. **Q15 删除宽限期**：建议软删 30 天；永久删除输入名称确认，账号注销立即擦除密钥。
16. **Q16 世界观卡必填与扩展上限**：建议四项基准全部必填，扩展字段上限 12 项；是否允许“先建后补”未定，默认不允许。
17. **Q17 改卡迁移默认值**：语气类默认“仅新内容生效”；色板/时代类首次修改时弹选择，默认选“仅新内容”，全局重渲染需二次确认。
18. **Q18 客串主权冲突的默认顺序**：建议平台安全 → 双方硬禁忌交集 → 宿主世界观卡 → 宿主场景/关系 → 客人软设定；是否允许宿主临时放宽自己世界的软规则未定，默认不允许。
19. **Q19 等级曲线与门槛**：建议等级 1–10，第 2/3/4 个宇宙分别 L5/L8/L10；经验来源只算关键剧情、官方演出、关系里程碑与物件被使用，具体数值待定。
20. **Q20 跳过解锁路径**：建议默认不提供；如运营需要“付费/活动跳过”，须另行登记并标注影响面，当前按“无跳过”执行。
21. **Q21 形象编辑器参数默认值**：网格阈值、部件层级/锚点、导出格式按《功能设计-完整功能设计.md》Q17/Q19/Q20 执行；同层唯一归属已由用户裁决（见《功能设计-完整功能设计.md》Q18，已定，不设 exclusive_group 与主归属）；MARD 色号表版本与授权见该文档 Q21，两处调整须同步。
22. **Q22 社交规划待确认项**：共 10 条——“要可以转”的语义、岛门长期授权时长、隐身观察是否告知访客、手信记忆归属、约戏剧本来源、约戏成品归属、公开页展示上限、未成年保护、版权与搬运、注销后的引用，详见《社区好友功能规划》Q1–Q10；未确认前按该文件建议默认值执行。
